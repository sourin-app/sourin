# Agent Note: 多执行者同改一个文件时，判据要按"我的改动是否在位"，不能按"文件 md5 不变"

Status: implemented

## Problem

本批有 8 个执行者**同时**在改同一棵 `rust/sourin_core/src/csp/`：

```text
被**多方追加**的共享文件（实测都有三个以上执行者在改）：
  · csp/mod.rs      —— 每个新类都要加一行 `pub mod`
  · Cargo.toml      —— 加依赖（rsa）
  · csp/shared.rs   —— 公共工具（impl_src_only / strip_comments）

实测 md5 漂移（同一次交付内）：
  csp/mod.rs：交付时 a3dcc4a1… → 复核时 **6928b9bc…**（别人又加了 7 个类的行）
```

**问题**：交付与复核之间，**文件 md5 必然变化** —— 因为别人在往同一文件追加。

后果（一个**会误报缺陷**的判据）：
```text
复核者若拿"交付者报的 mod.rs md5"去比对现盘 ⇒ 会判"文件被改坏了" ——
而实际上**交付者那几行分毫未动**，只是多了别人的行。
⇒ 这是**假红**，且它会把复核引向"追查谁改坏了文件"（而没人改坏任何东西）。
```

## Decision

**判据按文件的所有权分层：**

```text
· **私有文件**（一个执行者独占，本批 8 个类文件各自一份）
  ⇒ 判据 = **逐字节 md5**（它们不该被别人碰过；md5 变了就是真问题）
  ⇒ 可一行核一批：`md5sum src/csp/{a,b,c}.rs | md5sum` = <组合哈希>

· **共享文件**（多方追加同一文件）
  ⇒ 判据 = **"我的改动是否仍在且完整"**，**不是** md5 不变
  ⇒ 可跑命令（本批 csp/mod.rs 的实例）：
     `grep -cE "^pub mod (a|b|c);" src/csp/mod.rs`  → 预期 = 我加的行数
```

★ 本批实测（我按此复核 csp-batch-c 的交付）：
```text
· 共享文件判据（我在位）：
  $ grep -cE "pub mod (sports_kafei|ting_bokan|djuu|shuang_xing|sou4k|yinhai|short_haokan|ting_shijie);" src/csp/mod.rs
    8      ✅ 与它交付的 8 行一致
· 私有文件判据（md5）：
  $ cat src/csp/{那 8 个}.rs | md5sum
    c7a4cb5a8799b4cd460a41b86b480047
⇒ 两个判据各管一层：**共享文件核"在位"，私有文件核"md5"**。
```

★ **组合哈希必须路径无关**（这条是 csp-batch-c 自己踩到并更正的）：
```text
它第一版用 `md5sum {8 个文件} | md5sum` ⇒ 得到 **30ad530e…**
  —— 但那个值**把文件名也算了进去** ⇒ 换目录（仓库根 vs rust/sourin_core）就变成另一个值
  ⇒ **同一个交付态有两个"正确"值** ⇒ 复核者必然误报。
改为 `cat {8 个文件} | md5sum`（不含文件名）⇒ 从任意目录都是 **c7a4cb5a…**
⇒ 与上一条是**同一族问题的镜像**：
  · 共享文件用 md5 ⇒ **判据太宽**（把别人的改动算进来）
  · 组合哈希含文件名 ⇒ **判据混入环境**（把路径算进来）
  两者都属"**判据没有对准被测量的东西**"。
```

**为什么不能靠"谁最后写"来避免漂移**：共享文件的追加式编辑本身就是设计
（每类一行，加行是必要动作），无法也不该串行化 —— 真串行会让 8 个执行者互相等。
⇒ 所以解法不是"消灭共享"，而是**把判据对准所有权**。

## Alternatives considered

1. **给每个执行者一个"文件时间窗"**（谁在这个窗口内碰过它）。
   论据：能自动归因"谁改了"，看起来比 grep 更严格。
   **否决** —— 时间窗需要所有执行者上报精确时间戳并互相同步时钟，而**追加式编辑**里
   "窗口重叠"是常态而非异常；而且它**判不了改动内容**（窗口内可能有别人的 5 行 + 我的 8 行）。
   ⇒ 它对"我想验证的事"（我的改动在不在）没有增益。

2. **把 md5 一并写进交付，让复核者按"md5 变了 ⇒ 找该文件当前 owner"处理**。
   论据：保留最严的判据，只是加一条解释规则。
   **否决** —— 本批已有实测反例：`mod.rs` 在**同一次 session 内**被三方各加了几行，
   "找 owner"没有唯一答案。而且规则一复杂，复核者就会退化成"看 md5 不符 ⇒ 报缺陷"
   （那正是要避免的假红）。

3. **不做区分，统一用"git diff 里我的行还在不在"**。
   论据：git 是权威，且天然只管"内容差异"。
   **否决** —— 本仓库当前有大量**未 commit 的新文件**（本批 24 个类文件全是 `??`），
   `git diff` 对未跟踪文件**没有输出** ⇒ 判据会对"全部新增的类"失效（本批的主要形态）。

## Consequences

- **收益**：把一类**假红**（"文件被改坏了"）从复核流程里去掉了；两个判据各有唯一答案，
  复核者可机械照跑（命令已写在上方，不是口头说明）。
- **代价**：判据分两层 ⇒ 交付模板要**同时**给"私有文件 md5"与"共享文件行数/在位证据"。
  若只给一半，复核者仍会误判。★ 本批的交付模板**没有**要求后者 —— 是 csp-batch-c
  主动交出这条，我才注意到（**它自己先发现了这个缺口**）。
- **已知上限（如实记）**：本判据**只覆盖"追加"型共享编辑**。
  若有人**删改**共享文件里别人的行（本批未发生），`grep -c` 会**照旧通过**（只数我自己的行名）。
  ⇒ 更强的形态需要"行级归属"（如每行带 owner 标记），本批未做，也未证明必要。
