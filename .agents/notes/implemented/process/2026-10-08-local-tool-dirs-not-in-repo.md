# Agent Note: 小工具目录不进仓库

Status: implemented

## Problem

本机 agent 会话产物、一次性探针、临时脚本如果留在仓库里，会同时造成两个后果：
`git status` 长期是脏的（真信号被淹没）；机械门禁扫描时把它们当仓库内容，
产生大量假阳性。

这些内容有一个共同特征：**只对本机 / 本人成立**。

## Decision

它们进 `.gitignore`；门禁扫描时也显式跳过这些目录 —— 它们是**假阳性来源**，
不是仓库内容。

判定口径是「换台机器 clone 下来还成立吗」：不成立的就不进仓库。

Independent: 小工具目录不进仓库。仓库卫生的一条独立规则。

## Alternatives considered

- **把探针当作可发布的测试夹具** —— 它最强的论据是探针里常有真实数据，
  留着便于复现问题。否决理由：探针含本机路径与真实账号痕迹，且形态是一次性的；
  要发布的夹具应该正面放进 `test/`，按仓库内容对待。

- **只加 `.gitignore`，门禁照扫** —— 它最强的论据是「扫得越多越安全」。
  否决理由：扫描器不读 `.gitignore`，照扫的后果是假阳性淹没真信号，
  最终没人看门禁输出 —— 那比少扫更糟。

## Consequences

- **收益**：`git status` 恢复成可信信号；门禁输出里的每一条都是真命中。
- **代价与已知上限**：忽略清单与扫描跳过清单是两处，必须同步维护 ——
  只改一处会出现「忽略了但还在扫」或「不忽略了但没扫」。
  ⇒ 跳过范围要在扫描器代码里显式表达，不能只依赖 `.gitignore`。
- **重访条件**：某类工具变成团队通用 —— 那时应移进 `tools/` 并正面纳入扫描范围。
