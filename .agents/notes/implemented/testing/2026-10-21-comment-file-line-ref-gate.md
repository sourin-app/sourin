# Agent Note: 注释里的 `file:line` 引用只做「行号越界」核对 —— 三种候选判据里只有一种不假绿

Status: implemented

> 同域：[gate-self-traps-four-forms](2026-10-18-gate-self-traps-four-forms.md) 讲**门禁自身的陷阱**；
> 本篇是它的一个**定量实例** —— 我实测了三种候选判据的报错率，
> 只有 0.07% 那一种可用，85% 的两种**必然被绕过**。

## Problem

同一天在 `browse_page.dart` 抓到两处「注释与代码不一致」：

```text
① `test/t80a_skeleton_fade_test.dart` 文件头写「await FFI(必抛) → finally setState」
   而 `browse_page._init()` **从来没有 try/finally**
② `_init()` 的 `await _load(1)` 也没有兜底（判定为防御性缺失，当前不可达）
```

两处都是**靠人读注释时对照代码**才发现的。★ 而且第 ① 处存在了很久，
**它恰好让一条假断言得以通过**：`t80a` 的「第 1 帧骨架无包装」之所以能过，
正是因为 `_init()` 卡住了、页面永远停在骨架分支。

⇒ 这类缺陷没有守卫。但**注释的自然语言无法自动验证** ——
试图验证「注释说得对不对」必然假绿。所以问题是：**能机械核对的那个子集是什么？**

## Decision

**只核对「行号是否越界」，不核对「注释语义是否正确」。**

判据（`test/zz_t66_r3_comment_ref_test.dart`）：

```text
对每一行注释，正则抓 `([A-Za-z_]\w*\.dart):(\d+)`；
若该 .dart 在本仓唯一命中 ⇒ 读它的总行数；
  行号 < 1 或 行号 > 总行数  ⇒ **红**
```

**为什么只做这一条**：它是**绝对可判定**的 —— 行号超出文件行数就是一定指错了，
没有任何解释空间，也**不会假绿**（不会因为"看起来合理"而放过）。

### 三种候选的实测报错率（这才是选择依据）

```text
候选① 「同行有反引号标识符 ⇒ 该标识符必须出现在目标行」
   checked=160  ok=24  bad=136   ⇒ **85% 报错**
   原因：`file:line` 常指向「这一带」，标识符在附近而不在这一行

候选② 「`file.dart:NNN` 的 `ident`」（更紧的措辞形态）
   checked=20   ok=3   bad=17    ⇒ 同样 85% 报错

候选③ 「行号必须在该文件行数范围内」（**采用**）
   checked=1447 ok=1446 bad=1    ⇒ **0.07% 报错**
   而且那 1 条是真错（见下）
```

★ 候选①② 的报错率证明它们**必然被绕过**（永远红的门禁比没有更糟）。

### 覆盖度（本仓强制格式）

```text
扫描范围：lib/ + test/，769 个 .dart 文件，397529 行
发现 1850 处 `file.dart:行号` 引用
  跳过   30 处（SDK 源码引用：flutter/lib、dart-sdk）
  跳过  366 处（文件名不在本仓 ⇒ 第三方：print.dart / window_manager.dart /
               ink_well.dart / real.dart …）
  跳过    7 处（同名多份，无法判定）
  **实核 1447 处**
```

三条覆盖度纪律：

1. **必须打印**「扫了多少文件 / 多少条引用 / 多少条被实核」。
2. **`refsChecked > 500` 是硬断言**：扫描器自身失效时会是 0，
   而下面的断言全部通过 ⇒ 与「真的没问题」长得一模一样。
3. **跳过要点数、不静默**：三类跳过各自计数并打印，
   不许用 `continue` 悄悄吃掉。

### 排除 worktree / 探针目录（本轮实测撞到的假阳性）

```text
`.agents/worktrees/` 与 `.probe/` 里有 `lib/ui/theme_bridge.dart` 的**旧副本**：
   worktree 副本 863 行 / .probe 副本 816 行 / 主仓 **815 行**
若不排除，会用副本的行数去判主仓的引用 ⇒ 假阳性。
★ 这是「同名多份」的第二来源，必须在目录遍历层面排除，而不是靠"同名就跳过"
（那样会把我真正要查的主仓引用也跳掉）。
```

## Alternatives considered

**A. 做「语义一致」检查（注释说 finally，代码就得有 finally）**
否决：这需要理解自然语言与代码结构。实测候选①② 已经证明，
连「同一行的标识符是否出现在目标行」这种**弱得多**的判断都有 85% 假阳性。
做语义层只会更糟，而且失败方式是**假绿**（判据看不懂就放过）。

**B. 只核对 `file:line` 是否存在目标文件（不查行号范围）**
否决：`bad_nofile` 实测 365 条，其中绝大多数是 SDK / 第三方
（`print.dart:73`、`window_manager.dart:158`、`ink_well.dart:1408`…），
它们**不是错误**。要区分「本仓缺失」与「第三方引用」只能靠文件名白名单，
而白名单会过期（这正是「按模式清理」那条坑的同族）。

**C. 检查形态 A（控制流关键词）与形态 C（存在性断言）**
否决（**本轮主动放弃**，Lead 也认可收窄）：两者都容易滑向语义判断 ——
「注释提到 `finally`」而函数里有个**字符串**含 `finally`、或注释在讲**别的对象**，
都会误报。要做就需要「注释块 与 函数范围」的可靠映射，
那依赖 Dart 语法分析，远超本轮范围。

## Consequences

**收益**：一份能持续报警的守卫，且**零假阳性**（0.07% 报错率，那 1 条是真错）。

**修掉的 1 条存量问题**：

```text
lib/ui/theme/app_colors.dart:86
  改前：（theme_bridge.dart:820 有这段读数。）   ← theme_bridge.dart 只有 815 行
  改后：（theme_bridge.dart:772 有这段读数。）   ← 那段读数实际在 772-773
```

★ 按 Lead 的纪律「存量问题先只报告、不要一次全改」：
本轮只有 1 条，故直接修；若将来冒出多条，**先列清单报给人**，不要批量改 ——
改注释本身也可能引入新的不一致。

### ★ 已知的假阴性（这个门禁抓不到什么，必须写明）

```text
① 行号在范围内，但**指向了别的内容**（漂移）
   本轮实例：`theme_bridge.dart:820` → 修到 `:772`，漂移 48 行。
   若某次漂移只差 10 行，仍在 815 行范围内 ⇒ **本门禁抓不到**。
   ⇒ 这是最主要的假阴性，靠人读，不靠本门禁。

② 形态 A：注释说「这里有 try/finally」而代码没有
   → 不做（见 Alternatives C）

③ 形态 C：注释说「全仓库零调用」「已删除」而实际存在
   → 不做

④ 注释里的**无行号**引用（`见 browse_page.dart` 不写行号）
   → 无从核对

⑤ 同名文件的引用（7 处被跳过）：无法确定指哪一份

⑥ 第三方 / SDK 引用（396 处被跳过）：本就不该查
```

⇒ **本门禁的定位是「廉价的下限守卫」，不是「注释正确性保证」。**
它能挡住「指向根本不存在的行」，挡不住「指向错的行」。

### 何时该翻案

- 若将来 Dart 有稳定的**注释块 ↔ 函数范围**映射手段（analyzer 包可做）
  ⇒ 可以做形态 A，那时本门禁可以升级为「注释提到的控制流关键词必须在该函数内出现」。
  判据：先用它重跑本轮候选①的数据，**报错率需 < 5%** 才可采用；
  否则又是一条会被绕过的门禁。
- 若本门禁长期零命中且 `refsChecked` 越来越小（注释不再写行号）
  ⇒ 说明习惯变了，可考虑降级为软报告。
- 若发现它开始**频繁误报**（同一行号在多份同名文件、跨平台行尾差异）
  ⇒ 先修目录排除逻辑，不要调宽判据。
