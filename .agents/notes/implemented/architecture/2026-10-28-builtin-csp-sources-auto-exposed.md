# Agent Note: 内置 csp 源自动暴露 —— 让"类即源"，回到原版行为

Status: implemented

## Problem

Rust 侧实现了 66 个 csp 类（`register_site!` 自注册进 inventory），但**用户界面上看不到它们**。
原因在 `state.rs::bootstrap`：provider 只有两个来源 ——

```text
⑦  JS 插件（plugins/*.js）
⑦' 从落盘记录恢复的 TVBox 站点（`tvbox-sources.json`，来自用户导入的订阅）
```

csp 类只在"配置里恰好有一个 `api: csp_Xxx` 的站点"时才会被 `CspProvider::new` 建出来。
⇒ 一个类写得再对，只要用户没导入含它的订阅，就**永远不会出现在源列表里**。

Owner 的判断（2026-10-28 逐字）：

```text
> 哪个 tvbox 聚合源默认是自动的，不应该再额外生成配置，
>   参考的 apk 和链接他们就能实现，你不行吗？
```

他说得对：原版客户端的形态是**"jar 里有什么类，客户端就出什么源"**，
不需要用户为每个类去导一份配置。我们上一轮提出的"生成一份可导入订阅"是把平台缺陷转嫁给用户。

## Decision

`bootstrap` 里新增 **⑦'' 内置 csp 源**：为**每个已注册的 csp 类**自动建一条源。

```text
id   = `csp-<kebab 类名>`      （`ALLLive` → `csp-all-live`；稳定 ⇒ 可停用/排序/收藏）
name = 类名                    （中性，不含站名 —— t98 门禁会拦）
api  = `csp_<类名>`            （与配置里的写法逐字一致）
ext  = 空                      （没有 ext 的类点进去会看到**该类自己的可读 Err**：
                                 "需要 ext 里的站点地址（键 site/host）" ——
                                 比"源根本不出现"更接近原版，也比"假装能播"诚实）
```

三条边界：

```text
① **幂等**：按 id 查重（热重启/测试多次 bootstrap 不会重复注册）；
② **不与导入重复**：配置里已经导入过同一个 api（`imported_csp_apis`）的类跳过，
   否则同一个类会出现两条源（一条来自配置、一条内置）；
③ **顺序**：必须排在 ⑧「应用停用状态」**之前** —— 用户上次停用的内置源要能被恢复成停用。
```

## Alternatives considered

1. **生成一份"可导入订阅"给用户**（我上一轮的方案）。
   最强理由：零代码改动，不动 bootstrap 的注册顺序，风险最小。
   **否决（Owner 直接驳回）** —— 这等于把"客户端该做的事"变成"用户的额外步骤"，
   而原版不需要这一步；用户没有义务为了用上已实现的功能去导配置。
2. **只暴露"不需要 ext"的类**（给 `CspSite` 加 `needs_ext()` 默认 false，逐类覆盖）。
   最强理由：能避免用户点进"必然报缺配置"的源，观感更干净。
   **否决（本轮）** —— 需要逐类审计 66 个类对 ext 的依赖，而且"能不能不填 ext 就跑"
   本来就只有类自己知道；更关键的是：**隐藏起来**正是这次要修的病。
   每个类自己的 Err 文案已经写清了缺什么（本批统一要求），让用户看见"缺配置"比看不见更诚实。
3. **在 Dart 侧加一层"发现未注册类"的 UI**（设置页列出所有类，让用户勾选启用）。
   最强理由：用户可控，且不影响默认列表。
   **否决（本轮）** —— 多一层开关就多一条"默认关 = 功能等于没做"的路（本仓已有同类教训）；
   而且它仍然回答不了"为什么原版不用勾"。
4. **把内置源放进 `tvbox_aggregate` 聚合源里**（作为聚合的一个渠道）。
   最强理由：用户已经在用聚合页，不用新增列表项。
   **否决** —— 聚合是"多渠道合并"的视图，csp 源是独立 provider；
   塞进聚合会让"停用某个内置源"变成要在聚合页里操作，语义串了。

## Consequences

- 收益：**48 个已注册类在空数据目录下也能全部出现在源列表**（门禁
  `tests/zz_parity_builtin_csp_sources.rs` 用空目录 bootstrap 断言，注入循环不执行 ⇒ 48 个全部报缺失）。
- 收益：一个稳定的 id 规则（`csp-<kebab>`），用户停用/排序/收藏都靠它，不会随类改名漂移
  （改名会变 id —— 但类名本来就该稳）。
- 代价：源列表从个位数涨到 50+，**首屏更杂**；用户要自己停用不关心的类。
  缓解：id 稳定 + 停用状态持久化（`disabled-providers.json`）⇒ 一次性整理，之后不再变。
- 代价：需要 ext 的类（如要站点列表的那几个）点进去会看到"缺配置"的 Err。
  这是**刻意的**：它把"这个源存在但你还没配"告诉用户，而不是让源消失。
- 代价：`bootstrap` 里多了一段 O(类数) 的构造（66 次 `CspProvider::new`，纯内存，可忽略）。
