## Problem

本轮（第 66 轮）批量跑「本轮动过的 170 个测试文件」，捞出 2 条红。
查下来两条都不是产品缺陷，而是**判据本身错位**：

### 红 1：`t98_no_site_names_test.dart` —— 两个正确判据互相排斥

```text
t98         ：'<站点代号>' 不许出现（别泄露站名）
台账判据 d  ：key 必须逐字等于 "live_<站点代号>_real_test.dart"（防腐化）
⇒ 同一个字符串同时承担了两个语义：**站点名** / **文件标识符**
```

⚠️ 上面刻意用 `<站点代号>` 占位而不是真实站名 —— 因为 **t98 正好也在扫本文件**
（`.agents/notes/` 在它的扫描范围内）。写真实站名会让这篇讲豁免的笔记
自己变成 offender。真实标识符见台账 JSON 里的 key。

豁免本来能解决，但根因不是"少了一条豁免"，而是：
**当两个判据在同一个数据上互相排斥时，说明这个数据同时承担了两个语义。**

### 红 2：`zz_t66_selfaudit_crossgate_test.dart` —— 注释被判成代码

原判据：对本机工作区绝对路径做裸 `contains`（不剥注释；具体路径已脱敏）。
实测命中的是 `zz_t66_danmaku_send_safety_gate_test.dart:79-95` 的**注释**：

```text
 *   Platform.script   = file:///<REPO_ROOT>/main.dart
 *   实测 `Directory.current = <REPO_ROOT>`
```

那是一段**排障证据**（证明"为什么 `Directory.current` 可靠"），
不是"代码里写死本机路径"。让它红 = **逼人删证据换绿**。

### 顺带一条（同批修）：`t118_control_bars_link_test.dart` ⑦ —— 钉了缩进

```dart
final i = src.indexOf('                    _TopBar(');   // 20 个空格
```

`ddb0794`（本轮 N11 底栏改造）把挂载点从"以缩进开头"改成
`builder: (context, _) => _TopBar(`（行尾）⇒ `indexOf` 返回 **-1** ⇒
报 `Expected: >0, Actual: -1`。
**顶栏功能没变**，只是挂载点的缩进位置变了。

## Decision

### ① 内部台账豁免：三个条件同时成立

```text
① 路径在内部台账目录：.agents/notes/ 或 docs/notes/
② 该行**同时**含 `_test.dart`（即引用的是一个测试文件名）
③ 只豁免那一行 —— 同文件里其它行照样报
```

豁免表写成**数据**（`const _internalLedgerPrefixes`），不藏在 if 里的字符串判断 ——
这样"新加一个内部台账目录但忘了登记"会被自检抓住。

⚠️ **不豁免**：`docs/` 根目录（用户可见文档）、`lib/`、`test/`。

**并加边界自检 5 条**（`★★★ 内部台账豁免的边界`）：
台账+文件名引用 ⇒ 豁免 / 台账+普通叙述 ⇒ 不豁免 / `lib/` ⇒ 不豁免 /
`test/` ⇒ 不豁免 / `docs/` 根 ⇒ 不豁免 / 前缀拼错 ⇒ 不豁免。

★ 豁免是**削弱门禁**的动作，所以它的边界必须被另一条判据钉住，
否则今天加一条、明天加一条，门禁会静默失效。

### ② selfaudit：剥注释后判代码；注释命中只打印

```text
代码里有本机路径     ⇒ 红（fail）
只有注释里有         ⇒ 打印 [SELFAUDIT] 覆盖度，不红
```

用仓里既有的 `test/_support/strip_comments.dart`（**不抄第二份**）。

### ③ t118 ⑦：不钉缩进，用正则找符号

```dart
改前：final i = src.indexOf('                    _TopBar(');
改后：final ctor = RegExp(r'(_TopBar\()').firstMatch(src);
```

判据从「带 20 个空格的字节序列」改成「`_TopBar(` 出现，且它前 400 字符里没有 `if (`」——
**与缩进几个空格、是否在行尾无关**。

### ④ 三者共同加的覆盖度读数

```text
[T98-COVERAGE] 扫描文件=1050  行级豁免命中=61  内部台账豁免命中=621  offenders=2
[SELFAUDIT]    本机路径出现于 1 个门禁的**注释**里（代码里 0 处）
```

没有这些数字，「豁免了 621 处」与「扫描器坏了、一处都没扫到」
在输出上**完全无法区分**（两者都是"绿"）。

## Alternatives considered

**A. 把 `native-media-audit.json` 改成数组 `[{"file": "..."}]`，绕开 t98。**
最强理由：不动别人的门禁，纯数据重构。
否决理由：**没用**。文件名那串字符还在 JSON 里，t98 照样命中 ——
它扫的是**文本内容**，不是"键的位置"。这个方案我实测想过，是错的。

**B. 放宽台账判据 d（key 允许写别名）。**
最强理由：一劳永逸，不再与 t98 冲突。
否决理由：会毁掉 d 的防腐化能力 —— key 与文件名不再一一对应后，
"测试改名了但台账没跟着改"就查不出来了，而那正是 d 存在的理由。

**C. 删掉那段注释（selfaudit 那条）。**
最强理由：一行删除，立刻绿。
否决理由：**为了绿而销毁证据**。那段注释记录的是真机实测路径，
它解释了"为什么 `Directory.current` 可靠"这一设计判断。
本仓反复记过这条错（`docs/AGENTS.md` 的「不许为了过门禁而删证据」）。

**D. 让 t118 的判据改成"顶栏渲染树上有没有"（行为级）。**
最强理由：行为级比源码级强。
否决理由：该文件整组都是**源码级判据**（`t118` 的定位是"源码契约"），
单条改行为级会与该文件其余 15 条不一致，且行为级在这里拿不到
"顶栏是否常挂"的信号（它测的就是"有没有外层 if"这个**结构**事实）。
⇒ 保留源码级，只把"钉缩进"改成"钉符号"。

## Consequences

**收益**

```text
· t98 的豁免从"隐式放行"变成"三个显式条件 + 5 条边界自检"
  ⇒ 豁免面可判、可审、不会被随手加宽
· selfaudit 从此区分「代码写死」与「注释记录」，且用仓里唯一的 stripComments
· t118 ⑦ 不再被格式化/重构打红（一天内同族第二次：e363d2c 修过另一条）
· 三个判据都加了覆盖度打印
```

**代价**

```text
· t98 多了一次豁免判断（每行一次 startsWith + contains），1050 文件略慢；
  实测整条 t98 仍 6 秒内跑完，可接受。
· 豁免表是"白名单"，天然有腐化风险 —— 靠 5 条边界自检压住。
· selfaudit 现在**不**判"注释里有本机路径"，若将来有人把敏感路径
  写进注释（如真实用户目录），它不会红。这是有意的取舍：
  注释里的路径换机器不坏，且删了会丢证据。
```

**已知上限**

```text
· t98 还剩 1 处未解决（2 条输出）：`.agents/notes/.../danmaku-send-safety-gate.md:72`
  引用的是**私库源码名** `<provider>.ts`（真实文件名含站点名），
  不是测试文件名 ⇒ 条件②不成立 ⇒ 不豁免。
  它属于另一个作者、且按裁决不该由本豁免覆盖 ⇒ 留给他处置。
  ★ 本门禁**不为它放水**：放水会让"引用私库文件名"也变成合法，
    而那与 t98 的初衷（别泄露站名）冲突。
  ★ 已记为交付报告的「已知待办」—— 否则 t98 会一直红，
    下一个人会以为"这个门禁坏了"。
· 「两个判据互相排斥」这次只解决了**这一个实例**。
  没有通用机制能自动发现"某数据同时承担两个语义" —— 只能靠人读到红时想这一层。
```

**何时该翻案**

```text
· 若将来把 `native-media-audit.json` 移出仓库（改放 .probe/），
  内部台账豁免就可以删掉 —— 那时冲突自然消失。

· 若 `_test.dart` 这个标记不再足够（例如出现"引用测试目录"而非文件名），

```

## 第四批（2026-10-27）：判据的**适用范围**与交付物的**存放/变更方式**不一致

前几批讲"把合法内容当成违规"。第四批是**另一个形态**：
判据本身合法，但它**判的范围**（宽 / 窄 / 混入环境量）与交付物的实际情况不一致 ——
⇒ 结果同样是**"看起来判过了"，其实判的不是那件事**。

### 四个实例（本批实测）

```text
① 共享文件用 md5 判 ⇒ 判据比对象**宽**
   多执行者往同一个 `csp/mod.rs` 追加行（本批 8 个执行者）⇒ 它的 md5 **必然随别人变**。
   ⇒ 复核者拿"交付时的 md5"比对现盘 ⇒ 判"文件被改坏了" = **假红**，而其实交付者那几行分毫未动。
   正解：**私有文件核 md5；共享文件核"我的增量是否在位"**（`grep -c` 自己的行）。
   详见 [shared-file-verification-is-by-presence-not-md5](../process/2026-10-27-shared-file-verification-is-by-presence-not-md5.md)。

② 组合哈希**含文件名** ⇒ 判据混入了对象之外的东西
   `md5sum {8 个文件} | md5sum` 得到的值**把文件名算了进去**
   ⇒ 在 `rust/sourin_core/` 下算得 `30ad530e…`，从仓库根算得另一个值
   ⇒ **同一个交付态有两个"正确"值**（复核必然误报）。
   正解：`cat {8 个文件} | md5sum`（不含文件名）⇒ 路径无关。
   ★ 这条是**执行者自己先发现并更正的**（不是复核发现的）。

③ 审计脚本的**搜索范围**不含实际位置 ⇒ 判据比对象**窄**
   用 `md5sum * | grep -c` 在 `.probe/` 里核"台账列的每个 md5 是否都有对应文件"
   ⇒ 源码文件不在 `.probe/` ⇒ 匹配数 = 0
   ⇒ 会被误读成"**文件丢了**"，实际是"**我搜的目录里没有它们**"。
   正解：审计范围必须覆盖交付物的**实际存放位置**（本仓源码在 `rust/sourin_core/src/csp/`）。

④ `include_str!` 用了**错误的相对深度** ⇒ 判据指向一个不存在的路径
   ★ **本条我先写错了原因，实测后更正**（照实留痕）：
   我第一版写的是「`.probe/` 不在 crate 内 ⇒ `include_str!` 编译失败」——
   **那是错的**。实测（隔离 cargo 项目，两组对照）：
   ```text
   【实验 A】src/lib.rs 里 include_str!("../../outside-evidence.txt")（目标在 crate **外**）
     ⇒ cargo test **成功**，且真读到内容（打印验证）。
   【实验 B】按**本仓真实深度**复刻 repo/rust/sourin_core/src/csp/mod.rs，
     include_str!("../../../../.probe-evidence.txt")（crate 外）
     ⇒ cargo test **成功**，真读到内容。
   ⇒ ★ **`include_str!` 可以越过 crate root** —— 它不是硬约束。
   【实验 C】写成 `include_str!(".probe-evidence.txt")`（**以为相对仓库根**）
     ⇒ `error: couldn't read src\csp\.probe-evidence.txt` ⇒ **编译失败**
   ```
   ⇒ **真原因是"路径解析基准"**：`include_str!` 的路径**相对当前源文件所在目录**，
     **不是**相对仓库根，也**不受 crate root 限制**。
     ★ 而"编译失败"的表象与"crate 外"同时出现 ⇒ 极易归因到"crate 外"这个**无辜的属性**上。
   ⇒ 正解：路径按**本文件所在目录**算；跨多层要数清 `../` 层数。
     ★ 本仓的既有用法**全是同目录自读**（`include_str!("app_get.rs")` 等）⇒ 无先例、也不建议
       跨目录引 `.probe/`（那是 gitignored 的证据目录，**不进构建单元才是它该有的定位**）。
   ★★ **本条本身是「判据适用范围」族的又一个实例**：
     我把"**路径基准算错**"（可控、可修）表述成了"**crate 边界**"（听起来像硬约束、不可修）。
     ⇒ 表述强度与实际不符 —— 与第 ⑤ 条（"我不会红"说成"我不能写"）是**同一族**。

⑤ **链接门禁只追 markdown 链接，"文本里出现路径"不算** ⇒ 判据的**触发条件**比直觉窄
   笔记树门禁（`agent_notes_gate` 的 tree）会去校验「方括号＋圆括号」这种**链接**的目标是否存在。
   ★ **反引号挡不住它** —— 我第一版就是把示例写在反引号里，门禁照样红：
     `link: … -> ".probe/xx.log" target file does not exist`（**这条我当场踩了**，见下）。
     要写这种示例只能用**不构成链接的写法**（如换成全角括号、或拆开方括号）。
   ```text
   实测（35 个既有笔记都引用了 .probe/，门禁全过）：
     $ grep -rcE "\]\([^)]*\.probe/" .agents/notes/  → **0**   ← 没有一处写成链接
     $ grep -rc '\.probe/'        .agents/notes/  → **35**  ← 全是纯文本（无反括号链接）
   ⇒ **合法**：反引号内直接写路径（不含方括号＋圆括号）
     **会红**：把路径写成链接 —— 门禁会去找，`gitignore` 掉了 ⇒ target does not exist
   ```
   ★ 这条的价值：**"我引用了 .probe/ 却没事"不等于"引用 .probe/ 安全"** ——
     它取决于**写成了纯文本还是链接**。同一族：**判据的触发条件常常比"看起来相关的东西"更窄**。
   ★ 另一个同族实例（我本人踩的）：笔记间链接**跨 class 目录**时必须写 `../<class>/文件名.md`，
     否则同样报 `target file does not exist` —— 我写第四批实例时就因此红了一次，门禁当场抓到。
```

### 归纳（可操作的判据）

```text
**判据的适用范围必须与交付物的实际存放/变更方式对齐**：
  · 交付物**私有**（一个执行者独占） ⇒ 判据可以严（逐字节 md5）
  · 交付物**共享**（多方追加）       ⇒ 判据按"**我的增量**"，不是"整体/在位"
  · 判据涉及**多文件聚合**           ⇒ 必须剥离**路径 / 顺序 / 时间**等环境量，或显式约定
  · 判据涉及**构建期读取**           ⇒ 路径基准要按**源文件所在目录**算（不是仓库根，也不受 crate 边界限）
  · 判据的**触发条件**要说清         ⇒ 只追链接？还是也追纯文本？（⑤ 的教训）
  · 判据的**表述强度**要与实际一致   ⇒ 是"物理不允许"，还是"我选择不做"？（④⑤ 的教训）
```

★ 四条的共同表现：**"看起来判过了"**，但判的都不是那件事。
   与"**绿的未必是通过 / 红的未必是实现**"是同一个母题。
   ★ 第 ② 条尤其值得记：**它连"同一台机器换目录"都过不了** ——
     说明这个错不需要任何并发或外部变化就能触发。

### 与第三批的关系

```text
第三批：判据把**合法内容**当违规（t98 把站点名当泄露、注释里的路径当写死路径）
第四批：判据把**范围/口径**搞错（宽、窄、混入环境、构建范围不对）
⇒ 两批都属「判据作用在错误的对象上」，但**第四批的修法不是"加豁免"或"剥注释"**，
  而是**按交付物的所有权与存放方式重新划判据的适用范围**。
```

### 实例 ①：`pub mod` 与"是否注册"被混为一谈

```text
我要判"5 个零站引用类**没有被注册**"（本轮裁定：做实现、不注册）。
我的判据：`grep "register_site!"` + 剥注释 ⇒ 得到 **3 个文件各命中 1 处**
⇒ 结论差点写成"**它们偷偷注册了**"。
★ 去看那 3 行原文，全是**不是代码的东西**：
   · `//      crate::csp::register_site!(AppSy);`   ← 注释里举的"将来怎么加"示例
   · `assert!(!flat.contains("register_site!(AppFox)"), …)` ← **执行者自己写的门禁**
⇒ ★ 我的剥注释脚本**处理不了"注释里含代码样本"与"断言里的字符串字面量"**
  ⇒ 与第三批同一个形态（**判据把文档/字符串当成了实现**），只是这次是我踩。
```

**修法（可机械执行）**：

```text
"有没有注册"要**问注册表**，不能读源码 ——
  源码里的 `register_site!` 字样可能是：注释、文档、门禁断言、测试数据。
⇒ 写探针直接查 `build_registry_from_inventory()` 的真实键表：
     let keys: Vec<&str> = reg.keys().copied().collect();
     assert!(!keys.contains(&"AppSy"), "★ 不该在注册表里");
   ★ 并加**反空真**：`assert!(keys.len() > 20)` ——
     否则"注册表为空"会让上面每条断言都**空真通过**（铁律 149）。
```

### 实例 ②：我自己写的门禁，锚点不唯一 ⇒ 对**已经写对的代码**报红

```text
我写 R2-#2 入口门禁时用 `code.indexOf('AppMenuButton<String>')` 定位卡片菜单，
而那个串在文件里出现 **2 次** ⇒ 取到的是**别处**那一个 ⇒ **门禁报红，而代码是对的**。
★ 第 1 次错：锚点不唯一（我今天刚提醒过别人"锚点必须唯一"）。
★ 第 2 次错（修锚点后）：我从菜单项往前找 `if (_canEdit`，找到的是**包着「编辑」单项**的门控，
  而不是**包着整块菜单**的外层门控 —— 两者代码形状几乎相同（`if (_canEdit…`），
  只能靠**位置**区分（外层那道在 `AppMenuButton` **之前**）。
⇒ 这又是「判据作用在错误的对象上」：**同一个符号在两个层级各有一份**。
```

**修法**：

```text
· 锚点必须**唯一**：用只在目标处出现的串（本例用 `label: '编辑链接…'` 当锚）。
· 判"外层"门控时，必须断言"**目标门控与目标控件之间不再夹另一个同类控件**"
  （本例：取到的门控与 `AppMenuButton` 之间不该再有一个 `AppMenuButton`）
  —— 这是"锚点唯一"在**层级**上的推广，此前只考虑了"串在全文唯一"。
```

### 实例 ③：`cargo test` 的过滤词是**子串** ⇒ 把别的模块的数算成自己的

```text
我报"app_ys 有 25 条门禁"，执行者说"我的是 15"。双方都不肯让 ⇒ 用两种口径对照：
  $ cargo test --lib csp::app_ys    → **25 passed**   ← 子串匹配，同时命中两个模块
  $ cargo test --lib csp::app_ys::  → **15 passed**   ← 精确（带尾双冒号）
  $ cargo test --lib csp::app_ys_v2 → **10 passed**
⇒ 15 + 10 = 25 ⇒ **我测到的 25 是"两个不同模块的和"**，执行者的 15 才是它的。
★ 根因：本批有多组**同前缀**类（`app_ys`/`app_ys_v2`、`app_get`/…）⇒ 子串必然撞。
```

**修法（本批硬规矩）**：

```text
报模块读数一律用 `cargo test --lib csp::<mod>::`（**带尾双冒号**），
否则 `X` 会命中 `X_v2` / `X_pro` / `X2` —— 会把**别人的数计入自己**。
```

### 三条计数错法的共同点

```text
同一轮里我连续三次数错，**三种不同根因**：
  ① 读源码数 `register_site!` ⇒ 把**注释示例 / 断言里的字符串**当成真注册（**对象**错）
  ② 写门禁用 `indexOf('AppMenuButton<String>')` ⇒ 锚点在文件里**不唯一**（**对象**错）
  ③ `cargo test` 过滤词是**子串** ⇒ 命中同前缀的另一个模块（**范围**错）
⇒ 三者的共同表现：**"我数到的" ≠ "我问的那个"**。
  ①② 数的是**别的东西**（文档/别处那份），③ 数的是**更大的范围**。
★ 与「**判据作用在错误的对象上**」是同一母题的两个面：
  那几批讲**判据**错位，这条讲**计数/读数**错位 ——
  两者都表现为"**看起来量到了**"。
```

## 第六批（2026-10-27 同日，**执行者自报**）：**"看起来有红" ≠ "这次注入红了"**

```text
本批一位执行者自查出 **18 份早期注入日志"名不符实"**：
  文件名声称"某类 I1 注入"，而**内容里列的红测试不是它的**
  （打印的是 `commands::tests::*` / `backup::tests::*` 等**别的模块**的失败）。
★ 真因：注入脚本早期版把"失败行过滤"写成了**别人模块的前缀**，
  后来改成了 `^---- csp::`，但**前 18 次运行没重生成日志**
  ⇒ 于是"日志文件"与"它声称的那次注入"**对不上**。
```

**修法（对每份注入日志断言三件，可脚本化）**：

```text
① `改动：…` 存在
② **注入后 md5 ≠ 注入前 md5**
③ **红的测试名是本人的**（不是别的模块的失败）
★ 关键第 ③ 件：坏版本"**也有红**"，但那些红**不是这次注入造成的**。
  ⇒ 一句话：**「日志里有红」≠「这次注入红了」**。
```

### 本批这一族的三个成员（同一母题：**"看起来是" ≠ "它确实是"**）

```text
· `impl_src_only` 自伤：按**子串**切测试段 ⇒ 被注释/字符串字面量里的同名词切中
  ⇒ **静默少找**（判据看到的源码比真实少）
· 判据带空格恒真：归一化**去掉所有空格**后仍比对带空格串
  ⇒ 那个串永不出现 ⇒ 断言**恒真** ⇒ **假绿**
· 本次：日志里的红**不是本人的** ⇒ **看起来有红**
★ 三者**全部由执行者自查发现**（第 2 条还被它的**注入守卫当场标出**）。
⇒ 共同修法：**换一个独立证据源再算/再看一遍** ——
  第 1 条换成"行首锚定"、第 2 条换成"归一化后的形态"、第 3 条换成"按本人测试名过滤"。
```

### 与"哪些红是中间态"的关系（同日另一件事）

```text
本批我实测到 `cargo test` 的红**逐次换位置**（app_yqk → hxq/wwys → 1 条），
  md5 却与执行者报的交付值**逐字一致** ⇒ 判定"**编译时别人正在改**"（中间态）。
★ 判据（可复用）：**"单模块绿 + 全库红 + 位置漂移 + md5 未变" ⇒ 先怀疑中间态，不怀疑交付物**。
  反之"**单模块就红**"⇒ 可能是真红（本次 `wwys` 单跑红 1 条，后来执行者确认是它脚本改到一半）。
⇒ 这与「注入不红先核 diff」是**同一纪律的两个方向**：
    红了 ⇒ 先怀疑**环境/时序**；绿了 ⇒ 先怀疑**判据/对象**。
```

### 与前面几批的关系

```text
第三批：判据把**合法内容**当违规
第四批：判据把**范围/口径**搞错
第五批：**"有没有做 X"这类事实，不该从源码/文档文本推断** —— 要么问运行时，
        要么至少承认"源码文本里出现 X 的字样" **≠** "X 发生了"（注释/文档/断言都算字样）
⇒ 第五批的修法是**换证据源**（源码文本 → 运行时真值），而不是改判据的正则。
★ 与"**注入必做且必须证明落到被测对象上**"是同一族：
  两者都问"**那个事实真的发生了吗**"，而不是"有没有迹象表明它发生了"。
```

## 第七批（2026-10-27 同日）：**判据反过来污染了被测对象**

```text
一位执行者为了"在 Rust 侧就发现站名违规"，在 `app_ys.rs` 里**加了一条影子门禁**：
  断言"常量表以外不许出现站名"。
★ 但**为了写那条判据**，他在断言里**列出了 7 个站名字面量**作为判据数据
  ⇒ **那条"反站名"的门禁，自己把站名带进了仓库**
  ⇒ 跨栈的 `t98` 门禁立刻报红 14 处，**命中点全是他新写的那几行**。
⇒ 一句话：**"为了让它不红"而写的东西，本身让它红了。**
```

**修法（执行者自己选的，且没有走捷径）**：

```text
**删掉整条影子门禁** —— 不是：
  · 把站名拆开写（`"bili" + "bili"`）—— 那是**规避门禁**
  · 给它申请豁免 —— 它属"改了不会坏"的一类，**不配占豁免额度**
⇒ 理由（他自己给的）：**它与那条跨栈门禁重复**，而跨栈门禁本来就是这件事的判据。
  "同一件事不该有两个判据，其中一个还会自伤。"
```

### 本批这一族的六个成员（同一母题：**"看起来是" ≠ "它确实是"**）

```text
① `impl_src_only` 自伤：按**子串**切测试段 ⇒ 被注释/字符串里的同名词切中 ⇒ **静默少找**
② 判据带空格恒真（归一化去掉空格后仍比对带空格串）⇒ **假绿**
③ 注入日志里的红**不是本人的**（别的模块的失败）⇒ **看起来有红**
④ 比对脚本的**口径**问题（行格式/缩写/反向引用/编号）⇒ **看起来不一致**
⑤ 证据"人读清楚"但**按读取者的判据抽不到** ⇒ **看起来没红**
⑥ 判据的**触发条件比实际窄**：按钮文案是 `_hasLink ? '保存' : '填入'` 两态，
   探针只找「保存」⇒ 在"首次填写"（**最常见的路径**）上**假红**
⑦ **本次**：为"防回归"写的判据，**自己制造了要防的东西** ⇒ **判据成了缺陷来源**
⇒ 共同根：**"看起来对/有/不一致/没有" ≠ "它确实是那件事"**。
★ ⑦ 的**特殊性**：前六条是"**判据没验到/验错**"，⑦ 是"**判据污染了被测对象**"——
  即**加防护的动作本身引入了风险**。这是最需要防的一类，因为它的动机是好的。
```
