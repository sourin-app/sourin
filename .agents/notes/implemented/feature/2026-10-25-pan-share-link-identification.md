# Agent Note: 网盘能力先做"链接识别"这一跳，域名必须精确匹配

Status: implemented

Independent: 本仓此前**没有任何网盘播放实现**（`src/sync/` 里的"网盘"是 WebDAV
备份同步，与网盘分享取流无关；全仓无 `quark`/`aliyundrive`/`123pan` 等域名的
运行期处理）。因此本模块不与任何既有决定重叠或冲突。

## Problem

Owner 要求"支持网盘账号登录解锁源（夸克/百度云/UC/百度/123 等）"。

完整链路有六跳：

```text
识别分享链接 → 解析分享页 → 拿文件列表 → 换下载直链 → 交给播放器
                                     ↖ 私有内容还需要：账号登录 → cookie/token
```

其中**后五跳都需要真实账号或真实分享**才能验证，而测试账号尚未提供。

## Decision

先实现**第一跳**：`src/pan.rs::parse_share()` —— 把用户粘贴的一段文本认成
「哪个网盘 + 分享 id + 提取码」。

三条设计决定：

### 1. 吃"一段文本"而不是"一个 URL"

用户实际粘贴的是这样的：

```text
我用某网盘分享了「某影片」，点击链接即可保存。
链接：https://pan.example.com/s/abcdef123456
提取码：8x2k
```

提取码**不在链接里**，在正文。只接受干净 URL 会把这一半信息丢掉。

### 2. 域名**精确匹配**，不许用 `contains`

```rust
fn host_is(host: &str, domain: &str) -> bool {
    host == domain || host.ends_with(&format!(".{domain}"))
}
```

用 `contains` 会把 `evil-quark.example.com`、`pan.quark.cn.evil.com` 都认成
合法网盘 —— 用户会拿到一个指向别人域名的"分享"，而完全不知道哪里错了。

### 3. 认不出就 `Unknown`，**不猜**

与 TVBox 那边同一条纪律：错误的识别会让用户拿到打不开的结果，
且排查成本极高（他不知道是哪一步坏的）。`Unknown` 不是错误，
是"这个链接不归我管"。

### 4. 提取码只认**提示词后面**的短码

`提取码：8x2k` / `密码: abcd` 后面跟的 4~8 位字母数字。
不做全文扫描 —— 否则正文里的年份（2024）、集数（12）、清晰度（1080）
都会被当成提取码。

## Alternatives considered

### A. 先做完整的某个网盘（解析 + 取直链 + 登录）

**最强理由**：这是 Owner 真正要的东西，一步到位；只做识别看起来像"没做事"。

**否掉的原因**：登录链路需要**真实账号**才能验证，而账号尚未提供。
先做一个"代码写完但一行都没真跑过"的网盘，等于交付一个无法声称可用的功能 ——
那正是本仓明令禁止的形态。而识别这一跳**不依赖账号**，可以离线全量测，
是唯一现在就能做到"有独立验证证据"的部分。

### B. 用现成的网盘 SDK / 第三方 crate

**最强理由**：不重复造轮子。

**否掉的原因**：网盘没有官方 Rust SDK；第三方实现普遍绑死某个盘的登录流程，
且大多依赖逆向出来的签名算法（会随上游改版失效）。识别这一跳是纯字符串处理，
自己写更简单也更可控。

### C. 域名匹配用 `ends_with(domain)` 就够，不必加 `.` 边界

**最强理由**：代码更短。

**否掉的原因**：`notpan.baidu.com` 会以 `pan.baidu.com` 结尾吗？不会 ——
但 `evilpan.baidu.com` 会以 `baidu.com` 结尾，若表里写的是裸域就会误判。
加 `.` 边界是为了让"子域"与"长得像的域"能分开。这条已被注入验证钉死（见下）。

## Consequences

**收益**
- 网盘链路最容易错的一跳（域名判定、id 提取、提取码来源）现在是**纯函数 +
  9 条门禁**，不依赖网络与账号，可离线全量回归。
- 后面每一跳都要复用它；识别错了后面全白做，所以先把它做扎实是正确顺序。
- `PanKind::code()` / `display()` 是有意稳定下来的契约值（会进落盘与日志）。

**代价与边界**
- **识别 ≠ 能播**。FFI 返回体里显式带 `resolvable: false` 与
  `note: "已识别分享；解析与取直链尚未接入"` —— 不冒充可用。
- 登录链路、分享页解析、直链换取**全部未实现**，需要真账号才能验证。
- 域名表是硬编码的。上游换域名时这里要跟着改，且**必须精确匹配**；
  若新增盘，要同时补 `PanKind` 变体、`code()`、`display()` 与测试。
- 提取码识别覆盖 `提取码/密码/访问码/pwd` 四种提示词；其它说法（如"口令"）
  当前不认，会返回 `None` 而不是瞎抓。

## 验证结果（已发生）

- `cargo test --lib pan:: --release` → **9 passed**
  覆盖：8 种盘的域名识别、**4 个"长得像"的域名必须被拒**、id 提取（含 query 不许混入）、
  路径形态不认识时返回空串、URL 内 `?pwd=`、正文里的提取码、
  正文数字不许被当提取码、未知文本返回 `Unknown` 而非错误、契约值稳定。
- **故障注入**：把 `host_is` 改成 `host.contains(domain)` ⇒
  `lookalike_hosts_are_not_recognized` **FAILED**（8 passed / 1 failed），
  恢复后 9 passed。证明"长得像的域名不许被认"这条真能变红。

## 何时该翻案

拿到测试账号后，应把"解析分享页 + 换直链"补上，并把 FFI 的 `resolvable`
从常量 `false` 改成真实探测结果。若届时有网盘已停止服务，
应从 `PanKind` 里删掉而不是留着 `Unknown` 混在一起。
