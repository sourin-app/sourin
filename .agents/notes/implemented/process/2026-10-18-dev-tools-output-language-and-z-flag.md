# Agent Note: 面向开发者的工具链三处修正 —— 输出语言、退出码语义、非 ASCII 安全

Status: implemented

> 同域：[2026-10-08-local-tool-dirs-not-in-repo.md](./2026-10-08-local-tool-dirs-not-in-repo.md)
> 那篇定「工具产物不进仓库」；本篇定「工具本身要人可读、退出码要可读对、
> git 路径不能用转义形态」。前者管**放哪**，本篇管**怎么让人用对**。

## Problem

本轮在写工具与脚本时踩到三类**工具自身不可靠**的问题。它们的共同点：
工具照跑、照退出 0，但**人或机器读不出正确结论**。

### ① `.ps1` 的「ASCII 化」会把判定文案抹成 `?`

```text
实测 tools/live_probe_count.ps1 的 19 处判定文案被替换成 `?`，
而**语法 / 退出码 / 逻辑全部正常** ⇒ 工具照跑、照退出 0，
但**人读不出结论**，而"让人判断 0 次是好是坏"正是它存在的唯一理由。
```

根因：PowerShell 5.1 用 ANSI 936（GBK）读**无 BOM 的 .ps1**，中文乱码。

### ② 退出码含义没写在工具里，读者会读反

实测：守卫工具被误读成「0 = 有问题」。而实际是 `0 = 通过`。
一旦读反，绿灯会被当成红灯去"修"，或红灯被当成绿灯放行。

### ③ `git` 对非 ASCII 路径的默认转义导致静默漏检

```text
git diff --name-only 对非 ASCII 路径默认输出：
  "lib/\344\270\255\346\226\207.js"
⇒ 门禁里的 startsWith('lib/') 返回 false ⇒ 该文件**根本没被检查**
⇒ 现象是门禁全绿，而它守的东西完全没看。
```

## Decision

### ① 面向开发者的工具，**输出文案一律用英文**

`8a4cdd3`：`tools/live_probe_count.ps1` 的 19 处判定文案改英文；
`fix(round-66/LIVE-PROBE): 工具脚本混入非 ASCII` 同批清理。

不靠 BOM、不靠控制台代码页 —— 那是环境依赖，换台机器/换个 PowerShell 版本就变。
判据：
```text
grep -c "???" tools/*.ps1  必须 = 0
```

### ② 在工具**内部**写明退出码含义

`eb12cd4`：在脚本头部加「怎么正确读退出码」的警告块。

★ 关键：说明必须**在工具里**，不能只在文档里 ——
读工具的人常常是直接打开脚本改它，不会去翻文档。

### ③ `git` 调用补 `-z`，按 NUL 分隔读取

`fbafd3d`：所有从 git 取路径列表的地方改为 `-z` + 按 `\0` split。

```text
不带 -z ⇒ 非 ASCII 路径被转义并加引号 ⇒ 前缀匹配失败 ⇒ 静默放行
带 -z  ⇒ 原始字节，原样得到 "lib/中文.js"
```

## Alternatives considered

- **给 `.ps1` 加 UTF-8 BOM** —— 它最强的论据是一行改动，PowerShell 会正确识别。
  否决理由：BOM 在其他工具（许多非 Windows 的编辑器、某些 CI 环境）里
  会变成文件开头的不可见字符，导致 `#!` 行失效或 diff 噪声。
  ⇒ 改用「输出英文」这个更彻底的方案。

- **只在 README 里写退出码含义** —— 它最强的论据是集中管理，一处说明全部工具。
  否决理由：实测被误读的工具，读者当时就在看脚本本身。
  ⇒ 说明必须贴在使用现场。

- **用 `git -c core.quotePath=false` 代替 `-z`** —— 它最强的论据是改动更小，
  只加一个配置项，输出保持人性可读。
  否决理由：`quotePath=false` 只是不转义，**路径里含换行或空格时仍会被拆行**。
  `-z` 是唯一能保证「一个路径一条记录」的方式。

- **只在 CI 上加 `-z`，本地脚本不动** —— 它最强的论据是 CI 才是门禁真正跑的地方。
  否决理由：本地跑绿、CI 红（或反之）正是本轮另一篇笔记记录的问题
  （门禁读工作区而不是 blob）。**同一条判断标准必须处处一致。**

## Consequences

- **收益**：工具输出人可读；退出码不再被读反；非 ASCII 路径的源码改动
  才真正进入受管范围。
- **代价**：英文文案对中文开发者的可读性略降 → 用简短短语，不写长句；
  `-z` 让脚本里多一步 split，且调试时不能用 `echo` 直接看原始输出。
- **已知上限**：`-z` 只解决「路径含非 ASCII」；路径含换行仍会让某些
  逐行处理的工具出错（本仓未出现，未处理）。
- **重访条件**：当新增任何「从 git 读文件列表」的工具时，
  应默认带 `-z`；若有人用 `quotePath=false` 代替，应指回本篇。
