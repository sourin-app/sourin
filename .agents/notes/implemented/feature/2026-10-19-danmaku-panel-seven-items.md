# Agent Note: 弹幕面板七个子项 —— 四条根因与最初假设不同，两条「能跑但不做事」

Status: implemented

> 同域：[2026-10-18-danmaku-pipeline-five-changes.md](./2026-10-18-danmaku-pipeline-five-changes.md)
> 那篇是弹幕管线的整体改造；本篇是**面板层**的逐项取证，且四条根因推翻了假设。
> 相邻：[2026-10-18-danmaku-request-proxy.md](./2026-10-18-danmaku-request-proxy.md)（传输层代理）。

## Problem

用户一条反馈里藏了 7 件事：

```text
① 这个弹窗都看不清了          ② 里面的控件啊 文字啊
③ 这个弹幕来源也搜索不了      ④ 在这个弹窗内部双击会透传
⑤ 这个弹幕源可以绑定多个的    ⑥ 弹幕信息要显示清楚：哪个源 / 上次更新多久 / 一共多少条
⑦ 内置的那两个 dan-api 服务根本用不了
```

**7 条里有 4 条的根因与最初假设不同**（①②③⑦），2 条是「能跑但不做事」（⑤⑥）。
这正是本仓反复吃亏的形态：**假设看起来都合理，而实测四条全偏**。

## Decision

### ① ② 看不清 = 玻璃透光，不是对比度

```text
最初假设：对比度不足（已排除：常量对 5.86~14.5:1 全达标）
                  ⇒ 疑为玻璃背景（方向对，但没量化）

真渲染像素取证（RepaintBoundary.toImage，对每个 Text 矩形做颜色直方图，
众数 = 真实背景、前景族众数 = 笔画）：
  常量对 #14161B：      正文 14.50:1 · 次要 9.69:1 · 说明 5.86:1   ← 对照组
  信息面板（改前）：     真实背景 rgb(20,106,118) ← **青绿**！说明档 2.44:1
  设置弹窗（改前）：     卡片内 rgb(94,91,45) ← **橄榄**！说明档 2.09:1
  遮罩压暗（改前）：     底图白 → 遮罩 rgb(71,71,71) → 卡片内 rgb(92,93,96)
                        ⇒ **面板内比遮罩还亮**（这一条是机制判据，不依赖 shader 细节）
```

**根因**：真实背景根本不是 `#14161B` —— 玻璃把视频画面透进来了。

**修法：拆职责，不是调参数。**

```text
玻璃只负责**质感**（描边 / 模糊 / 高光）
遮光由**实色层**负责

· danmaku_info_panel：`_SurfaceBackstop` 垫在 GlassContainer **外面（下面）**，0xE6（90%）实色
  ★ 里层仍是 40% —— 保留 `zz_t66b_info_glass_test` 第③组「alpha < 0xE6」的**原意**
    （那条门禁守的是"里层别变成不透明"，不是"整块不许有不透明垫层"）
· app_dialog_shell：glass 档 Material 从 Colors.transparent 改成 #14161B@0.98
  （与非玻璃档**同源**，这样深浅两套主题都不会漏底）
```

**改后**：信息面板说明档 **6.49:1**，设置弹窗最差 **5.27:1**，勾选框 5.28~13.07:1。

**★ 这组读数的边界（2026-10-21 补）**：

> **以上只证明「颜色对比度」；中文排版宽度在 flutter_tester 里恒为 12.000/字，
> 故「会不会挤 / 折行」未验证。**

**为什么 Ahem 不影响对比度这条判据（论证）**：

```text
flutter_tester 默认字体是 Ahem ⇒ 每个字符渲染成**硬边实心方块**。
实测（渲染一行，看直方图）：独立颜色数 = **2**，
  14161b:10400（背景）/ e6e6e6:1600（字形）—— **零抗锯齿过渡色**。

★ 但这不损害本判据，因为对比度只取两个量，而**两个都不经过字形形状**：
  ① 前景色 = `TextStyle.color`；Ahem 方块整块涂的就是这个色 ⇒ 字色分量正确
  ② 背景色 = 直方图众数（背景像素远多于字形）；方块字形更规整、无抗锯齿噪声
     ⇒ 背景分量**更容易**取准
⇒ 「字色 vs 背景」这两个数都是对的。
  判据测的是「文字压在什么上面」，而「什么上面」完全由**布局与合成**决定。
```

**它证明不了的两件事（所以本条是「等级 2 带边界」）**：

```text
① 字形本身是否清晰（方块 vs 真字，两者都"看得见"）
② 中文实际排出来多宽 ⇒ **会不会折行 / 截断**
   （本仓已记录：flutter_tester 里中文恒为 12.000/字，拉丁字母才是真实度量）
⇒ 本条证明了**颜色达标**，没证明**版面不会挤**。
```

### ③ ⑦ 内置 dan-api = DNS 被劫持（归因改了两次）

```text
最初假设：*.vercel.app 被 DNS 污染
         ← **方向对，但当时引用的证据是别人的旧 nslookup，我没有自己核**

我的第一版（错）：DNS 没问题（getaddrinfo 不抛异常），断在 TCP（errno 10060 16s）
         ← **把后果当病因**

最终实测（自己跑三条）：
  本机 getaddrinfo → 74.86.17.48 / 2a03:2880:f117:83:face:b00c
  Cloudflare DoH   → 216.198.79.131 / 64.29.17.131        **完全不同**
  vercel.app apex  → 本机 199.96.58.15 vs DoH 216.198.79.3  **不同**
  vercel.com 对照  → 本机 64.239.109.193 vs DoH 64.239.123.129  ✓ 一致且 200

三条独立佐证：
  ① face:b00c —— Facebook 花样段，**三个** *.vercel.app 域名都返回它
  ② PTR 反查：74.86.17.48 → *.sl-reverse.com（SoftLayer）
              108.160.173.207 → www.v.dropbox.com（Dropbox！）
  ③ vercel.com 解析正确且 200 ⇒ **不是 DNS 整片坏，是针对性劫持**
```

**因果链（三层，别混）**：

```text
DNS 被劫持  →  连的是伪造地址  →  TCP 超时  →  而服务本身是活的
                                     ↑
                          「TCP 超时」不是独立病因，是第 1 层的后果
服务活的证据：代理下 401，带 token 前缀 200
```

**UI 侧**：加 `dnsHijacked` 分类，与 `dnsFailed` 指向**完全不同的操作**：

```text
dnsFailed    「域名解析失败（本机 DNS 不通）」             → 换网络 / 修 DNS
dnsHijacked  「域名被解析到了错误地址（DNS 可能被劫持）」  → 换 DNS(DoH) 或开代理；改弹幕地址没用
```

判据是**纯函数** `isKnownForgedAddress`（face:b00c / SoftLayer / Dropbox / 199.96.58 / Facebook / Twitter 段），
外加 DoH 复核兜底（解析成功 + TCP 超时 + DoH 真值不同 ⇒ 同一判定）。

★ **DoH 只是佐证，不是前提** —— 它自己也可能被拦；无 DoH 时靠已知伪造段也能定案。

### ④ 双击透传 —— 接受透传，落点无害（已在 `c642515` 落地）

「遮罩单击立即关」与「双击不穿透」**时序上不可兼得**（试过 5 版，含"关窗后保留 350ms 屏障"）。

★ 本轮补了**覆盖漏洞**：第一版只给 10 处关闭点里的 2 处装了守卫。详见
`../bug-fix/2026-10-19-sheet-guard-covered-two-of-ten.md`。

### ⑤ 多源绑定 —— 整个控件没接线（比假设更严重）

```text
最初假设：SwitchListTile 是单选语义，要改成多选
实际：**不是 SwitchListTile**（它在 _switchRow 里，是显示开关用的）
      来源行一直是 ☑/☐ 图标，问题是 **4/4 个调用点都 onChanged: null** ⇒ 只读
      而「当前生效」那行拼的是 _biliCount + 本机在线 + dan-api 配置，
      括号里的 state.count 是宿主取回的总数 ⇒ **与勾选无因果关系**
      ⇒ 就算能点，读数也不变
```

这是「同一个源比同一个源」的教科书形态：**界面上的读数没有来自它声称的来源。**

**修法**：`DanmakuFeedChannel` 枚举当键 + 真实 `_enabledFeeds` 集合 + `_toggleFeed`；
消费方是**真的** `DanmakuAggregator.merge`（不重写去重逻辑）。
读数改成读合并结果：单源 / `N 路 → 合并后 M 条（跨源去重 K 条）`。
本片源自带**不可取消**（视频本身带的事实）。

**降级不撒谎**：合并原料要 `List<DanmakuComment>`，面板是纯 UI 拿不到 ⇒ 新增 `feedSamples` 注入参数。
宿主没注入时如实降级 —— 只有本片源那一路，且多路时**只说「合计」不说「合并后」**
（没逐条内容就去不了重，不凭空画「N 路合并」）。

### ⑥ 弹幕信息 —— 原本没有源名、没有更新时间

```text
现状读数：DanmakuInfoData 有 source/match/count/total/title/cid/detail/error/loading/
          enabled/aggregate/truncated —— **没有源名字段、没有更新时间**
          全仓 grep「上次更新」在 UI 层 0 命中
```

**修法**：
- `sourceName` 三级退路：宿主给的 > 聚合里单路的 label·detail > 类别名；
  多路成功时**不挑一个**，说「N 路合并」
- `updatedAt` 三种事实分开说：
  · 宿主给的（精确到这一集）
  · 面板自己观察到的（**明说「本次会话观察到」**）
  · 「未记录」
- `didUpdateWidget` 才记观察时刻 —— **不在 build 里**，否则永远显示"刚刚"

## Alternatives considered

### ① 玻璃看不清 → 「提高字色对比度」

**最强论据**：最省事、不碰结构、且"字看不清就调字"是直觉上最直接的因果。

**为什么否决**：**它的前提被像素读数否掉了。** 真实背景是 `rgb(20,106,118)`（青绿），
在这种底上把白字提亮只会让它更刺眼，而"说明档 2.44:1"的成因是**底在动**，
不是字不够亮。★ 而且字色已经 14.5:1（对照组成立），再调就是为一个不存在的病因改设计。

### ② 玻璃看不清 → 「整体去掉玻璃」

**最强论据**：一劳永逸，再也没有透光问题；也与"彻底不用 Material"的方向一致。

**为什么否决**：**代价与收益不成比例，且违背既有设计决策。**
玻璃是本轮之前刻意引入的（`2026-10-18-glassify-where-it-is-visible.md` 有裁决）。
去掉它 = 推翻一个已落地的设计决策，而**问题只是"它不该同时承担遮光职责"**。
⇒ 拆职责（玻璃管质感、实色管遮光）保住了设计，也解决了缺陷。
★ 判据：**能用"分工"解决的，不要用"取消"解决。**

### ③ DNS → 「换掉那两个内置实例」

**最强论据**：最彻底 —— 换一个不被劫持的域名，用户什么都不用做。

**为什么否决**：**没有可换的候选，且换域解决不了问题。**

```text
· kDanmakuPublicInstances 两个都是 *.vercel.app，没有非 vercel 的可替代品
· 实测这两个服务本体是**活的**（代理下 401 / 带 token 200）
  ⇒ 坏的不是服务，是本机到它的路
· 换一个"没实测过的第三方地址"进内置清单 ⇒ 违反本仓纪律
  （那张表有规矩：没实测过的地址不许进）
⇒ 正确做法：让 UI 说真话，指引用户换 DNS / 开代理
```

### ④ 多源绑定 → 「保留只读，只改文案」

**最强论据**：改动面最小；而"原本就没接线"说明它可能不是用户真正在用的功能。

**为什么否决**：**用户明确要了（⑤「这个弹幕源可以绑定多个的，不要忘了」），
而"只改文案"会让标题与行为继续不一致。**

```text
标题现在写着「可多选 · 勾上即合并」，而 4/4 调用点 onChanged: null
⇒ 只改文案 = 承认这个功能不做，但用户要了
⇒ 必须真做，且消费方必须是真合并（否则又是"能点但不做事"）
```

### ⑤ 弹幕信息 → 「面板自己算更新时间（DateTime.now）」

**最强论据**：宿主不用改，面板自给自足，任何来源都有"上次更新"。

**为什么否决**：**那是编造事实。** `DateTime.now()` 在 build 里会永远显示"刚刚"，
用户会以为弹幕是刚拉到的。★ 正确做法是**区分三种事实**并把不确定的说成"未记录"。

|---|---|---|---|
| ① ② 信息面板 | 说明档 2.44:1 | **6.49:1** | 像素直方图 |
| ① ② 设置弹窗 | 最差 2.09:1 | **5.27:1** | 同上 |
| ③ ⑦ 分类 | 不区分 DNS/超时/空 | 6 档（含 `dnsHijacked`） | 纯函数 + 门禁 |

### 代价

```text
· `_SurfaceBackstop` 多一层，弹窗结构多一个包裹（可读性成本）
· `dnsHijacked` 的伪造段清单是**已知样本**，将来出现新的伪造段抓不到
  ⇒ 兜底靠 DoH 复核（但那也可能被拦）
· 多源合并的原料只能从 `_aggregateDanmaku` 的 `inputs` 取
  （那是全仓唯一还按来源分开的地方）⇒ 若将来合并逻辑上移，这个注入点要跟着搬
· 面板与设置页共用分类函数，改一处影响两处（这是**想要的**，但回归面变大）
```

### 还没覆盖的

```text
· **没有真机 Release 启动验证**（AGENTS.md §6 要求）—— 本批只覆盖 flutter test，
  不含真机启动与弹窗路径。这是已知缺口，批末统一补。
· ② 的"控件啊"只印证到一半：勾选框 5.28~13.07:1 达标，**没找到**控件自身的其它问题。
  若用户指的是别处（滑块/按钮），需要他指认。
· 没有非 vercel 的可替代内置实例 ⇒ 换域方案未采纳（理由见 Alternatives ③）
```

### 何时该翻案

```text
① 若真机验证证明玻璃垫层在浅色主题下过重（观感变"实心块"）
   ⇒ 把 0xE6 降到能过 4.5:1 的最低值，但**不许低于机制判据那条**（面板内不许比遮罩亮）
② 若出现新的伪造地址形态 ⇒ 扩 `isKnownForgedAddress`，并补一条反证
   （真值地址不许被判成伪造 —— 防止判据写成恒真）
③ 若有一天有真实的非 vercel 弹幕服务被实测可用
   ⇒ 可回到 Alternatives ③ 的方案，加进内置清单
④ 若多源合并逻辑上移到 core ⇒ `feedSamples` 注入点要跟着搬，
   否则面板拿到的仍是"只有本片源那一路"，会退化成假功能
```
