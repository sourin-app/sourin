# round-66 · 内容级复核证据（`verify-e2e`）

这批图是**「用户在界面上实际看到的文字」**的证据，不是「机制对不对」的证据。

## 为什么单独建一批

本轮最贵的教训是：**所有测试绿、所有门禁绿、修复已提交 —— 而真机上效果为零。**
唯一能发现它的动作是：启动产品、打开那个界面、**用眼睛读一遍内容**。

⇒ 本目录的每张图，回答的都是同一类问题：
**「用户看到的字是什么？有没有标记语法漏出？有没有被裁？数字读起来对不对？」**

## ★ 哪些图**不能**作为证据（重要）

```text
① icon 是否显示正确 —— 本批图里的 □ 有一部分是**图标位**，
   因为 flutter test / 该渲染路径下 MaterialIcons 字体可能未加载。
   ⇒ 图里出现的 □ **一律不得**当作"图标坏了"的证据。

② 02 / 03 的行内代码方块 —— **不能据此判真机缺陷**。
   我做过分档归因实验（inherit(theme) / monospace / FontLoader 加载的字体
   三档渲染同一串「更新下载方式」）：
       只有 FontLoader 显式加载的那档画得出中文，其余全变方块
   ⇒ 测试/渲染环境里"未显式加载的字体画不出中文"是**环境行为**。
   ⇒ 结论只能是：**「行内代码用 monospace 族名；真机是否显示中文未验证」**，
     既不能说它是缺陷，也不能说它没问题。

③ 本目录**没有** R8 缓存徽标、R1 站标徽章、播放页、详情页、设置二级页的图。
   原因：
     · R8 / R1 的现成图是**图形/候选对比**，不是"用户视角读到的文字"
     · R1 那张候选图的对象是**顶栏**，而 Owner 反馈的是**底栏**按钮 ⇒ 对象不对，不收录
     · 播放页 / 详情页 / 设置二级页 —— 无人值守环境下**无法导航到达**
```

## 与 `.probe/` 的关系

`.probe/` 是工作区（gitignored），本目录是**入库的终版证据**。
本目录只放 5 张，合计 **189,607 B**（约 185 KB）。

## 未取证（如实记）

- 弹窗正文在**修正后的模板**下的真机渲染 —— 当前已发布版本读的是旧副本，改动要下次发版才生效
- 行内代码中文在**真机**上的表现 —— 本批图来自渲染路径，不是真机字体栈
- 图标字体正确性 —— 见上方「不能作为证据」
