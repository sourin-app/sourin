# Agent Note: 起播/播放期错误日志不预设"中断"（措辞误导收口）

Status: implemented

Independent: 接续本批 HLS 续片修复（同一文件的相邻落点）。那一篇修的是
"该不该弹横幅"，本篇修的是"日志怎么写才不误导"——两者是同一条错误处理的
**行为面**与**可观测面**。

## Problem

真机验收（02:13 播一条 HLS 频道源）显示：续片修复本身**生效**（日志明确写
「分片续接（HLS 分片边界 EOF，非故障）⇒ 不弹横幅；已吞 N 次」，横幅未弹），
但 `_handleStreamError` 的**入口**仍无条件落一行：

```text
AppLog.write('PLAY', had ? '播放中断（已有画面，非阻断）：$e' : '起播失败：$e');
```

⇒ 续片与抑制两种情况，日志里都会**先**出现一行「播放中断」，紧接着才是
「分片续接…不弹横幅」。横幅没弹、日志却写着中断——**读数在说谎**，后来人
据此会以为 bug 复发。

这与本批 T4 那次事故同类：功能改对了，但**另一处（读数/闸门）没跟着改**，
于是"看起来没修好"。

## Decision

```text
① 入口改中性措辞：「播放期 stream.error（待定性）：$e」——只记事实，不定性。
② 定性交给三个分支各自补写：
   · 续片 ⇒「分片续接（HLS 分片边界 EOF，非故障）」
   · 抑制 ⇒「抖动抑制：同类错误重复出现…」
   · 其余 ⇒ 兜底补回「播放中断（已有画面，非阻断）」，保证真断流仍有明确定性。
③ 门禁钉住不回退：入口不许出现 `had ? '播放中断（已有画面，非阻断）`；
   必须出现中性串；兜底定性串必须仍在。
```

## Alternatives considered

- **只在续片分支追加一行说明、不动入口**：入口那行"中断"仍在，误导读数没消除。否决。
- **入口改判为"已知非中断"**：入口还不知道后面会怎么判（要等 EOF/抑制判定），
  提前下结论是编造。否决——保持"待定性"才是如实。
- **不动日志、只靠文档说明**：真机日志是事后排障的唯一依据，措辞错了就是错了。否决。

## Consequences

- 证红实测：把入口改回旧措辞 ⇒ 门禁 FAILED（"入口不许预设中断"）；还原后 19/19 全绿。
- 读数：zz_t1101 19/19、zz_t1023 4/4、zz_t110 6/6 全过；analyze errors=0；
  两文件 CRLF=0。
- 真机：续片日志为「分片续接…已吞 2 次」且横幅未弹（修复生效）；真断流时
  日志仍会出现「播放中断」——兜底定性保留，排障语义不丢。
