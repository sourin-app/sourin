# Agent Note: 行号锚定的门禁白名单，重新锚定前必须逐条核形态

Status: implemented

## Problem

`test/zz_t66_convergent_tile_gate_test.dart` 用「文件:行号」记豁免（`known` 表），
所以任何一次无关提交都可能把锚点推走，门禁就从「守住真实约束」退化成「报一行过期的数字」。

这次实测红：

```text
[T66] 已知必须留 2 处（白名单命中）
[T66] ★★★ 新增命中 6 处：player_page.dart 21307/21329/21510/21532、
                          emby_page.dart 984/1283
[T66] ★★★ 白名单里已消失 6 处：player_page.dart 21282/21304/21485/21507、
                                emby_page.dart 986/1285
00:07 +3 -1: Some tests failed.   EXIT=1
```

真正的风险不是这 6 条数字，而是**修法有两种、观感一样**：

- 真漂移 ⇒ 更新行号是对的；
- 真新增违规 ⇒ 更新行号就是**把违例写成豁免**，门禁从此看不见它。

门禁文件自己在注释里给了判据「GONE 一批 + 新增一批，且形态相同 ⇒ 只是漂移」。
但这条判据是**人写的**，机器没验：命中只按行号认账，不校验那一行里到底有没有 `Material`。

## Decision

按「先证明是同一段代码，再改数字」的顺序修，并把证明过程留在文件里：

1. **定位推手**（不看总数看净行数）
   - `lib/ui/player_page.dart` +25 ← `65e1694`（`67 42`，净 +25），四个 hunk 全在 21282 之上
   - `lib/ui/settings/emby_page.dart` −2 ← `f0cf7e0`（`10 12`，净 −2），两个 hunk 在 124/639
   - ⇒ 位移量与净行数**逐条相等**（+25/+25/+25/+25、−2/−2），不是"某处悄悄少了两行"
2. **逐条比形态**：取 `git show <推手>~1:<file>` 的旧 blob，与工作树新行做 3 行窗口 diff，
   六处**全为空**；再看链（`ColoredBox(black@0.92) → Material(transparency) → … → ListTile`），
   确认 ListTile 仍在 Material 之下。
3. **改数字并写清理由**：新锚点 + 推手 + 净行数 + 窗口 diff 结论 + 注入读数，全部写进白名单上方的注释。
4. **注入证明它仍能红**：在产物末尾追加一处真违例（不透明 `ColoredBox` → `ListTile`）⇒
   `NEW …:1380`，`+3 -1`，EXIT=1；还原后 `sha256` 等于基线。

## Alternatives considered

- **只更新 6 个数字，注释不动** —— 论据是「判据已经写在上面了」。
  否决：下次红的人只能读到一条抽象判据，读不到"这次为什么是漂移"的证据，
  只能重新做一遍 1、2 两步；数字会继续漂，成本不会因这次修好而下降。
- **把白名单整个删掉，改成按形态识别（不按行号）** —— 论据是根治锚定腐化。
  否决：形态识别要写"这段子树必须有 Material 祖先"的结构断言，等于重写门禁；
  现在 155 个文件里 26 处命中、8 处豁免，重写会在别的文件上炸出新红，
  属于行为变更，不该夹在"修一行过期的数字"里做。
- **让门禁宽容「相邻行号」**（±N 行内都算命中）—— 论据是抗漂移。
  否决：±N 会把"这一段整体挪走 3 行、新代码占据了原位置"也判成命中，
  等于放大假绿；锚定腐化是**可观测**的问题，用模糊匹配换安静不值得。

## Consequences

- **收益**：修后 `+4 All tests passed`、`0 error 0 warning`；6 条豁免的理由现在自带证据链，
  下一个人只需读注释里的 `git show --numstat` 与窗口 diff 结论即可复核。
- **代价**：白名单注释涨到 50+ 行；行号锚定**天然会再漂**，这次没有改变那个性质，
  下次红仍要重做「定位推手 + 逐条比形态」。
- **已知盲区（注入③实测，写进文件了）**：把一处**已豁免**的 `Material(transparency)`
  换成不透明 `ColoredBox`（运行期必抛 "ink splashes may be invisible"）⇒
  命中行号不变 ⇒ 门禁**仍然 EXIT=0 全绿**。
  ⇒ 白名单里的理由只是文档，不是被机器验证的约束。
- **重访条件**：若这类「行号锚定 + 人写理由」的门禁再出现第二次腐化，
  应改为结构断言（豁免项同时声明期望路径含 `Material(`），而不是继续改数字。
