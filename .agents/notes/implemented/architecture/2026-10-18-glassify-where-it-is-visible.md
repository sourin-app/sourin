# Agent Note: 玻璃化必须先判断「哪里该玻璃」—— 否则花了 GPU 却没有视觉变化

Status: implemented

## Problem

第 66 轮 Owner 的指示是「彻底不用 Material 组件，全部自建/玻璃」。
按字面执行会把所有组件换成玻璃件。但实测发现**三类元素玻璃化是无效甚至有害的**：

```text
① 玻璃叠在实色图片上 = 零视觉变化
   海报卡片的本体是实色海报图，占 2/3 面积。
   模糊一块实色图 = 实色图 ⇒ 花了 GPU，屏幕上什么都没变。
   ★ 真正"浮在图片之上、背景会透过来"的只有角标那一小层。

② 玻璃化功能性信号 = 可读性退化
   未读数角标原来是「红底白字」，对比度很高。
   第一版换成玻璃 + AppColors.badge 当**文字色** ⇒ 深红压深灰，
   截图里那个「7」几乎看不见。
   这不是审美取舍，是**功能退化**：用户看不出有几集没看。

③ 玻璃化长列表的每一行 = 破坏列表连续性
   直播列表 20 行全部玻璃化后，每行成了独立的圆角条，
   行与行之间出现明显缝隙 ⇒ 列表从「一个整体」变成「一叠卡片」。
   对「快速扫视 1178 个台」这个核心场景是**负收益**。
   实测：像素变化率 46.8%，但其中大部分是"不该变的地方变了"。
```

## Decision

玻璃化前先过三道判断，全部通过才动手：

```text
① 这一层下面**有没有东西会透过来**？
   实色图片/实色背景上做玻璃 = 无效。跳过。
② 这个元素是不是**功能性信号**（数字、状态、红点、LIVE 标记）？
   是 ⇒ 可读性优先，不做玻璃（或只玻璃化它的**容器**，不玻璃化内容）。
③ 这个元素在**长列表**里重复出现吗？
   是 ⇒ 只玻璃化"少数可见"的那几层（选中态、吸顶条外壳），
        不要玻璃化每一行 —— 会破坏列表连续性与扫视效率。
```

并用**像素变化率**量化方案，而不是靠"我觉得好看"：

```text
改前 vs 改后的像素差（阈值 6/255，每 4px 采样）
  直播页 A 全行玻璃      46.8%  ⇒ 但变化全在"不该动"的行背景上
  直播页 B 只选中行       0.8%  ⇒ 等于没做，Owner 看不出来
  直播页 C 筛选条外壳    20.0%  ⇒ 选中
```

Independent: 玻璃化范围判定。与 material 替换清单同期但不同议题（视觉材质 vs 控件去留）。

## Alternatives considered

### A. 照字面「全部玻璃」

**这是 Owner 的原话，且最容易交差** —— 数量上"玻璃化了 N 个组件"很好看。

放弃理由：上面 Problem 里的三类无效/有害场景。而且它会**制造功能退化**
（未读数看不见）和**性能浪费**（实色图上算模糊）。
Owner 要的是「好看」，不是「玻璃组件数量」。

### B. 完全不玻璃，只改颜色/圆角/字体

**这是风险最低的方案** —— 零新依赖、零性能影响、纯 CSS 级改动。

放弃理由：Owner 明确说了「彻底不用 Material 组件，全部自建/玻璃」，
且他抱怨的是「太丑」。只改色值解决不了"材质感"这个层面。
但这仍是**第一优先**的改动（语义色层 `AppSemanticColors` 已落地），
因为它零风险且立刻见效 —— 玻璃是第二层。

### C. 只做"看得见"的地方，看不见的如实报告

**最终采用的方案。**

放弃理由：（无 —— 这是被采纳的方案）
但它的代价是：**交付时"玻璃化组件数"会很少**，看起来像没干活。
⇒ 必须用像素变化率证明「少但有效」，而不是用组件数量证明。

## Consequences

**收益**：
```text
· 每个玻璃化动作都有可测量的视觉收益（像素变化率 ≥ 5%）
· 避免了功能退化（未读数、LIVE 标记保持可读）
· 长列表扫视效率不受影响
```

**代价**：
```text
· "玻璃化组件数"这个指标很难看（直播页只改了筛选条外壳）
· 需要额外做像素对比验证（每页多一道工序）
· 纯色底页面上玻璃效果天然弱 ⇒ 有些页面会得出「不值得做」的结论
```

**没有解决的**：
```text
· 玻璃在**纯色深底**上的可见度问题仍未量化（当前演示用的是渐变底，
  真实页面是纯色底，玻璃会更弱）。已要求各轨道在真实底色上重测，
  若变化率 < 5% 则如实报「本页玻璃化收益低」，不硬做。
```

## 附：本轮由这个判据拦下的三个具体问题

```text
1. 海报卡片本体玻璃化 —— 拦下（实色图上无效），只做角标
2. 未读数玻璃化        —— 拦下（功能性信号），改回实心红底白字
3. 直播列表全行玻璃化   —— 拦下（破坏扫视），只做筛选条外壳
```

三条都是**先出图/出读数，再决定**，而不是先改后验。
