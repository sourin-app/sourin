# Agent Note: 给「用户可见文案」加防腐守卫 —— 先剥注释再判

Status: implemented

Independent: 与本仓其它 testing/process 笔记不同 —— 那几篇讲**测试与源码**的判据
（[恒绿断言的四种形态](../testing/2026-10-19-four-shapes-of-always-green-assertions.md)、
[固定字符窗口](../testing/2026-10-19-source-scan-judge-should-not-use-fixed-window.md)、
[静默 skip 比红更危险](../process/2026-10-19-silent-skip-is-worse-than-red-in-ci.md)）。
本篇的对象是**给人看的文案**，而它的失效形态不是红，是**悄悄变假**。

## Problem

`.github/release-notes.md` 的 `## 关于本版本` 那节曾写着：

```text
「全量 Dart 测试 2243 通过 / 47 跳过 / 0 失败」
```

★ `git log -S` 定位：那是 **2026-10-08 建 CI 时手填的常量**，
  之后 **11 天、约 50 个 commit 一次没更新**。
★ 而「0 失败」是**向用户作出的不实陈述** —— 当时的实测是 `-23`。

⇒ 已改写为不变量（「全部自动化测试通过」）。
⇒ 但**没有机制防止它再次腐化** —— 而这次能发现，纯粹是因为有人回头看了一眼。

## Decision

新增 `tools/guard_release_notes_numbers.py`，并接进 windows 主 job
（紧邻决策笔记门禁，同样性质：仓内一致性）。

### 判据的三个关键点

```text
① **只扫「关于本版本」那一节**（`## X` 到下一个 `## `）
   ⇒ 全文扫会误伤「下载」表的版本号、「系统要求」的 macOS 12 / API 24 / 150 MB

② **★ 先剥 HTML 注释**（`<!-- ... -->` → 等量换行，保留行号）
   ⇒ 那一节的注释里留了「2243 通过」这类**取证记录**，那是历史证据必须保留
   ⇒ 朴素 grep 会命中它 ⇒ **假红**
   ★ 剥的时候要**保留行数**，否则报错行号会错位

③ **只禁「数字 + 统计词」的共现**，不禁裸数字
   r"[0-9]+\s*(?:条|个|项|处)?\s*(?:通过|失败|跳过)|(?:通过|失败|跳过)\s*[0-9]+"
```

### 8 样例故障注入（8/8 全对）

| 样例 | 期望 | 实测 |
|---|---|---|
| 正文干净 | PASS | PASS |
| **注释里有 2243** | **PASS** | **PASS** ★ 最关键的反向验证 |
| 正文写「2243 通过 / 47 跳过 / 0 失败」 | FIRED | FIRED |
| 词在前「通过 4600 项」 | FIRED | FIRED |
| 量词「4600 个测试通过」 | FIRED | FIRED |
| 合法数字「Windows 10/11 / 约 150 MB / 72px / 3 秒」 | PASS | PASS |
| **「本次修了 12 个问题」** | **PASS** | **PASS** |
| 注释夹在正文中间 | PASS | PASS |

⇒ 「本次修了 12 个问题」不误伤，因为 `12` 后跟的是「个问题」而非统计词。
  但「本次修了 12 个**失败**用例」会命中 —— **这是有意的**，那种表述同样会腐烂。

### ★ 顺带修掉我那条 CI 守卫的盲区（复核查出）

同一次复核还发现：我上轮加的「默认套件不许静默 skip」那条守卫
**只 `grep '夹具缺失'`**，而 **libmpv 偶发 native 崩溃**时
7 条变成 `did not complete`，输出里**没有**「夹具缺失」字样
⇒ 守卫放行，而实际上「那 15 条一条都没跑完」。

⇒ 改成两条互补判据，**第二条才是根本**：

```bash
if ! echo "$out" | grep -q 'All tests passed'; then
  echo "::error::这 15 条门禁**没有跑完** —— 不是「缺件」，是 native 崩溃。"
  exit 1
fi
```

6 样例验证全对，**含第③条正是那个盲区**（旧判据在它上面会 PASS）。
且这一步加了 `continue-on-error: true` ——
`dart_test.yaml` 顶部记载 libmpv 崩溃率不低，**不该让它拦合并**。

## Alternatives considered

**A. 全文 grep + 排除注释行（`grep -v '<!--'`）。**
最强理由：一行 shell 搞定。
否决理由：**HTML 注释是多行的**（那段取证记录跨十几行），
逐行 `grep -v` 只能滤掉起始行，注释体里的「2243 通过」照样命中。

**B. 只扫「渲染后可见文本」（跑 markdown 渲染器）。**
最强理由：语义最准。
否决理由：**引入依赖**。而在一段里「剥 `<!-- -->`」与「只看可见文本」**等价**。

**C. 禁掉该节的**所有**数字。**
最强理由：最简单，绝不会漏。
否决理由：会逼着把「三端」「Windows 10/11」这类必要表述也改掉
⇒ **守卫不该逼人写坏文案**。

**D. 不加守卫，靠 code review。**
最强理由：零成本。
否决理由：**这一节的数字已经烂了 11 天没人发现** ——
说明它不会在 review 里被注意到，因为它看起来完全正常。

## Consequences

**★ 可迁移的判据**

```text
给「用户可见文案」加守卫时，三件事必须同时做：
① 限定作用域（只扫该关心的那节/那段）—— 全文扫必然误伤
② ★ 先剥注释 —— 文案里的注释常是**取证记录**，那是资产不是垃圾
③ ★ 只禁「会腐烂的形态」，别禁「裸数字」
⇒ 守卫不该逼人写坏文案；它要拦的是「承诺」，不是「数字」。
```

**★ 一条环境坑（本轮踩到）**

```text
守卫脚本里用 `✔`（U+2714）打成功提示
⇒ 在 Windows 控制台（GBK 编码）直接 UnicodeEncodeError 崩掉
⇒ ★ 脚本类交付物不要用非 ASCII 符号做装饰 ——
  CI 跑在 Ubuntu（UTF-8）不会暴露这个，本地才会。
```

**★ 与 build.yml 里既有的两条约定一致**

```text
① 显式 `shell: bash` —— windows runner 默认 pwsh 的
   `$ErrorActionPreference='Stop'` **管不到外部程序的退出码**
   ⇒ 用 pwsh 会假绿（同 build.yml:129-141 已记载）
② 用 `python3` 不是 `python` —— 后者可能指向 Microsoft Store 的桩程序
```

**已知上限**

```text
· 守卫只覆盖 `.github/release-notes.md` 的「关于本版本」一节。
  「本版更新」「功能」两节若将来也出现同类腐烂，需要各自加判据。
· 判据是**正则**而非 markdown AST。若将来那一节出现
  「2243 通过」但被写在**行内代码**或**链接文本**里，仍会命中
  —— 我认为这是可接受的（那也是用户会看到的内容）。
· 那条 CI 守卫加了 `continue-on-error: true` ⇒ 它**不拦合并**，
  只在日志里留 `::error::`。若 Owner 认为这 15 条必须拦合并，
  需要先解决 libmpv 的崩溃率，而不是去掉这个开关。
```

**何时该翻案**

```text
· 若发布说明改为从一个**结构化数据源**（如 CI 产物）自动生成，
  这条守卫就该改成「校验生成器」而不是「校验文案」。
· 若 libmpv 的崩溃率被根治（换版本 / 加重试 / 改夹具加载方式），
  `continue-on-error: true` 可以去掉，让它真正拦合并。
```
