# Agent Note: 半透明边缘的"毛边"必须在**有内容的背景**上量 —— 纯黑背景会让它与不透明**读数不可区分**

Status: implemented

## Problem

Owner 2026-10-27 反馈「弹幕那个**还是有毛边**」，附了截图。

这次故障的**真正代价不是那个像素**，而是：**它让三个人（含 Lead）连续改错对象，而每一轮都有"看起来可复核"的读数支撑。**

```text
上一份记录（`.agents/notes/proposed/bug-fix/2026-10-20-…-adjacent-badge.md`，至今 proposed）
断言：chip alpha=0.9994（**不透明**）vs badge alpha=0.5479
  ⇒ edgeStd 差 2760 倍（0.018 vs 49.634）⇒ 结论「毛边不是 chip，是旁边那枚 badge」
  ⇒ 它据此把"改 chip"列为三条弯路之一，并推荐 Owner 选"接受现状 / 调 badge 的 alpha"。
```

**Lead 按那份记录改了站标徽章（0.55→0.85）** —— 而 Owner 随后给截图指认：
毛边在**「弹幕」胶囊（chip）**上。**⇒ 改错了对象。**

## Decision

**判据：量一个半透明对象的填充/边缘，必须在"有内容的背景"上量。**
在纯黑背景上，`black@0.55` 与 `black@1.0` 的读数**不可区分**（都读成黑），
此时任何"它不透明"的推断都是**测量条件的产物**，不是对象的性质。

依据（用 Owner 截图复算，可复跑）：

```text
· chip 内亮度（无字处）      = 108.2
· chip 外同一帧的背景（反推） = 108.2 / (1 − 0.55) = **240**   ← 背景是亮的
· ⇒ chip 把它压到了 45% ⇒ **chip 确实是 `black@0.55` 半透明**
· 而旧记录量的那帧背景是**纯黑**：
    black@0.55 叠在黑底 ⇒ 结果仍是黑 ⇒ 与"不透明"读数**无法区分** ⇒ 它误判成不透明。
```

⇒ 因此旧记录的**排除法结论（"不是 chip"）建立在错误前提上**，
它列的那条"弯路"（改 chip）也就**站不住**。

## 本次落地

```text
① **回滚**站标徽章（0.55 保持不变 —— 它**未被 Owner 指认**）。
② **改真正的对象**：弹幕 chip `backgroundColor` 0.55 → **0.85**（Owner 裁定 A）。
   ⇒ 依据旧记录给的定量关系 `edgeStd ∝ (1−alpha)`：预期摆动 ≈ 16.7（**约降到 1/3**）。
③ 代码里**留档**：两处都写明"对象是谁、旧记录错在哪、为什么只在有内容背景上量"。
④ 门禁 `zz_t1064`（+9）把它钉成判据：
   · chip == 0.85 / 徽章 == 0.55（**两个方向都反面断言**）
   · `edgeStd ∝ (1−alpha)` 自证（阈值来自实测，不拍）
   · ★ **复算 108.2/0.45 = 240 > 200** —— 把"旧记录为什么翻车"变成可执行的断言，
     并带反面（chip 内亮度必须显著低于背景，否则"半透明"不成立）
   · 源码锚点：那段纠正说明必须留在文件里（防后人再按旧记录改）
```

## Alternatives considered

1. **按旧记录继续调 badge 的 alpha（我第一版做的）**。
   论据是最强的：那份记录有**六条像素证据**、有定量关系、有阴性对照，看起来极其扎实；
   而它明确把"改 chip"列为弯路。**这正是我照它做的原因，也是我错的原因。**
   **否决** —— Owner 的截图指认推翻了它的对象判断；而且我复算出了它**为什么**会判错
   （纯黑背景上的不可区分性）。★ **不是它不严谨，是它的测量条件有系统偏差。**

2. **只改 chip、不回滚 badge**（"反正两个都是半透明，一起调更彻底"）。
   论据：两者由同一套 pill 语言定义，观感一致性可能更好。
   **否决** —— 目标对象是**Owner 指认的那一个**。未被指认的改动 = 未经测量的改动
   （旧记录三次弯路的老毛病）。回滚是**纪律**，不是保守。

3. **把 chip 改成完全不透明（alpha=1.0）**，让摆动归零。
   论据：旧记录实测 alpha=1.00 时 edgeStd=0.239 ≈ 0，**效果最彻底**。
   **否决** —— Owner 选的是 A（0.85）：他表述是"**还是**有毛边"，即**要减轻**，
   不是"必须消失"。且变成实色会破坏三枚并排的层级线索（旧记录已论证）。

4. **再补一批静态图给 Owner 看**（而不是真机）。
   论据：旧记录正是这么做的（3 张图 + 每张该看什么）。
   **否决** —— 旧记录自己写了这条的边界：
   「静态图能展示'5 帧不一样'，但**不能复现'动起来是什么感觉'**」。
   ⇒ 这次改用**真机 + Owner 亲眼看**，正是把旧记录那条边界补上。

## Consequences

- **收益**：改对了对象（Owner 指认 + 复算支撑），预期"明显减轻"；
  且**旧记录的错误前提被写成可执行断言**，后来人不会再走同一条路。
- **代价**：chip 边缘仍有约 1/3 的摆动（不是归零）—— 这是裁定 A 的既定取舍。
- **已知上限（如实记）**：`edgeStd ∝ (1−alpha)` 这个关系来自旧记录的实测（三档点），
  **本轮没有重新实测**（那需要 5 帧动态底 + 像素仪，属另一条工作）。
  ⇒ 所以"降到 1/3"是**依据旧关系推出来的预期**，不是本轮实测结论。
  **判观感仍需 Owner 亲眼看**（两侧都没用眼睛验过归零后的效果）。
- **结构性教训（同族第 2 例）**：本批还有一例"**证据本身有前提错**"——
  `csp` 普查里 `Pan` 族"32 类"的族名（其中 20 个不是网盘）。
  ⇒ 共性：**读数的对象或条件错了，读数再精确也没用**。
  这与本批另一条纪律配对：**"红 ≠ 实现坏，绿 ≠ 通过"**（判据本身要被怀疑）。
