# Agent Note: 仓库里不出现任何具体视频网站的名字

Status: implemented

## Problem

这是**产品定位**问题，不是版权洁癖：仓库一旦写了「支持 X 站」，
它就从「通用播放器」变成「某站的客户端」—— 那是两件完全不同的事。
本软件提供的是**播放能力**；具体网站由用户自己放在本地的插件提供。

只在文档里写这条规矩不够：本仓已有教训 —— 规范写了、代码里照样犯。
凡是能机械判定的规矩，都要有一条会变红的测试。

## Decision

插件只放用户本地、不进仓库；源码 / 用户可见文案 / 文档 / **提交信息与 git 历史**里
都不出现具体视频网站名。

判据锚定在「**对接的某个具体视频网站**」上，不外扩：

```text
禁  具体视频网站 / 直播平台（用户在那儿看视频）
放  弹幕服务 / 自建媒体服务器 / 通用协议（如 iptv、tvbox 这类协议与配置格式名）
留  客户端自己要请求的端点主机名 —— 行级豁免，且必须标注它是可覆盖的默认值
```

机械门禁是 `test/t98_no_site_names_test.dart`，**白名单式**（扫描所有会发布的文本，
命中名单即报错），并带阳性对照 —— 否则一条「扫描关键词」的测试天然容易变成恒不绿的空转。

## Alternatives considered

- **把弹幕服务名也列进禁名单** —— 它最强的论据是「既然要中性化，就一次清干净」。
  否决理由：**过严**。判据锚在「具体视频网站」上；弹幕服务与自建媒体服务器不是视频网站，
  把它们的名字删掉不解决定位问题，反而误伤功能。

- **只写在文档里，不加机械门禁** —— 它最强的论据是零维护成本，且判断「是不是站名」
  本来就需要人。否决理由：本仓已实测过「规范写了、代码里照样犯」；
  能机械判定的规矩必须有会变红的测试，否则等于没有规矩。

- **黑名单式（列出所有站名去查）** —— 它最强的论据是误报少。
  否决理由：列不全，新网站天然绕过。

## Consequences

- **收益**：产品定位有机械保障；新站点出现时只需往名单加一个词。
- **代价与已知上限**：
  - 名单要人工维护，且**边界容易扩过头** —— 本项目已两次把不该禁的东西
    （弹幕服务、协议名）加进去又撤回。
  - 行级豁免是精确到行的，豁免标记必须是**唯一锚串**：用常见词当标记
    （例如用「弹幕」二字）等于整文件放行，那是假绿。
  - 扫描器自己递归遍历文件系统、不读 `.gitignore`，所以跳过范围必须在代码里
    显式表达；跳过写错就是覆盖漏洞。
- **重访条件**：产品定位改变（例如 Owner 决定做成某站官方客户端）。
