# Agent Note: 本轮把六条「纸糊门禁」修成真门禁 —— 每条都做了故障注入

Status: implemented

## Problem

本轮开始时，仓库里有一批**看起来在守、实际守不住**的门禁。它们不是没写，
而是判据作用在了错误的对象上，导致缺陷逃逸。

实证到的形态（每一个都有具体提交）：

```text
① 判据锁 API 名而不是不变量
   fullscreen_titlebar 的门禁写「必须调用 _exitPlayer」⇒
   换个函数名就红、换个地方 pop 就绿。守的是名字，不是「唯一出口」这个性质。

② 门禁读源码字符串，不读行为
   弹幕缓存文案的门禁 `src.contains('_mpvBytes > 0')` ⇒
   把三元表达式的两个分支**写反**，源码里那几个字符还在 ⇒ 门禁仍全绿，
   而用户看到的信息完全相反。

③ 被 skip 藏住的「确定会红」
   native-media 标签的测试默认跳过 ⇒ 全量跑时只体现为 ~N 计数器 +1，
   一句过时断言可以躺很久没人发现。

④ 门禁读工作区而不是 blob
   CI 上跑的和本地跑的不是同一份内容 ⇒ 行尾差异让注入行为不同，
   本地永远看不出问题，CI 上才红。

⑤ 门禁读被测对象时，对象被改写过了
   代理归因的门禁检查「错误分类是否正确」，但被喂进分类函数的是
   **给用户看的改写版文本**（`hideInternalUrls` 的产物）⇒ 恒判 proxy。

⑥ 判据把「能解释现象的原因」当成了「排除现象的证据」
   直播控件位置的核对里，用「外层有 ClipRRect 所以不可能溢出」反证
   「控件不会超界」—— 而**裁剪正是「只显示一半」的成因**。
```

这六条同属一类错误：**判据没有真正作用在被测对象上**。

## Decision

对每一条，做法固定为三步：

```text
① 先写「要防的缺陷」的精确描述（不是"测试一下这个功能"）
② 做故障注入：把缺陷人为还原，确认门禁变红
③ 还原后确认门禁仍绿，且 dart analyze 0 error
```

### 具体改法

| 提交 | 问题 | 改法 |
|---|---|---|
| `eb72f25` | 锁 API 名 | 改成守「唯一出口」这个安全属性（任何 pop 路径都必须经它） |
| 见 bug-fix | 读源码字符串 | 把文案抽成**顶层纯函数**，断言读返回值；并加**反向断言**（有值时不许出现"不占磁盘"） |
| `e363d2c` | 被 skip 藏住 | 用 `--run-skipped --plain-name` 单独跑出来，修断言为新行为 |
| `fbafd3d` | 读工作区 / 中文路径 | git 调用补 `-z`；否则非 ASCII 路径被转义成 `\344\270\255` 并加引号，`startsWith('lib/')` 直接失败 ⇒ **源码改动被静默放行** |
| `f47d2ed` | 被测对象被改写 | 判定与展示分家：`text`（原文）给归因、`display`（净化版）给用户 |
| 见计划 §十二 | 反证方向错 | 重查：`ClipRRect` 是成因候选，不是排除证据 |

### 六条里最危险的一条：中文路径静默逃检

`fbafd3d` 的真实机制：

```text
git diff --name-only 对非 ASCII 路径默认转义并加引号：
  "lib/\344\270\255\346\226\207.js"
⇒ 门禁里的 startsWith('lib/') 返回 false ⇒ 这个文件**根本没被检查**
⇒ 现象是门禁全绿，而它守的东西完全没看
```
★ 这类缺陷比「红」危险得多：红会有人修，绿没人看。

## Alternatives considered

- **给每个门禁加一行注释「本门禁已验证」** —— 它最强的论据是成本几乎为零，
  且记录意图本身有价值。
  否决理由：注释会过期。本轮实测到「注释里写了『我验过注入』，
  但代码里现在并不成立」的情形。**结论必须由可执行的东西守住**。

- **只修不改的门禁，不做故障注入** —— 它最强的论据是注入要跑两遍测试，
  在 4000+ 用例的仓里代价可观。
  否决理由：本轮六条里有**五条**是在做注入时才暴露的。不做注入等于不知道修没修好。

- **统一写一个「门禁框架」来消除这类错误** —— 它最强的论据是治本，
  一次投产能防止后来者再犯。
  否决理由：六条错误的共同点只是「判据没作用在被测对象上」，
  但**表现形式完全不同**（字符串 / 文件编码 / 改写文本 / 反证方向）。
  没有哪个框架能自动判断「你这条判据测的是不是你以为的东西」。
  ⇒ 改为**把判据写成清单进 AGENTS.md**，由人/agent 在写门禁时对照。

## Consequences

- **收益**：六条门禁现在真的能红；其中「中文路径静默逃检」这条修好后，
  此前所有非 ASCII 路径的源码改动才真正进入受管范围。
- **代价**：每条门禁多一轮「注入 → 观察变红 → 还原」的人工操作，
  且要在交付报告里留下读数。在 4000+ 用例的仓里，这是实打实的时间成本。
- **已知上限**：无法在测试里观测的东西（如真机引擎的文本输入管线）
  必须改用可稳定观测的等价判据，并在文件头写明理由 ——
  **不许**因为测不了就写一条恒真的东西充数。
- **重访条件**：当出现第七种形态时，应追加进
  [2026-10-12-gates-must-be-able-to-fail.md](../../../implemented/testing/2026-10-12-gates-must-be-able-to-fail.md)，
  而不是新开一篇。
