# Agent Note: 去掉 PR 规模门禁，改成「一条 PR 一件事 + 禁假绿」

Status: implemented

## Problem

曾经有一条按 diff 行数判红的 CI job（阈值 600 / 1200 行）。它反复造成
「为了过门禁而拆 PR」—— 拆出来的中间状态反而更难评审：一半的改动在
「为下一半做准备」的形态里，没有可验证的完整行为。

门禁本该回答「这次改动是否可信」，行数回答不了这个问题。

## Decision

删掉按 diff 行数判红的 job 与阈值。保留的**唯一**要求是「一条 PR = 一个功能域」，
判据是**标题描述的是不是一件事**，不设行数上限。

「不许夹带与本 PR 主题无关的顺手修改」仍然禁止，且与行数无关 ——
夹带 3 行的无关注释同样不允许。

## Alternatives considered

- **保留行数阈值，只调大** —— 它最强的论据是机械、无歧义、不需要人判断功能域。
  否决理由：只要阈值存在，就会继续制造「为过门禁而拆」的中间态；
  而真正该拦的夹带与混功能域，行数阈值本来就拦不住。

- **用「标题不含和 / 以及 / 、」当判据** —— 它最强的论据是能机械检查、无需人工判断。
  否决理由：单一功能域完全可能天然带「与」（例如「播放器与详情页统一用同一套底栏」
  是一件事）。关键词只是提示「是不是把两件事写进一个标题了」，答得上来就不必改。

## Consequences

- **收益**：一条 3000 行的单功能域重构是**好 PR**；一条 200 行但混了两个不相关修复的
  PR 该拆。判据回到「是否一件事」上，不再与规模挂钩。
- **代价与已知上限**：「是不是一个功能域」靠人判断，没有机械门禁。
  `git diff --ignore-all-space --ignore-blank-lines --shortstat` 仍保留，但它现在服务于
  「看清改了什么」——空白噪音会让人误读成巨型改动 —— 而**不是**「够不够格开 PR」。
- **重访条件**：出现大量「一条 PR 混多件事」导致评审失效的实例时，
  先加**功能域**判据，而不是回到行数阈值。
