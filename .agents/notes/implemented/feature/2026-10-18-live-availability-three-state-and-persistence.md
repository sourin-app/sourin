# Agent Note: 直播可用性 —— 状态三态化、启动零网络、分组语义修正

Status: implemented

> 同域：[2026-10-15-home-keeps-guest-source.md](../bug-fix/2026-10-15-home-keeps-guest-source.md)
> 那篇解决「首页把访客源弄丢」，属**数据保留**；本篇解决「直播可用性状态与缓存」，
> 属**状态表达**。两者都在处理「多源场景下用户看到的与真实的不一致」，但对象不同。

## Problem

直播这块在本轮暴露了三个独立但同源的问题：

```text
① 启动时全量探测所有源
   ⇒ 每个源都要联网探一次，串行 ⇒ 启动被拖到用户以为卡死。
   ⇒ 且这些探测结果**不持久化**，下次启动又全部重来。
   （Owner 的措辞是「这是错误的 一定要有缓存啊，不然这样子迟早要被拉黑」）

② 「可用 / 不可用」是一个布尔，但现实是三种状态
   ⇒ 「还没探过」「探过且不可用」「探过但结果过期」被压成同一个 false，
     用户看到「这个源没直播」而实际是「还没查」。

③ 空分组被兜底成「全部」
   ⇒ 用户明明把某个分组清空了，界面却显示全部频道，
     看起来像"我的设置没生效"。
```

## Decision

### ① 可用性持久化 + 启动零网络

`885c647`：直播源的可用性结果落盘，启动时**不发起任何网络探测**，
先把上次结果直接渲染出来，再按需延迟探测。

★ 判据在「启动阶段网络请求数 = 0」，不是「启动变快了」。
后者无法做成门禁（受机器影响），前者可以。

### ② 播放结果驱动的三态标记

`N15 直播可用性`：状态从「可用/不可用」改为三态，由**实际播放结果**驱动，
而不是由探测驱动。

```text
未探过   —— 从未尝试，不代表不可用
可用     —— 最近一次播放成功
不可用   —— 最近一次播放失败（带失败原因与时间）
```

★ 为什么必须由播放结果驱动：探测（发个 HEAD 或小请求）成功 ≠ 能播。
把探测结果当可用性，就会反复出现「显示可用，点进去黑屏」。

### ③ 空分组不再兜底成全部

`68617bc`：分组为空就显示空，不再回退到「全部」。

**同时**：搜索框从顶部移进右侧列表区域（Owner 明确要求
「直播的搜索框不要放在最上面，放在右侧的列表区域」），
并让已有分组可改名。

### ④ 全链路门禁：勾选 ⇒ 落盘 ⇒ 重启后仍在

`直播分组：补一条全链路门禁`：验证的不是「设置项存在」，
而是「用户勾选 → 写盘 → 重启 → 读回」整条链路。

★ 这条门禁的价值：它守的是**用户设置不丢**，而不是某个函数被调用。

## Alternatives considered

- **启动时并发探测所有源（而不是不探测）** —— 它最强的论据是并发后总耗时
  可以压到接近单个源，用户打开就能看到最新的可用性。
  否决理由：源可能有几十个，并发会对每个源站发起请求 —— 这正是 Owner 说的
  「迟早要被拉黑」。而且冷启动时网络未必可用，探测失败会把全部源误标为不可用。

- **可用性只用内存缓存，不落盘** —— 它最强的论据是不用处理缓存失效与版本迁移，
  实现简单且不会有"陈旧数据"问题。
  否决理由：不落盘就做不到「启动零网络」——每次启动都得重新探。

- **保留「空分组 ⇒ 全部」的兜底** —— 它最强的论据是空界面会让用户以为坏了，
  显示全部至少"有东西看"。
  否决理由：那会让用户的清空操作看起来没生效，等于**软件撒谎**。
  正确做法是空态显示明确文案（「这个分组还没有频道」）。

- **探测结果与播放结果合并成一个状态** —— 它最强的论据是少一个维度，
  UI 更简单。
  否决理由：两者的可信度差一个量级（探测成功不代表能播）。
  合并后无法表达「探测说行、播了不行」这种最常见的真实情况。

## Consequences

- **收益**：启动不再打网络；可用性状态能表达「还不知道」；
  用户的分组设置真正生效且重启不丢。
- **代价**：
  · 落盘引入缓存失效问题 —— 上次的结果可能已经很旧，
    需要展示「多久之前的结果」而不是假装它是当前的
  · 三态让 UI 复杂了一档（不是两色，是三色/三文案）
- **未完成**：Owner 本轮反馈「直播的弹幕和清晰度都没支持，
  在直播页还没进详情页，就应该把该有的直播控件都显示出来」——
  这是**信息架构变更**（把播放控件从详情页提到列表页），本轮未做。
- **重访条件**：当缓存的陈旧度开始造成误判（用户看到"可用"但打不开）时，
  需要给缓存加显式过期而非无限沿用。
