# Agent Note: "调半透明度"能治「一圈亮边」—— 方向对了才治，方向反了会**加重 20 倍**

Status: implemented

## Problem

Owner 2026-10-27 连发两张截图，两次都说「弹幕按钮**四个边还是有亮亮像毛边的东西**」。

```text
第一张（alpha 0.55，我改前）：内部 108.2 / 边缘 74.8
第二张（alpha 0.85，我改后）：内部  37.4 / 边缘 74.8   ← 边缘比内部**亮 2 倍**
⇒ 他一眼看出"还在"，而我一眼看不出方向已经反了。
```

**我在这一次故障里连续犯了两类错，都由"读数看起来支持我"喂大**：

```text
第 1 错（对象）：我改了**站标徽章**。依据是
  `.agents/notes/proposed/bug-fix/2026-10-20-danmaku-chip-edge-is-adjacent-badge.md`
  ——那份记录用六条像素证据断言「chip 不透明 ⇒ 毛边不是 chip，是旁边那枚 badge」。
  而 Owner 指的**就是这个 chip**。
第 2 错（方向）：对象改对后，我把 0.55 提到 0.85。结果是**把毛边做重了 20 倍**。
```

## Decision

**判据：拿半透明控件去"压住"它边缘的亮线时，必须先判定那条亮线来自哪一侧。
若是"控件自身底下的亮面从边缘漏出来"，则提高 alpha 会让内部更暗、亮线更明显 ——
方向相反。**

受控渲染实测（`test/zz_t1068_chip_layer_test.dart`，**纯红底** 1:1 渲染真 chip）：

```text
alpha   内部 RGB        内部 L   左缘 Δ   上缘 Δ   下缘 Δ
0.55    (114,111,115)   112.4    +1.8     −3.4     −3.0   ← 最干净
0.85    ( 38, 37, 38)    37.4    +38.8     —        —
1.00    (  0,  0,  0)     0.0    +76.2    +89.5    +89.6   ← 最严重
⇒ **alpha 越高，"边缘−内部"越大** ⇒ "调 alpha"与这个毛病**方向相反**。
```

★ 决定性线索：**纯红底上内部却是中性灰**（114,111,115 —— 不是红的）
⇒ chip **自己底下压着一层亮/白面**（黑@alpha 盖在它上面），
边缘 AA 像素把那层亮面按覆盖度漏出来 ⇒ 读成"一圈亮边"。
**病根在 chip 自身的构造，不在 alpha。**

⇒ 落地：**回滚到 0.55**（实测三档里最干净的一档），并把三段教训全部写进代码注释。

## Alternatives considered

1. **继续提高 alpha（我第 2 次做的，0.85）**。
   论据最强：旧记录给了定量关系 `edgeStd ∝ (1−alpha)`，且实测 0.55→49.634 / 0.85→16.740
   —— **"跨帧摆动确实降到 1/3"是真的**。而"摆动"看起来正是"毛"的同义词。
   **否决** —— 我把两件事混成了一件：旧记录量的是**跨帧摆动**（画面在动时边缘的稳定性），
   而 Owner 报的是**单帧就能看到的亮线**（静态对比度）。**半透明减轻前者、加重后者。**
   ⇒ 这是本批"**读数没错，错在读数的对象**"的又一例（与大类普查里 `Pan` 族"32 类"同族）。

2. **改成完全不透明（alpha 1.0）**，让亮线"归内"。
   论据：不透明后边缘 AA 只混黑背景 ⇒ 摆动数学上归零（旧记录阴性对照 0.239）。
   **否决** —— 受控渲染实测它**最糟**：左缘 Δ=+76.2、上下缘 Δ≈+89.6。
   原因：内部变成纯黑 (0,0,0)，而那层亮面漏得更彻底 ⇒ 亮线最刺眼。

3. **包一层"己方控制"的半透明黑容器**（`E_black55_materialcolor_wrapper`）。
   论据：把半透明度从 chip 挪到自己手里，chip 本体设 transparent ⇒ 从根上换掉那层亮面。
   **否决** —— 实测内部 L=250（几乎全白）⇒ **那层亮面还在**（在 Material 层，不在 chip），
   换包装没用。这反而**证明了病根不在 chip 的 `backgroundColor`**。

4. **改用不透明色模拟 55% 观感**（`D_opaque_black_with_55_visual`，`#FF726F73`）。
   论据：内部观感保持"半透明黑"（114 灰），而边缘 AA 变成 灰↔红 过渡（不混白）。
   **本次未采用但列为最优候选** —— 实测左缘 Δ 从 +1.8 涨到 +4.0、上下缘涨到 +13.6/+14.7
   ⇒ **它比 0.55 更差**。⇒ 我的假设被自己的实测否掉了（**没有因为"看着合理"就采用它**）。
   ★ 附带结论：0.55 的 Δ≈+1.8/−3.4/−3.0 说明**现状已经是三档里最好的**，
     真正要动的是**那层亮面的来源**（Material 层），而那是**观感取舍**，交 Owner 定。

## Consequences

- **收益**：止住了"越改越糟"（0.85 的 Δ=+38.8 已回滚为 +1.8）；把"截图判不了这条"
  （截图仅 88×67，采样点会打到图标上 —— 我因此误报过一次）变成了**可复跑的受控判据**。
- **代价**：**那圈亮边仍然存在**（Δ≈+1.8/−3.4/−3.0）—— 我没能去掉它，
  只证明了"现状是好的一档、且不能靠 alpha 去掉"。**这是如实结论，不是完成。**
- **判据化**：门禁 `test/zz_t1064_r2_badge_alpha_test.dart`（+6）现在守三件事：
  ① chip 与徽章都必须 0.55（且 `backgroundColor` **恰好 1 处** —— 防我回滚时插出重复属性）
  ② **受控渲染**：左/上/下三边 Δ 必须 ≤ +3.0
  ③ **阴性对照**：把 alpha 改 0.85 时 Δ 必须 >10（**证明 ② 有分辨力**，不是恒真）
- **同族教训（本批第 3 例）**：**"读数支持我" ≠ "读数支持我的结论"**。
  本例的读数是"跨帧摆动降到 1/3"（真），我的结论是"毛边变轻"（假）。
  ⇒ 与"红 ≠ 实现坏 / 绿 ≠ 通过"配对：**先问读数测的是哪件事，再问它支不支持你的结论。**
