# Agent Note: 判 DNS 是否被劫持，必须与权威通道真值对照 —— 「能解析」不是「解析正确」

> 那篇讲「量的对象错了」；本篇是它的镜像 —— **量对了对象，但读数的语义读错了**。
> 相邻：[../feature/2026-10-19-danmaku-panel-seven-items.md](../feature/2026-10-19-danmaku-panel-seven-items.md)

## Problem

用户报「内置两个 dan-api 根本用不了」。

内置实例都是 `*.vercel.app`，而本机访问它们全部超时。

当时的判据是 `getaddrinfo` **有没有抛异常**：

```text
InternetAddress.lookup('danmu-api-delta.vercel.app') → 返回了地址（没抛）
⇒ 判定：DNS 正常，问题在 TCP
⇒ 结论写成：「DNS 没被污染，断在 TCP 连接超时」
```

**这个结论是错的**，而且错得很自然 —— 因为读数本身是真的：

```text
真的：解析确实没抛异常
真的：TCP 确实超时（errno 10060，16.06s）
假的：归因。TCP 连的那个地址**本来就是错的**
      ⇒ 超时不是独立病因，是劫持的**后果**
```

拿 DoH（Cloudflare，绕开本机 resolver）对照后真相立刻清楚：

```text
域名                          本机 DNS                      DoH 真值                       判定
danmu-api-delta.vercel.app    74.86.17.48                  216.198.79.3 / 64.29.17.3      ✗
                              + 2a03:2880:…:face:b00c
danmu-api-kappa.vercel.app    108.160.173.207              216.198.79.67 / 64.29.17.67    ✗
                              + 2a03:2880:…:face:b00c
vercel.app (apex)             199.96.58.15                 216.198.79.131 / 64.29.17.131  ✗
                              + 2a03:2880:…:face:b00c
vercel.com（对照，能通）       64.239.109.193               64.239.123.129                 ✓
```

三条独立佐证：

```text
① face:b00c —— Facebook 的固定花样段，**三个** *.vercel.app 域名都返回它
② PTR 反查（证明了**归属**，比"看起来不像"强一档）：
     74.86.17.48      → *.sl-reverse.com（SoftLayer/IBM）
     108.160.173.207  → www.v.dropbox.com（Dropbox！）
     199.59.150.39    → r-199-59-150-39.twttr.com（Twitter）
     199.59.148.1     → r-199-59-148-1.twttr.com
     199.96.58.1      → ge-2-0-3.pao1.cr2.twttr.com
③ vercel.com 解析正确且 200 ⇒ 不是"DNS 整片坏"，是**针对性劫持**
```

### ★★ 并且伪造地址会**轮换**

```text
同一台机器、同一个域名：
  08:2x  danmu-api-delta → 74.86.17.48     + face:b00c
  08:4x  danmu-api-delta → 199.59.150.39   + face:b00c
         danmu-api-kappa → 104.244.43.182
  DoH 真值两次都是 216.198.79.x / 64.29.17.x（稳定）

Lead 复核：短时连采 3 次（间隔 2s）→ 三次一致
⇒ **不是"每次请求都变"，是"几小时的尺度上会漂"**
```

⇒ **任何"完整枚举伪造段"的做法都注定失败。**

## Decision

**判 DNS 是否被劫持，必须与权威/加密通道（DoH/DoT）的真值对照。**

判据写成两层（`DanmakuProbeReport`）：

```text
第一层（强证据，不需联网）：解析结果落在**已知伪造段表**里 ⇒ 直接定案 dnsHijacked
第二层（兜底）：解析成功 + TCP 连不上 + DoH 真值与本机答案**没有交集** ⇒ 同样定案
```

两层都**只用于解释失败原因**，不参与"允不允许连"（那会让误判变成功能不可用）。

### 表的定位：已知样本，不是全集

`kForgedAddressRanges`（数据驱动，9 条，**每条强制带 `evidence`**）：
PTR / DoH / 花样段，三者之一是依据，空依据 = 假绿。

```text
★ 明确写在表上方：命中即可定案（强证据）；**没命中不代表正常** —— 由 DoH 腿兜底。
```

**撤掉了 `199.16.x`** —— 它没有 PTR、也没在 DoH 里得到印证，
只凭"我记得它是 Twitter 段"就列进来，正是「看着不像」。
保留 `104.244.43.` 但标注「依据最弱：无 PTR，仅与 DoH 真值不符 ⇒ 删掉不削弱定案能力」。

### 用户可见文案必须把两者分开，因为操作完全不同

```text
dnsFailed    「域名解析失败（本机 DNS 不通）」
             ⇒ 换网络 / 修 DNS

dnsHijacked  「域名被解析到了错误地址（DNS 可能被劫持）」
             ⇒ **换 DNS（DoH/DoT）或开代理** —— 改弹幕地址没用
```

并且 detail 里**把本机地址与真值都摆出来**，用户不需要懂 DNS 就能看懂：

```text
有 DoH：
  本机解析到：74.86.17.48
  权威 DNS（加密查询）真值：216.198.79.3 / 64.29.17.3
  ⇒ 同一个域名，你这台机器拿到的和真实地址**不是一个东西**。

无 DoH（不编真值）：
  本机解析到：108.160.173.207
  这个地址落在**已知的伪造段**里（同一网段被实测判定为他人服务器）。
  ⚠️ 本次没能核对权威 DNS 真值 —— 但上面这个地址本身已经能说明问题。
```

## Alternatives considered

### ① 只看 `getaddrinfo` 有没有抛异常

**最强论据**：最省事、零网络依赖、跨平台，且"抛异常 = 域名不存在"这个语义是确定的。

**否决理由**：**它只证明"有答案"，不证明"答案对"。**
劫持的实现方式恰恰是"正常返回一个假地址" ⇒ 这个判据对本次的故障形态**结构性失明**。
我第一次就是这么判错的。

### ② 只看 `nslookup` / 系统自带工具

**最强论据**：系统自带、人人会用、输出格式熟悉。

**否决理由**：**它用的是同一个被劫持的 resolver** ⇒ 拿到的是同一个假答案。
用它复核劫持，等于用嫌疑人自己的口供证明他无罪。

### ③ 把 DoH 当作**前提**（没有 DoH 就不下结论）

**最强论据**：最权威，真值来源最干净；不给结论比给错结论好。

**否决理由**：**DoH 请求自己也要过网络。**
在"DNS 被劫持"的环境里，`cloudflare-dns.com` 也可能连不上。
把它设成前提会让**最需要这条诊断的用户**反而得不到结论。

⇒ 定位为**佐证**：拿得到就给出对照（证据最直观），拿不到就靠伪造段表定案。

### ④ 硬编码一个"完整"的伪造段清单

**最强论据**：实现简单，纯函数，零网络，可单测。

**否决理由**：**实测伪造地址会轮换**（见 Problem 末段）⇒ 任何枚举都只是"已知样本"。

⇒ 保留这张表（命中即可定案），但明确它是样本不是全集，并由 DoH 那条腿兜底。
表做成**数据驱动**（每条强制带 `evidence`），否则下一个人无法判断某条还能不能删。

### ⑤ 「把两个内置实例换成非 vercel 的域」

**最强论据**：最彻底 —— 换一个不被劫持的域名，用户什么都不用做。

**否决理由**：**没有可换的候选，且换域解决不了问题。**

```text
· 两个内置实例都是 *.vercel.app，没有非 vercel 的可替代品
· 实测这两个服务本体是**活的**（代理下 401 / 带 token 200）
  ⇒ 坏的不是服务，是本机到它的路
· 换一个"没实测过的第三方地址"进内置清单 ⇒ 违反本仓纪律
  （那张表有规矩：没实测过的地址不许进）
```

## Consequences

### 收益

```text
· 故障定位从"网络不通"精确到"DNS 被劫持"
· 用户拿到的建议从"换网络碰运气"变成"换 DNS / 开代理" —— 后者是真能解决问题的那个
· detail 摆出两个地址 ⇒ 用户不需要相信我们，自己能看见证据
```

### 代价（必须记住的）

```text
· **伪造段表是已知样本，抓不到新形态**。这是有意的取舍：
  换来的是"不需联网也能定案"（很多用户的 DoH 也被拦）
  ⇒ **表里没命中不代表正常**，DoH 那条腿不能删
· **多了一处联网点**（DoH）。已约束：只在**已判定连不上**时才发，超时 5s，
  失败即返回空表且**不影响主判定**
· **两张表会漂移**：面板与设置页共用同一份 `DanmakuProbeReport`（故实际只有一份）；
  若将来有人复制一份，这条约束就破了
· **轮换规律未知**：只采样了两次（+ 短时连采 3 次一致），
  不足以断言"轮换周期"。要确认得多采几次（会持续打 DNS，本轮没做）
```

### 门禁（8 条，每条对着一个具体的失败形态）

```text
① 每条依据必须非空且**含可复跑的取证方式**（PTR / DoH / 花样段 / 归属名）
   ★ 光非空不够：写"反正就是假"也能过，所以查关键词
② 表里不许有重复前缀
③ 反证：7 个 DoH 真值地址一个都不许被判成伪造（含 kappa 两次采样的两组真值）
④ 回归保护：轮换走掉的旧伪造地址必须仍能命中
⑤ 阳性对照：每条前缀自己构造样本喂回去必须命中（防前缀写错）
⑥ 有 DoH / 无 DoH 两种 detail 必须不同（否则"没有真值"这个事实被吞掉）
⑦ 无 DoH 时 detail 里**不许**出现 216.198. / 64.29.（那是编的）
⑧ 旧断言 `contains('不一致')` → `contains('不是一个东西')`
   ⚠️ 这是**文案有意改进**后的同步（不是放宽）—— 新断言在旧文案下会红
```

```text
注入：清空 `74.86.17.` 的 evidence  ⇒ -1 红
      把真值 replace 成"（真值已隐藏）" ⇒ -2 红
还原后逐字节相同；dart analyze 0 error
R3 五个门禁合计 73 条、相关既有 149 条 ⇒ 全绿
```

### ★ 一条不限于 DNS 的判据

```text
「能解析 ≠ 解析正确」的同族陷阱：
  · getaddrinfo 不抛 ≠ 地址对
  · File.exists 为真 ≠ 里面是我要的内容
  · HTTP 200 ≠ 返回的是我要的数据
  · 端口在监听 ≠ 服务在正常工作

⇒ 一般化：**任何"工具正常返回"的读数，都要再问一句「它返回的东西内容对不对」。**
   工具是否报错，只说明"调用成功了"，不说明"结果是对的"。
```

### 何时该翻案

```text
① 若发现 Vercel 真的把 *.vercel.app 迁到了本表中某个段
   ⇒ 该条必须删，并补 DoH 对照复验
② 若将来内置实例换成非 *.vercel.app 域 ⇒ 本表大部分条目失去意义，需按新域重测
③ 若某天 DoH 成为前提是可行的（例如本地内置一个可信 resolver）⇒ 可简化为单层判定
④ 若这张表**长期没有任何新增**且 DoH 腿反复单独命中
   ⇒ 说明表已过时，考虑只留 DoH 腿
⑤ 若确认了轮换规律（例如每 N 分钟换一批）⇒ 可以据此设计"采样多次取多数"的判据
```

## 原始读数（可复跑）

```bash
# ① 本机 DNS
python -c "import socket;print(sorted({x[4][0] for x in socket.getaddrinfo('danmu-api-delta.vercel.app',443)}))"

# ② 真值（DoH，绕开本机 resolver）
curl -s --max-time 12 "https://cloudflare-dns.com/dns-query?name=danmu-api-delta.vercel.app&type=A" \
  -H "accept: application/dns-json"

# ③ PTR（证明归属）
python -c "import socket;print(socket.gethostbyaddr('108.160.173.207'))"

# ④ 服务本体是活的（代理下；绕开被劫持的本地解析）
curl -s -o /dev/null -w "%{http_code}\n" --max-time 15 \
  "https://danmu-api-delta.vercel.app/87654321/api/v2/search/anime?keyword=a"
```
