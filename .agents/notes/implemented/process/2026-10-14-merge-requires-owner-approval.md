# Agent Note: 合并权限收归 Owner —— 提交可以，合并要 Owner 点头

Status: implemented

## Problem

CI 全绿就自动合并，看起来是效率优化，实际会造成两个可观察的问题：
Owner 常常一边测一边提问题，提前合掉会让后续问题基于旧版定位；
而且他还没来得及说「这条别合」。

这与「自主推进」不冲突：能不能自己判断怎么修，和能不能把它合进 main，是两件事。

## Decision

```text
commit / push / 开 PR   ⇒ 随便做（这是"存工作"，可回退）
merge PR / 关 PR        ⇒ 必须等 Owner 明确说「合并」
```

**不论改动多小**（错别字、注释、CI 修复）都先停下等 Owner 说合并。
不许因为「CI 绿了」就自己合。

## Alternatives considered

- **CI 全绿就自己合** —— 它最强的论据是反馈回路最短，单人开发时不必等。
  否决理由：它假设「Owner 已把问题说完」，而这个前提在实测中反复不成立。
  本条正是推翻这条旧许可的产物。

- **文档 / 错别字这类小事直接合** —— 它最强的论据是低风险、不值得占 Owner 的注意力。
  否决理由：判断「小不小」的成本比等待的成本更高，且「这条别合」的理由往往与改动大小无关。

## Consequences

- **收益**：Owner 的问题反馈始终基于他正在看的那一版；「先别合」这个决定始终来得及。
- **代价与已知上限**：合并这一步成为需要人参与的环节，交付节奏受 Owner 响应时间约束。
  自主推进的范围因此收窄到「自己判断怎么修、自己跑测试」，不含「合进 main」。
- **重访条件**：Owner 明确收回。
