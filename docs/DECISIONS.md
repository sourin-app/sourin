## A. 技术路线

### A1. 用 Flutter 重写，而不是继续修 Tauri + Vue 版（2026-09-22）

- **决策**：整个客户端重写为 Flutter（UI）+ Rust（业务）双栈，取代最初的 Tauri + Vue 实现。
- **为什么**：原版跑在 WebView2 上、走 Media Foundation 解码，而 Windows 默认不注册 HEVC 解码器
  MFT（实测 61 个 MFT 里零个 HEVC）—— 用户一遇到 HEVC 就黑屏。Flutter 版用 libmpv（自带完整
  FFmpeg，完全不碰 Media Foundation），从根上解决。
- **排除了什么**：在 Tauri 版里塞第三方解码器 / 让用户自己装 HEVC 扩展。
- **何时该翻案**：所有目标平台都自带可用的 HEVC 硬解与字幕/音轨处理能力，且 libmpv 在某个
  目标平台被证明不可用（许可证、商店政策、包体）。
- **出处**：[../README.md](../README.md)「这是什么」、[ARCHITECTURE.md](ARCHITECTURE.md)。

### A2. 业务逻辑全放 Rust，Flutter 只做 UI，dart:ffi 直调（2026-09）

- **决策**：数据源解析、插件沙箱、流代理、云同步、数据库都在 `rust/sourin_core`（cdylib），
  两侧用 **dart:ffi 直接调用**，不经过任何 IPC 层。Rust 侧只导出 7 个符号，命令走 JSON。
- **为什么**：① 原版 Rust 业务代码 81% 可原样复用；② 沙箱 / SQLite / HTTP 代理留在原生侧，
  Dart 侧零开销；③ 同一份 `.rs` 编出 Windows 的 `.dll` 与 Android 的三个 `.so`；
  ④ `cargo test` 直接测业务逻辑，不用起 UI。
- **排除了什么**：Dart 侧直写业务逻辑；本地 HTTP/WebSocket 服务做前后端分离。
- **何时该翻案**：FFI 边界成为主要开发瓶颈（例如每次改动都要重编 cdylib 并手动拷贝），
  或某平台禁止动态库加载。
- **出处**：[ARCHITECTURE.md](ARCHITECTURE.md)。

### A3. 流代理的预取开关按**实例**读，不按进程全局（2026-10-08）

- **决策**：`SOURIN_PREFETCH_DISABLE` 在**构造** `StreamProxy` 时读一次并存进实例字段。
- **为什么**：改前是每次请求现读全局环境变量，并发跑的测试会互相干扰（一个测试改了环境变量，
  另一个测试的行为跟着变）。
- **排除了什么**：让测试串行执行来规避干扰。
- **何时该翻案**：不再有并发测试，且需要运行期动态切换预取（那时应换成显式配置项而不是环境变量）。
- **出处**：[CONFIG.md](CONFIG.md)「运行期环境变量」；回归测试
  `streamproxy.rs::prefetch_switch_is_per_instance_not_process_global`。

## B. 仓库与流程

### B1. 走 PR，不直推 main；必需检查只列「真的在验证东西」的（2026-10-08）

- **决策**：`main` 开分支保护，任何直推被服务端拒绝（GH006）；必需检查只列 `Windows` 与 `macOS`
  两个 job，**不列** `Android` 与发 Release（它们在 PR 上会被 job 级 `if:` 判成 skipped）。
- **为什么**：没有第二双眼睛时拦不住的几类问题（分支永远走不到、断言恒真、改了 A 忘了同步 B、
  并发/时序）本仓**每一条都真踩过**，共同特征是「CI 全绿，问题在用户那里才爆」。
  而 skipped 的 job 会被报成 `Success` —— 列进必需检查就等于加了一条**恒过的假门禁**。
- **排除了什么**：把 Android / Release job 加进必需检查（实测 PR #1：它们列不列都不挡合并，
  真正挡住合并的是 `required_conversation_resolution`）。
- **何时该翻案**：Android / Release job 改成在 PR 上真的执行（不再 skip）—— 那时**应该**把它们
  列进必需检查。
- **出处**：[../CONTRIBUTING.md](../CONTRIBUTING.md)「这条规矩已经强制生效了」。

### B2. 去掉 PR 规模门禁，改成「一条 PR 一件事 + 禁假绿」（2026-10-12，Owner 指示）

- **决策**：删掉按 diff 行数（600 / 1200 行）判红的那条 CI job 与阈值。
- **为什么**：阈值反复造成「为了过门禁而拆 PR」，拆出来的中间状态反而更难评审；
  真正的门禁应该是「没有假绿」，不是「diff 多少行」。
- **排除了什么**：「标题不含和/以及/、」这类启发式判据（它曾是勾选项，与「按功能域判断」
  自相矛盾 —— 单一功能域完全可能天然带「与」）。
- **何时该翻案**：出现大量「一条 PR 混多件事」导致评审失效的实例时，先加**功能域**判据，
  而不是回到行数阈值。
- **出处**：[../CONTRIBUTING.md](../CONTRIBUTING.md)「一条 PR = 一个功能域」。

### B3. 合并权限收归 Owner：「提交可以，合并要 Owner 点头」（2026-10-14，Owner 原话）

- **决策**：commit / push / 开 PR 随便做；**merge 或关 PR 必须等 Owner 明确说「合并」**，
  不论改动多小。
- **为什么**：Owner 常常一边测一边提问题，提前合掉会让（a）后续问题基于旧版定位、
  （b）他还没来得及说「这条别合」。
- **排除了什么**：CI 全绿就自己合；「文档/错别字这类小事可以直接合」的旧许可（已被本条推翻）。
- **何时该翻案**：Owner 明确收回。**在此之前一律按本条执行。**
- **出处**：[../CONTRIBUTING.md](../CONTRIBUTING.md)「合并权限」。

### B4. 仓库里不出现任何具体视频网站的名字（2026-10-13，Owner 原话）

- **决策**：插件只放用户本地、不进仓库；源码/文案/文档/**提交信息与 git 历史**里都不出现站名。
- **为什么**：这是**产品定位**问题 —— 仓库一旦写了「支持 X 站」，它就从「通用播放器」变成
  「某站的客户端」，那是两件完全不同的事。本软件提供的是**播放能力**。
- **排除了什么**：把弹幕服务名也列进禁名单（**过严**，已撤回）；`iptv` / `tvbox` 这类协议与
  配置格式名不在禁名单（它们不是「某个具体的视频网站」）。
- **何时该翻案**：产品定位改变（例如 Owner 决定做成某站官方客户端）。
- **出处**：[../CONTRIBUTING.md](../CONTRIBUTING.md)「规矩三」；机械门禁
  `test/t98_no_site_names_test.dart`（含阳性对照，防正则空转假绿）。

### B5. 外部弹幕服务凭证在**构建期**由 secrets 注入，只挂步骤级（2026-10-12）

- **决策**：仓库里只留空占位符；三条发布构建的**步骤级** `env` 从 GitHub secrets 取值，
  构建命令用对应 shell 语法（Windows `$env:NAME`、macOS/Android `$NAME`）引用。
- **为什么**：① 该服务的官方文档「安全注意事项」明确允许开源客户端这么做；
  ② 挂 job 级 env 会注入到该 job 的每一个步骤，「全量测试」与第三方 Action 都能读到 Secret
  （CWE-94 注入面）；③ 用 `${{ }}` 文本插值会让含引号/`$`/反引号的 Secret 改变脚本解析。
- **排除了什么**：把凭证写进仓库；让用户自己填 AppId 输入框（Owner 明确要求删掉该输入框）。
- **何时该翻案**：该服务取消开源客户端凭证政策，或改为公开的免签名接口。
- **出处**：[CONFIG.md](CONFIG.md)「外部弹幕服务凭证（发版说明）」；门禁
  `test/t27_w11_ci_appkey_inject_test.dart`、`test/zz_t27_15_local_cred_inject_test.dart`。

### B6. 文档：根 README 只留定位 + 快速开始 + 索引，细节进 `docs/`（2026-10-15，Owner 指示）

- **决策**：把 README 的架构 / 构建 / 配置 / 平台 / 数据目录 / 主题 / 插件 / 测试 / FAQ /
  项目结构共 10 节拆到 `docs/`，根 README 收敛为定位 + 快速开始 + 文档索引；新增
  `docs/AGENTS.md`（开发入口）、`docs/DECISIONS.md`（本文）、`docs/RUNBOOK.md`。
- **为什么**：README 长到 1116 行后，改一处细节要在大文件里定位、评审 diff 噪音大；
  而「开工前必读」的内容与「查配置字段」的内容受众不同。
- **排除了什么**：另起一套新文档重写内容（会与现有正文分叉）—— 采用**搬家不改写**，
  并用脚本校验「原文每一行都能在目标文件里找到」。
- **何时该翻案**：文档再次碎片化（出现同一主题散落多篇），或 `docs/` 层级超过两层。
- **出处**：本次拆分提交；校验方式见该提交的提交信息。

### B7. 交互契约是**验收基准**，有意差异必须先问 Owner（2026-09-22）

- **决策**：[../PLAYER-CONTRACT.md](../PLAYER-CONTRACT.md) 与

- **排除了什么**：「新版体验更好所以改了」这类自作主张。

### B8. 「小工具目录」不进仓库：`.claude/`、`.probe*`、`.local/` 等本机痕迹（2026-10-08 起）

- **决策**：本机 agent 会话产物、一次性探针、临时脚本进 `.gitignore`；
  门禁扫描时也显式跳过这些目录（它们是**假阳性来源**，不是仓库内容）。
- **为什么**：它们只对本机/本人成立；让它们常驻脏状态会淹没真正的信号
  （曾有「常驻脏状态」把 git status 变成噪音）。
- **排除了什么**：把探针当作可发布的测试夹具（要发布的东西放 `test/`）。
- **何时该翻案**：某类工具变成团队通用（那时应移进 `tools/` 并正面纳入扫描范围）。
- **出处**：`.gitignore`；`test/t98_no_site_names_test.dart` 的 `_skipDirs`。

## C. 测试与门禁

### C1. `native-media` 标签用 `tags: {skip:}` 而不是 `exclude_tags:`（2026-09-25 实测）

- **决策**：依赖真 libmpv 的测试标 `native-media`，在 `dart_test.yaml` 里用 `skip:` 默认跳过，
  需要时 `--run-skipped --tags native-media` 放行。
- **为什么**：`MediaKit.ensureInitialized()` 加载 libmpv 时 `flutter_tester.exe` **原生崩溃**
  （访问违例 c0000005，证据链见 `dart_test.yaml` 顶部）；而 `exclude_tags:` 方案下
  「排除发生在选择之前」⇒ 排除了就**无法**用 `--tags` 放行（实测三选一，两条路径都 exit=79）。
- **排除了什么**：修崩溃本身（根因在第三方 `libmpv-2.dll`，改不了源码）。
- **何时该翻案**：上游修掉崩溃，或 Flutter 的 `flutter_tester` 不再丢弃崩溃信息。
- **出处**：`dart_test.yaml` 顶部；[TESTING.md](TESTING.md)。

### C2. 门禁必须能**真的变红**：新门禁先做故障注入 / 撤销验证（2026-10-12）

- **决策**：任何新增或改动的门禁，交付前必须把要防的缺陷**人为还原**，确认门禁变红；
  还原后仍绿 ⇒ 判定假绿 ⇒ 重写。交付报告里要附这次读数。
- **为什么**：本仓出现过**从构造上不可能红**的门禁（`return (v, v)` 让「顶底栏透明度相等」
  恒真），却「验过」了一个真实缺陷很久。
- **排除了什么**：只跑编译 / 只跑单测就宣称通过；为消掉评审意见而放宽断言、加 skip、加 ignore。
- **何时该翻案**：不翻案。这是硬规矩。
- **出处**：[../CONTRIBUTING.md](../CONTRIBUTING.md)「⑥ 规矩二」；[AGENTS.md](AGENTS.md) §4。

### C3. 「在某个提交上跑测试」必须用纯净 worktree（2026-10-14）

- **决策**：要证明「修复前应当红」的红基线，必须 `git worktree add` 检出目标提交到纯净副本再跑。
- **为什么**：工作树里有在途未提交改动时，测试实际测的是**工作树**，不是那个提交 ——
  会得到「已经修好所以全绿」的无意义结论。变异复红同理。
- **排除了什么**：`git stash` 后跑（会与并行工作冲突，且容易忘记恢复）。
- **何时该翻案**：不翻案。
- **出处**：[AGENTS.md](AGENTS.md) §6「验证纪律」；[../CONTRIBUTING.md](../CONTRIBUTING.md)。
