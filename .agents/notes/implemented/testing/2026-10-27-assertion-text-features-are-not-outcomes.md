# Agent Note: 判据的数量/文本特征 ≠ 判断的结果

Status: implemented

## Problem

同一批里**连续四次**踩到同一个形状：**判据看着对、注入也确实"红了别人的东西"，但它防不住本该防的那件事**。

```text
① 计数阈值（本次 D2 第一版）
   test/zz_n9_agg_channel_rail_test.dart ④组原先断言：
     RegExp(r'_isAggChannelsSection').allMatches(code).length >= 3
   把**内容区**那处消费点改成 `if (false)`（注释不留）
     ⇒ stripComments 后计数 = 3 ⇒ **断言 PASS** ⇒ **+23 全绿**
   而语义上：内容区分流失效 ⇒ 不走 `AggChannelsBlock` ⇒ 落到
     `else if (src.type == 'custom')` ⇒ `_LiveStrip(liveStrip: 空)` ⇒ 零尺寸
     ⇒ **聚合区块整块静默消失、不报任何错**（正是该组文件头写明的缺陷形态）。

② 文本特征全对，仍被一个 AND 项绕过（本次 D2 第二轮，复核者构造）
   补了"语义位置 + 肯定形态 + 反向对照"三层后，他把判据改成
     `if (_isAggChannelsSection(section) && false)`      ← 恒假附加条件
     ⇒ **+23 全绿**，而聚合区块照样不走 `AggChannelsBlock` ⇒ 整块静默消失。
   根因：三层都是**源码文本判据**（名字在不在窗口 / 形态对不对 / 注释剥没剥），
     **都不问"这个判断的**结果**是什么"**；加一个 AND 项**不改变任何文本特征**。
   ★ 且这不是刻意作弊：`if (x && 某开关)` 是后来的人加条件时**顺手就会写**的形态。

③ 对象选宽（`.probe/t66-scanner-blockcomment-scope.md`）
   zz_t66 的行内字面量扫描器只跳过 `//`、**不认 `/* */`**
     ⇒ 块注释里写 `'…：$e'`（"改前是什么"的说明）**会被计为犯规**。
   判据对象比它自称的宽一档。

④ 不剥注释 ⇒ 删代码留注释仍绿（t1053 的 N6-host 组，本批复核者 R5 实测）

⑤ 引用的**形态**决定判据成不成立（t94 的词边界守卫）
   守卫用 `(?<![\w$])ClassName(?![\w$])` 数引用 ⇒
     `showPanSettingsPage(ctx)`（类名前挨着 `w`）**不命中** ⇒ 判它"没人引用"。
```

## Decision

写"源码锚点"类判据时，**必须回答三问**，并且**只要答案里有"看源码文本"，就必须再问第四问**：

```text
Q1 它依赖什么**文本特征**？（名字出现？次数？位置？）
Q2 那特征能被什么"**不改语义的改法**"保留？
   —— 例如：计次数 ⇒ 删一个消费点仍够数；看名字在不在 ⇒ 加 `&& 恒假` 名字照样在；
        窗口里出现过 ⇒ 可以出现在注释里（未剥注释时）；名字前缀被挤 ⇒ 形态变了不匹配。
Q3 判断的**结果**由谁验？（有没有一条"看结果"而不是"看文本"的断言？）
Q4（Q3 答"没有"时必答）**能不能加一条只看结果的行为级兜底？**
```

**本次处置（按此表落地）**：D2 那条判据改成**四层**，前三层封文本特征，第四层封"条件闭合"：

```text
① 语义位置：断言消费点在 `AggChannelsBlock(` **紧邻之前**的窗口里（不是"全文任意位置"）。
② 肯定形态：断言是 `if (_isAggChannelsSection(` 而**不是** `if (!…)`（防"名字在、语义反"）。
③ 反向对照：断言**未剥注释**的原文里确实含 `src.type == 'custom'`
           ⇒ 证明 stripComments 真起作用（否则注释里的反例会让本组被注释满足）。
④ 条件闭合：断言 `if (` 里**只有判据自身** ——
   `RegExp(r'if\s*\(\s*_SectionBlock\._isAggChannelsSection\([^)]*\)\s*\)')`
   ⇒ 封死 `&&` / `||` 附加条件。
```

**④ 的代价是故意的**：将来真要在该处加合法条件 ⇒ 必须同批改这条断言 ——
那是个**语义变更**，就该被门禁看见。

**★ 但代价的完整范围比"加条件"宽（复核者第 3 轮真门禁逐条实测，我复现确认）**：
```text
· 多余括号 `if ((…))`       ⇒ **误红**（零语义变化）
· 去掉外层 `class` 前缀      ⇒ **误红**（同文件内合法重构）
· AND 绕过 / 取反            ⇒ RED ✓（两层确实挡住了）
★ 且误红**不是只长在最后加的那一层**：复核者第一版归给第 4 层，
  把第 4 层正则放宽后**仍然红** ⇒ 真凶是**第 2 层「肯定形态」**也不容忍 `if ((`。
  ⇒ **第 2 层与第 4 层各管一部分，只改最后一层不解决问题。**
★ 他复盘归错原因：**逐层单独验**过"每层有效"，**从没验过层与层的代价叠加**。
⇒ 处置：把代价写在注释里（含"遇到时按改断言处理、别怀疑实现坏了"），
  并**不采纳**"放宽两层正则"的推演版方案 —— 那条提案的作者自己标注"只推演没实测"。
```

**仍存的已知缺口（如实登记）**：真正**封闭**的形态是**行为级**（喂一个 key 匹配的 Section 进
`_SectionBlock`，断言树上出现 `ValueKey('home-agg-channels')`）—— 它只看结果，四层全绕过也躲不过。
本轮**没做到**（`_SectionBlock` 是私有类，要挂它得给生产文件开 `@visibleForTesting` 缝），
记为下批加固项。

## Alternatives considered

- **只加行为级兜底、不做四层文本判据** ——
  它最强的论据是**一步到位**：行为级是唯一真正封闭的形态，做了它前面四层都可有可无（更少的判据要维护）。
  否决理由：行为级需要**给生产文件开缝**（改 `home_page.dart`），而本次修复的窗口里
  `home_page.dart` 属别人的 writeScope，且正被复核者读 —— **在别人的窗口里改生产文件**
  会把"谁引入了什么"搅乱。文本四层的成本是**只改测试文件**，能在同一窗口内闭环。
  ⇒ 正确顺序是**先在能改的范围内把能封的封住，把需要开缝的那条如实记为缺口**，而不是
  为了"更彻底的方案"搁置修复。

- **把判据改成"跑一次真的 UI 挂载"（比行为级更广）** ——
  它最强的论据是覆盖面最大：不光分流，连渲染都验。
  否决理由：本次要防的是**分流路由**这一件事，铺到整页挂载会引入
  `listProviders()` → 真 FFI → 无核心必抛 的依赖（本批 home-ui 已如实记录过这个约束）。
  **判据的射程应与它自称防的那件事对齐**，不是越广越好。

- **不做第 4 层，只把注释改成"①②③ 仍可被 AND 绕过"（如实登记风险）** ——
  它最强的论据是**成本最低**，且 AND 绕过确实"不是刻意作弊、是顺手写法"。
  否决理由：第 4 层是**一行正则**，而它挡掉的正是"后来人顺手加条件"这个**最高频**的演化路径。
  如实登记风险不能替代封住最高频的绕过 —— 登记是给"当前做不到"的补偿，不是给"成本只有一行"的补偿。
  （对比：行为级那条**确实**受窗口限制，所以它才配用"如实登记 + 下批加固"处置。）

- **让复核者自己动手加第 4 层** ——
  它最强的论据是复核者最清楚绕过怎么构造。
  否决理由：`zz_n9_agg_channel_rail_test.dart` 是**被复核对象的一部分**，
  由复核者改它等于**自证**（本批明令禁止）。复核者的职责是**构造绕过并实测**，
  修复必须由持有该文件的人做 —— 他构造、我修、他再验，这个分工是对的。

## Consequences

- **收益**：把"假绿"从**靠人想到绕过**变成**四问清单**。本批两次都由复核者构造的绕过驱动修复，
  第二次（AND 项）如果只停在"①②③ 都验证有效"，会留下一条**顺手写法就能触发**的缺口。
- **收益（连带）**：逼出"注入本身也要证明它落到了文件上" —— 复核者第一次 injection 因 python 转义
  没生效、跑出全绿，他识别出那是**空转读数**（注入未生效 ≠ 门禁无效）后重做才得真红；
  若采信那个绿，会得出**完全反向**的结论（menu-glass 在 N7 也踩过同款：`python3` 是 Win Store 存根）。
- **代价**：判据变长（一条断言变成四条），且 ④ 会在"真加合法条件"时**故意报红**，需要同批改断言。
  这是**有意的摩擦**：那个改动是语义变更，本就该被门禁看见。
- **代价（实测比预期宽）**：文本正则对**语义等价的改写**天然敏感（多余括号、去 class 前缀都会误红），
  且**误红可能来自多层**（第 2/4 层各管一部分）⇒ 遇到时要**改断言**而不是怀疑实现。
  这是"用文本特征判语义"的固有代价，也是为什么根治方向是**行为级兜底**。
- **代价（方法论）**：**逐层单独验 ≠ 验过层的叠加**。复核者正是据此归错过一次层级
  （把两层共有的误红只归给最后加的那层）。⇒ 验"多层判据"时要**跑代价矩阵**（每个变体 × 每层）。
- **代价**：Q4 的"行为级兜底"在本仓常需要开缝 ⇒ 会积累"如实登记的缺口"。
  本批做法是**在 `.probe/` 与代码注释里都写明"未做"，并说明原因**（不许含糊成"已有兜底"）。
- **边界**：本条只管**源码锚点类**判据。行为级判据（真挂载 + 真交互）不受此限 ——
  它们的 Q1 答案本来就是"不看文本"。
- **重访条件**：若本仓为 `_SectionBlock` 开了 `@visibleForTesting` 缝（下批加固项落地），
  本条应就地把"仍存的已知缺口"改成"已由行为级兜底覆盖"，并互链那条新笔记。
