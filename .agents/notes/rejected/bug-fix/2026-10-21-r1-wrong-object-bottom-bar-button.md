# Agent Note: R1「弹幕按钮一圈毛边」—— 我查错了对象（不是 chip，是底栏按钮白字的抗锯齿）

Status: rejected — 原判断（「会『毛』的是站标徽章 alpha 0.55」）作废；Owner 原话指向**底栏那枚「弹幕」按钮**，成因是**白字抗锯齿半像素**，非缺陷。

> **本篇是对 [「弹幕按钮一圈毛边」不是 chip 的问题，是旁边那枚半透明徽章](../../proposed/bug-fix/2026-10-20-danmaku-chip-edge-is-adjacent-badge.md)
> 的否定。** 那篇的 `## Decision` **不改**（保留「当时怎么想的」），本篇用相对链接指回去。
> ⇒ 按 AGENTS §7.1 第③条：决定翻转必须新开一篇并互链，禁止改写原 `## Decision` 成反面。

## Problem

Owner 的反馈是一句话：

> 「就是那个**弹幕**的按钮，一圈毛边」

我把这句话读成了「**弹幕 chip**」（顶栏那枚显示「弹幕 128」的 pill），
然后一路查下去：

```text
第 1 轮：查弹幕 chip            ⇒ 干净（impliedAlpha 0.9994，edgeStd 0.018）  ← 对象就错了
第 2 轮：查站标徽章 alpha 0.55   ⇒ edgeStd 49.634，找到"会动"              ← 错上加错
第 3 轮：穷举顶栏 5 个候选       ⇒ 发现 topbar gradient 62.18               ← 仍在错的区域
第 4 轮：加形状标注论证"只有站标徽章有一圈" ⇒ 得出"只可能是站标徽章"        ← 结论错
```

**而正确答案早就写在台账里**（`docs/notes/plan-round-66.md:458`，2026-10-19 定案）：

```text
| R1（18:2x）| 弹幕按钮一圈毛边 |
  ★★★ 定案：成因是白色文字的抗锯齿半像素，不是缺陷。
  Owner 原话（:2183 逐字）：「就是那个弹幕的按钮，一圈毛边」
  ⇒ 指的是**底栏那枚按钮**，不是 chip。

  三条证据（真树读数，按 danmakuToggleKey 定位）：
  ① 按钮内 2640 px 里 2380 px（90.2%）跨帧方差 > 20 ⇒ 它**根本没有背景层**
     （`TextButton.styleFrom` 只有 visualDensity + padding，无底色）
  ② 字缘像素 184 个，100% 比 2px 外更亮，亮度 p50=p95=max=255（纯白）
     ⇒ 那圈「边」就是白字的抗锯齿半像素
  ③ 字缘亮度 5 帧恒为 255（方差 0）⇒ 静态抗锯齿，不是动态透光

  ★ 不做任何产品改动：消除抗锯齿会让文字变锯齿；
    给按钮加半透明底是「引入新设计」而非「修缺陷」。
```

`docs/round-66-owner-summary.md:34` 也早已指出过这件事：

> 「门禁守的是『弹幕 chip』，你说的是**底栏按钮**，不是同一对象」

**两条现成的记录都指向「对象错了」，而我开工时一条都没读。**

## Proposal

被否决的提案是（原文见 [proposed 笔记](../../proposed/bug-fix/2026-10-20-danmaku-chip-edge-is-adjacent-badge.md)）：

> 弹幕 chip 本身干净；会「毛」的是紧挨着它的**站标徽章**
> （`black@0.55` 半透明 pill，`edgeStd` 49.634）；
> 建议 C（接受现状），次选 A（把 alpha 提到 0.85）。

具体做法：给 chip 的边缘加 `Clip.antiAlias`、把站标徽章的 alpha 从 0.55 提到 0.85，
以消除「紧邻高对比控件造成的边缘观感问题」。

**这个提案在「对象」这一层就已经错了** —— 它研究的是顶栏的 chip 与站标徽章，
而 Owner 说的是底栏那枚按钮。因此它后续的全部读数（哪怕测得很准）都不回答他的问题。

## Decision（rejected）

**撤回原判断。** 会「毛」的**不是**站标徽章，**不是**弹幕 chip，而是：

```text
底栏那枚「弹幕」按钮（key = player_bottom_bar.dart:567 danmakuToggleKey）
其「一圈毛边」= 白色文字（18px 图标 + 「弹幕」标签）压在视频上的
**抗锯齿半像素**，随字缘自然产生。
```

**结论：非缺陷，不改产品代码。**

- 消除抗锯齿 ⇒ 文字变锯齿，更差；
- 给按钮加半透明底 ⇒ 那是**引入新设计**（会让它看起来像一个「块」），
  不是「修缺陷」，需单独的设计裁决。

**若 Owner 不接受这个观感**，正确的问法不是「哪一枚有毛边」（他答不上来），而是二选一：

> 底栏「弹幕」两个字外面有一圈淡淡的灰边，这是字形抗锯齿。
> 要让这圈边消失，只能给按钮加一块半透明底（会让它看起来像一个「块」）。
> 您想要：**A 保持现状 / B 加底片？**

★ 选 B 的实现已知：加底，与 `_BarIconButton` 的 active 态一致。

## Alternatives considered

| 方案 | 结论 |
|---|---|
| **① 保持现状** | **采用**。抗锯齿是字形渲染的正常结果，不是渲染缺陷 |
| ② 给按钮加半透明底 | 台账已裁决为「引入新设计」，需单独设计裁决。**若 Owner 选 B，走这条** |
| ③ 消除抗锯齿（如关掉 `antiAlias` / 用位图字） | 否决：文字会变锯齿，比现状更差 |

**另有三条被证伪的假设**（来自原 proposed 笔记，其读数仍然有效，只是**对象不相关**）：

| 假设 | 实测 | 结论 |
|---|---|---|
| 加 `Clip.antiAlias` 能去掉 chip 的毛边 | 边缘**更亮** 1.59 亮度级 | 方向反了 |
| chip 边缘在闪烁 | chip `edgeStd` 0.018，比不透明对照还稳 | 不成立 |
| chip 边界落在非整数像素 | 像素框 107.0/213.0 **全整数** | 不成立 |

⇒ 这三条对**弹幕 chip** 的结论依然成立，只是**Owner 说的不是弹幕 chip**。

## Consequences

### 这份判断错误的代价（必须记账）

```text
· 四轮测量（edgeStd / 两把独立尺子 / 穷举 5 候选 / 形状标注）全部用在**错的对象**上
· 产出了一篇结论错误的 proposed 笔记（本篇否定它）
· 产出了一份给 Owner 的决策材料（三档 alpha 对照图 / 整排一致性图）——
  对象错，材料也错
· 组内两条现成记录（plan-round-66.md:458 / owner-summary.md:34）都在说"对象错了"，
  我没有先读
```

### ★ 根因：测量越精密，越不会去问对象对不对

```text
我在 R1 上的四轮，每一轮都在**提高测量精度**：
  edgeStd → 两把独立尺子（交叉验证）→ 穷举全部候选 → 加形状维度
每一轮都让我更确信"我在正确的地方"。

而"对象对不对"这个问题，**一次都没问**。
⇒ 精密测量给人一种"已经站在正确位置"的错觉：
   越量化，越觉得"我都测到这个精度了，方向肯定没错"。
```

**这条与 PITFALLS 里「判据作用在错误的对象上」是同一族，但更具体**：
那条讲的是「判据作用在错误的测量点」；这一条讲的是
**「整条研究路线作用在错误的对象上，而且精度提升会掩盖它」**。

**可操作的做法**：
```text
开工第一条命令，不是测量，而是：
  grep -rn "<Owner 的原话关键词>" docs/notes/plan-round-66.md docs/round-66-owner-summary.md
⇒ 先确认「他说的那个东西在我们的代码里叫哪个 key / 哪个文件」。
⇒ 若台账已有定案 ⇒ **直接采用，不要重查**；只在"质疑该定案"时才动手。
```
