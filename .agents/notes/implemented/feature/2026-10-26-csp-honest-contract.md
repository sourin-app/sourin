# Agent Note: csp 类的诚实契约（空结果、镜像回退、放行与代理）

Status: implemented

## Problem

给 `csp_PanWebShare` / `csp_4KZhinan` 写 `CspSite` 四件套时，两个"看起来无害"的写法各自变成一类缺陷，
且都是**交叉复核**才抓出来的（写的人自己看不出来）：

```text
① 假支持：list() 解析出 0 条仍返回 Ok([])
   → 上层 csp/provider.rs 原样透传 → 站点 200 但模板改版/风控壳页时，
     用户看到"这个源没内容"。而同文件的 home/detail/play 都给了可读 Err
     ⇒ 不是设计决定，是漏了一条纪律。

② 代理冒充宕机：本机 HTTP_PROXY=127.0.0.1:7890，
   不直连时**所有 host 都返回 502 ip=127.0.0.1**
   → 只看那一轮会把"16 个镜像里 9 个可用"判成"全宕"，
     进而把整个类错误地写进"暂不可用"清单（并且真网络用例会红）。
```

两者都是"**把观察不到当成不存在**"：没解析到 ⇒ 说没内容；没连上（其实是代理） ⇒ 说站挂了。

## Decision

csp 类的四条硬约束：

1. **空结果必须报错，不许当"没内容"**。`home`/`list`/`detail` 任一解析出 0 条 ⇒ `Err` 并写明
   可能是"模板改版/风控壳页"，把判断权交回用户。只有 `play` 允许"成功但没有可播地址"这种语义
   （它返回的是**网盘分享页 URL + Referer**，且 label 里明写"（分享页）"，转直链属第 20 项）。
2. **镜像回退要能自证**。`fetch_first` 顺序试 `ext.site` 里的镜像、首个成功即用；
   全失败时**汇总前 N 条失败摘要 + 总条数**（而不是只回最后一个镜像的错误 ——
   否则 16 个里 15 个超时、最后一个是 522，用户只会看到 522，误以为整个类挂了）。
3. **远端可用性只能直连复测**。本机存在系统代理时，`curl` 与 `reqwest` 都会走它；
   判"站点是否活着"必须 `--noproxy '*'`（或显式禁用代理），并且把这条写进文件头注释。
4. **不新增运行时**。`csp_4KZhinan` 的 HTML 解析用本仓已有的 `regex`，局限（不做 DOM 树）写在注释里；
   `Cargo.toml` 与本批零 diff。

## Alternatives considered

1. **`list()` 空结果 `Ok([])` + 上层按"空列表"显示"暂无内容"**。
   这正是缺陷本身：把"我没解析到"渲染成"这个源没片子"，用户会去怀疑源而不是模板。
   **否决** —— 而且它与同文件另外三个方法的做法自相矛盾。
2. **`fetch_first` 只保留最后一个错误（现状）**。
   省一点内存，但把"15 个失败"的信息全丢掉，排障时必然误导。**否决**。
3. **把镜像探测结果做全局缓存（sticky）**，现在不做 —— 它是**性能**优化（实测三次调用 122.86s，
   几乎全是跳过死镜像 × 20s 超时），与本篇的**正确性**议题不同，单独排期。
4. **给 `csp_4KZhinan` 引入一个 HTML 选择器库**。
   更省事，但要新增运行时依赖（本仓纪律：不新增运行时）。**否决**，用已有 `regex` + 写明局限。
5. **把"全宕"的类从注册表摘掉**。
   会低报覆盖，且镜像会漂（`sd.sduc.site` 稳定 522，但兄弟镜像 `shandian.blog` 稳定 200）。
   **否决** —— 标"可用但慢/镜像不稳"才是事实。

## Consequences

- 收益：两个类共覆盖 8 个源（`PanWebShare` 6 + `4KZhinan` 2），且失败时给的都是**可读原因**而不是空数据；
  文档层面同步修掉两处"会直接骗到插件作者"的漂移（`host.http.raw` 的 `headers` → `setCookie`、
  最小示例缺 `@id` 头注释）。
- 代价：`list()` 改为空即 `Err` 后，**真的没有内容的源**也会报错而不是空列表 ——
  这是刻意的：错误文案里写明"可能改版/风控"，比静默空列表更接近事实。
- 代价：`csp_PanWebShare` 的串行镜像重试**慢**（122.86s）。已登记为待改（失败摘要 + 整体 deadline + sticky），
  本轮未做；`csp::route(` 目前**无生产调用点**，所以这个慢还到不了用户眼前，但接线前必须补。
- 残留（如实登记）：`csp_4KZhinan` 的 `play` 落点是网盘分享页，要"真能播"卡在第 20 项（需真账号）；
  `csp_Bili` + `csp_PanWebShare` + `csp_4KZhinan` = 18/94 源，其余 72 类仍在"尚未实现"。
