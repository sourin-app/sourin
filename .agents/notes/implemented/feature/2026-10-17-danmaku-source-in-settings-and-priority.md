# Agent Note: 弹幕源入口提到设置一级，且用户配的 dan-api 优先于本机弹弹play

Status: implemented

## Problem

两件事，都不只是「加个入口」：

```text
① 发现性缺陷：能力其实早就全实现了（DanmakuEndpoint、两个偏好键、地址框、
   测试按钮都在 widgets/danmaku_settings_dialog.dart 里），但那是个**播放页**的弹窗
   ⇒ 用户在设置页从头翻到尾看不到一个「弹幕」字样。
② 优先级倒置：改前 ExternalDanmakuClient 取端点的顺序是
   显式参数 → 若无则 _unsignedLocal 时直接返回 null → 否则读用户偏好。
   而宿主的判据 usingLocal = localStatus.online && !forceOfficial 里，
   online 是「本机 2080 **或** 自建后端」共用的一个标志
   ⇒ 本机弹弹play 一在线，用户配的 dan-api 就**永远轮不到**。
```

「代码写完了」与「功能可用了」之间差一次接线 —— 这与本仓记过的同类教训一致。

## Decision

```text
① 设置页一级「内容源与插件」组**第一行**放「弹幕源」入口，
   副标题实时显示状态（未配置 / 已配置：<地址>）；
② 点进去是二级页 lib/ui/settings/danmaku_source_page.dart
   （服务地址 + Token + 测试连接 + 清除 + 状态行）；
③ 取弹幕的**优先级**：显式参数 → 用户配的 dan-api → 本机弹弹play(2080) → 官方。
```

Independent: 弹幕源入口位置与优先级。与「发送入口」是弹幕功能的两个不同侧面，互不取代。

## Alternatives considered

- **把两个 TextField 直接塞进一级页列表** —— 它最强的论据是少一次跳转。
  否决理由：一级页是一列入口行（行高约 56），地址 + Token + 测试 + 状态是四个控件，
  塞进去会破坏整页节奏；而 Owner 要的是「能被发现」，一条带状态的入口行就满足。

- **新增「数据源优先级」开关让用户自己排** —— 它最强的论据是给用户完全控制权。
  否决理由：用户说不清也不想说；而「显式配了地址」本身就是最强的意图表达。

- **探到 dan-api 才优先（而不是「配了就优先」）** —— 它最强的论据是更稳妥：
  确认服务真的在才切换。否决理由：宿主那次 probe 探的可能是 2080，
  拿它当 dan-api 的依据是**错的读数**；真的连不上会由请求自己失败，
  且宿主的「改用官方」回头路仍然可用。

- **抽一个共享 widget 复用弹幕面板里的自建服务表单** —— 它最强的论据是消除重复。
  否决理由：那两处场景不同（播放中调节 vs 静态配置），硬绑在一起得不偿失；
  两者读写**同一对偏好键**，改哪边都立刻生效。

## Consequences

- **收益**：用户在设置页一级就能发现弹幕源配置；显式配置的 dan-api 不再被本机服务遮蔽。
- **代价与已知上限**：
  - 表单逻辑与弹幕面板**有意重复**了一份（约 100 行）。
  - 一级页副标题在每次 build 时重算（纯同步读偏好，零网络 ——
    这是硬约束：build 里绝不发探测请求，否则设置页一打开就打网络）。
  - 只配了 2080、没配 dan-api 的机器行为逐字不变。
- **重访条件**：
  - 出现「用户配了 dan-api 但想临时用本机弹弹play」的真实需求 ⇒
    那时给的是**显式选择**（同「改用官方 API」那个按钮），而不是把优先级改回来。
  - 弹幕面板与二级页的表单开始各自演化出不同字段 ⇒ 那时才抽共享组件。
