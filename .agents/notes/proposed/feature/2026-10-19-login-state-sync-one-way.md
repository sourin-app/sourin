## Problem

CS-1 落地后，用户换机器的真实路径是**两条并存的**，不是一条：

```text
WebDAV 凭据同步   ⇒ 只有**上行**（本机 → 云端 data/credentials.enc）
备份导出 / 导入   ⇒ 完整双向（导出含加密凭据 → 新机器导入后恢复）
```

也就是说：**新机器上"同步"一趟，登录态不会自己过来。**

这条事实已经实测确认，不是推断（见下面 `## 为什么不能只做上行而不说` 的读数）：

```text
新机器 B：SyncEngine::sync_credentials(Some(pass)) 后
  pushed = 0
  note   = "凭据未同步：没有任何已保存的登录态"
  本机 plugins/.data/fake-provider-a.json 是否存在 = false   ← ★ 关键
```

`sync_credentials` 从头到尾**没有任何 `backend.get("data/credentials.enc")`**：
它读本机 `.data` → 加密 → `put` 上去，就结束了。

## Proposal

### 现状语义（已实现，本笔记要固定的就是它）

```text
方向    本机 → 云端          （唯一方向）
远端路径 data/credentials.enc
冲突    后写覆盖（无合并）
取回    必须先「备份导出」拿到含凭据的 zip，再在新机器「导入」
```

### 若将来要做自动下行，两种可能语义 + 各自代价

#### 语义 A：启动时拉取，"云端更新则覆盖本机"

判据可以用远端 `Last-Modified` 或密文头部的时间戳。

```text
代价：
· **覆盖会打掉本机更新的登录态**。典型场景：
    家里 PC 登录了账号 X（较新）
    公司 PC 上还留着三天前登录的账号 Y
    ⇒ 公司 PC 开机 ⇒ 被云端那份覆盖 ⇒ 用户在那个源上"莫名被登出/换号"
· 而且要回答"本机从没设过口令怎么办"：命令行/无 UI 启动时不能弹口令框
  ⇒ 要么阻塞启动、要么静默跳过（后者又回到假绿）
```

#### 语义 B：逐源 LWW 合并（像 favorites 那样）

把每个 `provider` 当成一条带 `updated_at` 的记录。

```text
代价：
· **凭据不是可合并的记录**。它没有天然的时间戳 ——
  `plugins/.data/<id>.json` 里是插件自己写的键值，插件不会告诉我们
  "这个 session 是什么时候换的"
· 就算我们加时间戳，也解决不了"两台机器同时登录了**不同账号**"：
  合并的结果只能是二选一，而用户可能真的想两台用不同账号
· 会话有效期问题：远端那份可能已经**过期**，覆盖本机有效的登录态
  ⇒ 用户从"能看"变成"不能看"，这是最坏的一种"同步"结果
```

### 用户该怎么做（必须让用户看得见）

```text
换新机器  ⇒ 用「备份导出 → 导入」（不是"同步"）
两台都在用 ⇒ 各登各的；同步不会互相覆盖（因为只上行）
```

这条已经在 UI 上落实：

```text
sync_panel 的凭据状态行：
  「凭据将同步：N 个源（仅上行：本机 → 云端；从云端取回请用「备份导入」）」
  ★ 文案常量 = CredentialsStatus.directionNote（门禁断言的是同一个常量）
备份导入对话框：
  「口令不对时整次导入会失败（不会只导一半）」
```

## Alternatives considered

- **双向同步（语义 A 或 B）** —— 见上面 Proposal 的两段代价分析。
  最强论据是"用户心理预期：同步了就该两边都有"。
  否决理由：**覆盖掉本机更新的登录态**是比"要手动导入"严重得多的失败 ——
  前者让用户从能用变成不能用，后者只是多一步操作。
  且"两台机器用不同账号"是真实需求，合并语义无法满足。

- **同步时若本机没有 `.data` 且云端有 ⇒ 提示"云端有登录态，要恢复吗"**
  —— 这是 A 的一个温和变体，不自动覆盖、只提示。
  否决理由：它需要**口令**才能判断"云端有没有登录态"（密文无法看出内容），
  而口令在钥匙串里、可以读到 —— 技术上可行。但它把"同步"这个动作
  变成了"可能要弹框"，破坏了自动同步（无人值守）这个前提。
  ⇒ 记为**将来可选的折中**，但不作为默认。

- **不做凭据同步，只做导出导入** —— 提案的 Alternatives 里已否掉
  （Owner 明确要求两者都要）。这里不重复。

## Acceptance criteria

```text
① sync_credentials 只 push：新机器同步后本机 .data 仍为空
   ★ 已有实测读数（见 Problem 节）
② UI 状态行必须同时含「上行」语义与「导入」出口
   ★ 门禁：zz_t66_cs1_credentials_gate_test.dart 的 ③-b 组（4 条）
③ 若将来加了自动下行 ⇒ 本条笔记必须翻案（见下节）
```

## Risks

```text
· 用户仍可能以为"同步"包含下行 ⇒ 换机器后发现要重新登录。
  缓解：状态行写清 + 导入对话框说明。但**用户可能不看状态行**。
  ⇒ 缓解不彻底，这是本决策的已知代价。
· 两条路径并存本身有认知成本：用户要记住"同步"与"备份"各自管什么。
  提案当初分开两者的理由是「云盘没网时还能用文件传」，
  这个理由在凭据这里同样成立（没网也能带 U 盘走）。
```

## 何时该翻案

```text
出现以下任一信号 ⇒ 重新评估自动下行：
① 用户明确反馈"换机器后要重新登录很烦"（而不是"我该怎么做"）
② 出现"多设备同时使用"的真实诉求，且用户接受"后登录的覆盖先登录的"
③ 插件存储格式演进到带 updated_at（那时语义 B 才有判据可用）
```
