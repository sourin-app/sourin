# Agent Note: Release notes 用列表而不是 Markdown 表格

Status: implemented

- 日期：2026-10-21
- 适用：`.github/release-notes.md`、`lib/ui/widgets/release_notes.dart`

## Problem

更新弹窗（`showUpdateDialog`）里的版本说明，用户看到的是**原始 Markdown 源码**：

```text
| 平台 | 文件 | 说明 |
|---|---|---|
| Windows 10/11 (x64) | Sourin-Setup-1.3.0.exe | 安装版（推荐）：… |
```

2026-10-21 真机验证时拍到（`.probe/independent-dialog.png`，127,480 B），
窗口 1280×800，弹窗压在设置页上。

根因是**两侧各自都「对」**：

```text
渲染器  lib/ui/widgets/release_notes.dart:12-14
        // # 明确不支持的（遇到了就按纯文本显示，不报错）
        // 表格、图片、引用块嵌套、HTML 内联。
        ⇒ 设计上不支持表格，遇到就按纯文本输出（这是**声明过的**行为）

内容    .github/release-notes.md 有 4 张表、31 行 `|...`
        ⇒ 而正文确实包含表格
```

⇒ 不是 bug，是**两个合法的决定碰在一起**产生的可见缺陷。

### 为什么三条真机判据抓不到它

AGENTS.md §6 的三条判据（`Unhandled Exception = 0` / 窗口渲染 / 弹窗弹出）
全部通过 —— 它们判的是「**有没有发生某个事件**」，没有一条判「**内容对不对**」。
弹窗弹出来了但内容是坏的 ⇒ 三条全绿。

## Decision

**改内容，不改渲染器**：把 `.github/release-notes.md` 里的 4 张表改成列表。

并加机械门禁 `test/zz_t66_release_notes_no_table_test.dart`：
release notes 正文里不许出现以 `|` 开头的表格行。

### 为什么是「改内容」而不是「加表格支持」

```text
① release_notes.dart 的设计决定明确：「语法很窄，不值得为此加一个包
   （它还会拖进 `markdown` 与一整套解析器，而本仓正在为安装包体积把关）」
   ⇒ 加表格支持会**推翻这个决定**，而那需要单独一篇笔记说明为什么翻案。

② 表格解析一旦引入，就要处理：对齐、嵌套、转义、超宽、合并单元格…
   每一样都是新 bug 面，而收益只是「我们自己写的表格能显示」。

③ release notes 是**我们自己的内容**，改成列表零成本、零风险、立即生效。
```

★ 判据：**能用改内容解决的，不要改解析器。**

## Alternatives considered

**① 给 `release_notes.dart` 加表格渲染。**
拒：推翻既有设计决定（体积 + 语法很窄），且引入对齐/嵌套/转义/超宽等新 bug 面。

**② 不管**（认为"release notes 内容以后会注意"）。
拒：2026-10-21 这一版用户看到的就是坏的。而且**下次仍会有人写表格** ——
没有机械门禁的约定等于没有约定。

**③ 让运行时把表格降级成某种排版**（比如按 `|` 切列渲染成两列）。
拒：那是"半个表格解析器"，比 ① 更差 —— 既引入复杂度，又做不对。

## Consequences

- 用户看到的版本说明从「`|` 竖线 + `---` 分隔行」变成正常的列表排版。
- 门禁 `zz_t66_release_notes_no_table_test.dart` 守住「正文里不许有表格行」。
  它有一条**独立成条**的阳性对照（造含表格样本 ⇒ 必须扫出 3 行），
  以及一条「合法列表不误报」的负向对照 ——
  否则一个永远返回空的坏扫描器也会让主断言变绿。
- **新增约束**：以后写 release notes 只能用列表，不能用表格。
  这条约束的代价是排版表现力，收益是内容一定可读。
- **何时该翻案**：如果将来 renderer 因为别的需求（例如支持图片）
  已经引入了完整的 Markdown 解析器，那么"表格"就是附带能力，
  这条约束可以撤销 —— 但要新开一篇笔记，并删掉那个门禁。

### 未覆盖

- 门禁只扫 `.github/release-notes.md`。若将来 release 正文有第二个来源
  （例如 CHANGELOG），需要把它的路径加进门禁的扫描列表。
- 「本版更新」那一节由 `tools/gen_release_notes.py` 生成，
  该生成器**目前不产出表格**；本门禁覆盖的是生成结果所在的整个文件，所以也覆盖它。
