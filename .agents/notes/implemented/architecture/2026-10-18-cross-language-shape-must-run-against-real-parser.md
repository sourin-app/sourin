# Agent Note: 跨语言边界的数据形状，必须用对面的解析器真跑一遍

Status: implemented

## Problem

第 66 轮给某个站点插件实现弹幕读取时，返回的数据形状是「照着看起来合理的字段名」写的：

```js
// ❌ 第一版
{ time: 12.5, text: '名场面', mode: 5, color: 16711680 }
```

而宿主 Dart 侧的 `DanmakuComment.fromJson`（`lib/core/danmaku.dart:231-233`）**逐字只读三个键**：

```dart
final cid = _asInt(j['cid']);
final p   = j['p']?.toString() ?? '';
final m   = j['m']?.toString() ?? '';
if (cid == null) return null;        // ← 整条丢弃，不抛异常
```

⇒ 自造的 `text` / `time` / `mode` / `color` **一个都不会被读到**，
表现是：**弹幕加载"成功"，但一条都不显示，且不报错**。

这个 bug 的隐蔽性在于三层叠加：

```text
① 不报错 —— 没有异常，日志干净
② 有返回 —— 插件确实返回了数据，宿主也确实收到了
③ 形状"看起来对" —— time/text/mode/color 是完全合理的字段名
⇒ 排查时会怀疑网络、怀疑鉴权、怀疑服务端、怀疑渲染，
  很难想到"字段名对面根本不认识"
```

而且同一轮里，这个插件的作者（同一个 agent）**已经在另外两处做了实测**
（错误分类、query 拼接），唯独形状是凭"我记得契约是这样"写的。

## Decision

**跨语言边界的数据形状，必须用对面的解析器真跑一遍**，不能靠记忆或"看起来合理"。

具体做法（三条，缺一不可）：

```text
① 写代码前先贴一段**真实形状的样例 JSON**，让对面语言的解析器跑一次
   —— 不是"读代码确认"，是"喂进去看结果"
② 断言解析**成功条数**与**字段映射**（模式/时间单位/类型），
   不只断言"返回了非空"
③ 故意留一条**缺必需字段**的样本，验证它被丢弃 ——
   这反过来证明"补位逻辑"（Rust 侧 fill_missing_cids）不是多余的
```

本轮验证记录：

```text
喂入 4 条（3 条带 cid + 1 条故意不带）
⇒ 解析成功 3/4，模式 [scroll, top, bottom]
⇒ 第 4 条被 fromJson 丢弃（印证宿主行为）
```

Independent: 方法论：跨语言数据形状必须用对面解析器真跑。它约束的是验证手段，不取代任何具体实现决定。

## Alternatives considered

### A. 靠"读宿主代码 + 记忆契约"来保证形状正确

**这是最省事、也最自然的做法** —— 契约就在宿主源码里，读一遍不就行了。

放弃理由：本轮的 bug 正是这么产生的。读代码时看到 `WireComment` 结构体、
看到 `p`/`m` 字段名，但**没有注意到 `p` 是四段逗号分隔的复合字段**
（`时间秒,模式数字,颜色,用户ID`），也没注意到 `cid == null` 会整条丢弃。
「读过」不等于「理解到位」，而**跑一遍会立刻暴露**。

### B. 在插件里写一份 shape 校验，自己校验自己

**这看起来更工程化** —— 有 schema 校验，听起来很稳。

放弃理由：**自己校验自己等于没校验**。如果我对形状的理解是错的，
我写的校验器也会按错的理解写。必须是**对面的解析器**（宿主真实的 `fromJson`）
来判，那才是独立信源。

### C. 等宿主侧加"形状不符就报错"的严格校验

**这是根治** —— 让静默丢弃变成显式报错。

放弃理由：这是**下一轮该做的事**，不是本轮能等的。宿主 `fromJson` 返回 null
的设计有其历史原因（容忍上游脏数据），改成抛异常会影响所有现有插件。
⇒ 记为本轮未解决的改进项。

## Consequences

**收益**：
```text
· 拦下了一个"全部弹幕静默丢弃"的 bug（本轮实际发生）
· 建立了"跨语言边界必须真跑"的判据
· 门禁扩到 39 条，其中 8 条专钉形状（含"不许残留自造字段"）
```

**代价**：
```text
· 每次跨语言改动都要多一道"喂样例"的工序
· 需要能跑起对面语言的运行时（本轮用宿主真实 QuickJS + Dart 解析器）
```

**没有解决的**：
```text
· 宿主 fromJson 在形状不符时**静默返回 null**，不报错也不留痕。
  本轮靠"人工喂样例"发现，而不是靠系统自动发现。
  ⇒ 建议下一轮：在 fromJson 里加 debugPrint（仅 debug 模式），
    或在 Rust 侧的 fill_missing_cids 里统计"被丢弃条数"并上报。
```

## 附：同一轮里「静默失效」的三个同类样本

本轮共发现三个"写了但没生效、且不报错"的问题，形态各异但根因同源：

```text
① api() 不支持 opts.query，传了被静默忽略
   ⇒ 请求缺参数，本地看起来"发出了一个合法请求"
② danmakuList 返回自造字段名
   ⇒ 数据全被丢弃，本地看起来"加载成功了"
③ LiveChannelList.header 声明了、构造了、从没被渲染
   ⇒ 传进去的内容不显示，本地看起来"参数传对了"
```

共性：**没有任何一处会报错**。这类缺陷只能靠「跑一遍看结果」或「渲染树实测」发现，
不能靠读代码或跑单测（单测若按同样的错误理解写，也会绿）。
