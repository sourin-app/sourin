# Agent Note: 删除前先证明归属 —— "重复"是需要证据的判断

Status: implemented

## Problem

批末"工程整洁清场"时，我按"同一份产物只留一处"的纪律删除 `.probe/` 下的日志：

```bash
rm -v .probe/lead-full-suite-final[0-9]*.log .probe/lead-full-suite-r4.log .probe/lead-full-suite-r4b.log
```

**删掉的是 10-25/26 历史轮次的产物（`final2`~`final12`），不是本批的。**
判据错在：我按**文件名模式**（`final*` / `r4*`）推断归属，
**既没查 mtime、也没查引用**。

后果（逐项核实，见 `.probe/incident-deleted-historical-suite-logs.md`）：

```text
· final4 承载的「第 29 轮 Dart 全量读数」**未内联**在任何文档 ⇒ **永久丢失**
· final8 是一条"半降级"判断的原始依据 ⇒ 失去可复核性
· final5/final6 读数**已内联**在 plan-bak*.md ⇒ 实质无损
· final2/3/7/9-12 无文档引用 ⇒ 仅文件本身
★ `.probe/` 在 `.gitignore:103` ⇒ 不在版本控制里 ⇒ **一删即永久**
  （复核者逐条排除：git / 回收站 / VSS 卷影 / 别处副本 / spill 缓存 ⇒ 均无）
```

## Decision

**删除任何产物前，"归属"必须由证据判定，不能由文件名或印象判定。** 两条必备检查：

```bash
# ① 引用数：有没有文档/脚本把它当证据或输入
grep -rl -- "$(basename "$f")" . --include=*.md --include=*.sh --include=*.ps1 | wc -l
# ② mtime：它是本轮的中间产物，还是历史轮的证据
stat -c '%y' "$f"           # 与本轮开始时刻比较
```

**两个条件必须同时成立才允许删**：

```text
引用数 == 0  **且**  mtime 落在本轮窗口内 ⇒ 可删
（只查 mtime 会漏"被引用"；只查引用会漏"是本轮的可再生中间物"。）
```

**若被引用**：先看引用处是否**已内联读数**。
```text
已内联    ⇒ 可删，但删前记一句"读数已内联在 <文档>:<行>"
未内联    ⇒ **不许删** —— 引用即已成为证据链的一环，删掉它 = 引用变成悬空断言
            （本事故里 final4 正是这种：文档写"见下（final4.log）"，
             而"见下"那段读数**从未写进文档** ⇒ 删了即不可复原。）
```

**若目标目录不在版本控制里**（本仓 `.probe/` 被 gitignore），**阈值更高**：
"宁可留着" —— 因为没有 `git restore` 这条退路。

## Alternatives considered

- **一律不删 `.probe/`（最保守）** ——
  它最强的论据是**根除风险**：没有删除就没有误删。
  否决理由：本仓的整洁纪律（`user` 规范）明确要求"任务结束主动清场、不留工程垃圾"，
  且 `.probe/` 已达 206MB（含历史轮次的大日志与截图）。
  **一律不删会把"清场"变成一句空话**，反而使目录膨胀到没人敢动。
  ⇒ 正解是**给删除一个可机械执行的判据**，而不是取消删除。
  （对照：本次误删的 `final*` 若按本判据跑，`final4/5/6/8` 会因**引用数 > 0**被拦下 ——
   判据确实能挡住这次事故。）

- **删除前先把待删文件挪进一个 `trash/` 目录、过一周再清** ——
  它最强的论据是**给了后悔窗口**，比"删前检查"更宽容（检查漏了也能捞回来）。
  否决理由：本仓 `.probe/` 本身就是**被 gitignore 的临时目录**，
  在它里面再建一层回收站会让目录更臃肿，且"过一周再清"在**单批任务**里没有执行者
  （下一批的人不知道要不要清）。
  ⇒ 更契合本仓的做法是**保留证据型产物（有引用的）**、只清**可再生的中间物**。

- **靠 git 兜底（把 `.probe/` 纳入版本控制）** ——
  它最强的论据是**彻底解决**：一旦入库，`git restore` 就是通用退路，本事故不会发生。
  否决理由：`.probe/` 含**探针产物、真机截图、日志**（本批 206MB）；
  入库会污染仓库体积与历史，且其中有些产物含**本机路径/真实数据痕迹**
  （本仓另有隐私门禁要求扫整棵已发布树）。
  ⇒ 保持 gitignore 是对的；**代价**就是"删除不可逆"，只能靠判据约束 —— 这正是本条的位置。

## Consequences

- **收益**：给"清场"一个**可机械执行**的判据（引用数 + mtime），
  把"我觉得这是重复的"变成"我测过它是重复的"。
- **收益（诊断力）**：本事故还暴露了一个更一般的问法 ——
  **"这是证据还是垃圾？"** 判据是"**有没有别的文档在引用它**"。
  被引用即不可删（哪怕它看起来像临时产物）；这比按目录/命名/大小判断都准。
- **代价**：每个删除动作多两条命令；且"引用数"是**快照判断**
  （今天无引用，明天可能被引用 ⇒ 但删除只需在**当下**成立即可）。
- **代价**：保留了 `plan-bak*.md` 里指向已删文件的**悬空引用**（见 §处置）。
  这是刻意选择：改历史文档会让"当时的引用"失真；
  集中在 `.probe/incident-deleted-historical-suite-logs.md` 登记损失并从台账互链，
  比逐个改动更干净。（遗留后果：读历史台账的人仍会看到"见下（final4.log）"。）
- **★ 族谱（重要）**：本条与**同批**另外两条纪律是**同一形状在不同动作上的复现**：
  ```text
  · 恢复源被引用为参照物前，先与现盘 diff 一次
    （2026-10-27-restore-target-must-be-diffed-against-worktree.md）
  · 判据的"代价"要写全（不能只写直觉那一条，要写实测出的完整范围）
    （2026-10-27-assertion-text-features-are-not-outcomes.md）
  · 本条：删除前先证明归属
  ⇒ 共同点：**把"我认为"换成"我测过"再动手。**
  ⚠️ 所以本条**不是**一条孤立的"删文件要小心" ——若只记住那一句，
    下次会在改判据 / 恢复快照 / 写注释上再犯同形状的错。
  ```
- **重访条件**：若将来 `.probe/` 有了自动快照/垃圾回收机制，
  本条的"两条命令"可被工具替代 —— 那时保留"引用数 + 时效"这条判据本身即可。
