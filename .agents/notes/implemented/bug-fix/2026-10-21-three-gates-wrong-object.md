## Problem

本轮（第 66 轮）批量跑「本轮动过的 170 个测试文件」，捞出 2 条红。
查下来两条都不是产品缺陷，而是**判据本身错位**：

### 红 1：`t98_no_site_names_test.dart` —— 两个正确判据互相排斥

```text
t98         ：'cctv' 不许出现（别泄露站名）
台账判据 d  ：key 必须逐字等于 "live_cctv_real_test.dart"（防腐化）
⇒ 同一个字符串同时承担了两个语义：**站点名** / **文件标识符**
```

豁免本来能解决，但根因不是"少了一条豁免"，而是：
**当两个判据在同一个数据上互相排斥时，说明这个数据同时承担了两个语义。**

### 红 2：`zz_t66_selfaudit_crossgate_test.dart` —— 注释被判成代码

原判据：`s.contains('D:\WishProject')`（裸 contains，不剥注释）。
实测命中的是 `zz_t66_danmaku_send_safety_gate_test.dart:79-95` 的**注释**：

```text
 *   Platform.script   = file:///D:/WishProject/sourin-flutter-spike/main.dart
 *   实测 `Directory.current = D:\WishProject\sourin-flutter-spike`
```

那是一段**排障证据**（证明"为什么 `Directory.current` 可靠"），
不是"代码里写死本机路径"。让它红 = **逼人删证据换绿**。

### 顺带一条（同批修）：`t118_control_bars_link_test.dart` ⑦ —— 钉了缩进

```dart
final i = src.indexOf('                    _TopBar(');   // 20 个空格
```

`ddb0794`（本轮 N11 底栏改造）把挂载点从"以缩进开头"改成
`builder: (context, _) => _TopBar(`（行尾）⇒ `indexOf` 返回 **-1** ⇒
报 `Expected: >0, Actual: -1`。
**顶栏功能没变**，只是挂载点的缩进位置变了。

## Decision

### ① 内部台账豁免：三个条件同时成立

```text
① 路径在内部台账目录：.agents/notes/ 或 docs/notes/
② 该行**同时**含 `_test.dart`（即引用的是一个测试文件名）
③ 只豁免那一行 —— 同文件里其它行照样报
```

豁免表写成**数据**（`const _internalLedgerPrefixes`），不藏在 if 里的字符串判断 ——
这样"新加一个内部台账目录但忘了登记"会被自检抓住。

⚠️ **不豁免**：`docs/` 根目录（用户可见文档）、`lib/`、`test/`。

**并加边界自检 5 条**（`★★★ 内部台账豁免的边界`）：
台账+文件名引用 ⇒ 豁免 / 台账+普通叙述 ⇒ 不豁免 / `lib/` ⇒ 不豁免 /
`test/` ⇒ 不豁免 / `docs/` 根 ⇒ 不豁免 / 前缀拼错 ⇒ 不豁免。

★ 豁免是**削弱门禁**的动作，所以它的边界必须被另一条判据钉住，
否则今天加一条、明天加一条，门禁会静默失效。

### ② selfaudit：剥注释后判代码；注释命中只打印

```text
代码里有本机路径     ⇒ 红（fail）
只有注释里有         ⇒ 打印 [SELFAUDIT] 覆盖度，不红
```

用仓里既有的 `test/_support/strip_comments.dart`（**不抄第二份**）。

### ③ t118 ⑦：不钉缩进，用正则找符号

```dart
改前：final i = src.indexOf('                    _TopBar(');
改后：final ctor = RegExp(r'(_TopBar\()').firstMatch(src);
```

判据从「带 20 个空格的字节序列」改成「`_TopBar(` 出现，且它前 400 字符里没有 `if (`」——
**与缩进几个空格、是否在行尾无关**。

### ④ 三者共同加的覆盖度读数

```text
[T98-COVERAGE] 扫描文件=1050  行级豁免命中=61  内部台账豁免命中=621  offenders=2
[SELFAUDIT]    本机路径出现于 1 个门禁的**注释**里（代码里 0 处）
```

没有这些数字，「豁免了 621 处」与「扫描器坏了、一处都没扫到」
在输出上**完全无法区分**（两者都是"绿"）。

## Alternatives considered

**A. 把 `native-media-audit.json` 改成数组 `[{"file": "..."}]`，绕开 t98。**
最强理由：不动别人的门禁，纯数据重构。
否决理由：**没用**。文件名那串字符还在 JSON 里，t98 照样命中 ——
它扫的是**文本内容**，不是"键的位置"。这个方案我实测想过，是错的。

**B. 放宽台账判据 d（key 允许写别名）。**
最强理由：一劳永逸，不再与 t98 冲突。
否决理由：会毁掉 d 的防腐化能力 —— key 与文件名不再一一对应后，
"测试改名了但台账没跟着改"就查不出来了，而那正是 d 存在的理由。

**C. 删掉那段注释（selfaudit 那条）。**
最强理由：一行删除，立刻绿。
否决理由：**为了绿而销毁证据**。那段注释记录的是真机实测路径，
它解释了"为什么 `Directory.current` 可靠"这一设计判断。
本仓反复记过这条错（`docs/AGENTS.md` 的「不许为了过门禁而删证据」）。

**D. 让 t118 的判据改成"顶栏渲染树上有没有"（行为级）。**
最强理由：行为级比源码级强。
否决理由：该文件整组都是**源码级判据**（`t118` 的定位是"源码契约"），
单条改行为级会与该文件其余 15 条不一致，且行为级在这里拿不到
"顶栏是否常挂"的信号（它测的就是"有没有外层 if"这个**结构**事实）。
⇒ 保留源码级，只把"钉缩进"改成"钉符号"。

## Consequences

**收益**

```text
· t98 的豁免从"隐式放行"变成"三个显式条件 + 5 条边界自检"
  ⇒ 豁免面可判、可审、不会被随手加宽
· selfaudit 从此区分「代码写死」与「注释记录」，且用仓里唯一的 stripComments
· t118 ⑦ 不再被格式化/重构打红（一天内同族第二次：e363d2c 修过另一条）
· 三个判据都加了覆盖度打印
```

**代价**

```text
· t98 多了一次豁免判断（每行一次 startsWith + contains），1050 文件略慢；
  实测整条 t98 仍 6 秒内跑完，可接受。
· 豁免表是"白名单"，天然有腐化风险 —— 靠 5 条边界自检压住。
· selfaudit 现在**不**判"注释里有本机路径"，若将来有人把敏感路径
  写进注释（如真实用户目录），它不会红。这是有意的取舍：
  注释里的路径换机器不坏，且删了会丢证据。
```

**已知上限**

```text
· t98 还剩 1 处未解决（2 条输出）：`.agents/notes/.../danmaku-send-safety-gate.md:72`
  引用的是**私库源码名** `bilibili.ts`，不是测试文件名 ⇒ 条件②不成立 ⇒ 不豁免。
  它属于另一个作者、且按裁决不该由本豁免覆盖 ⇒ 留给他处置。
  ★ 本门禁**不为它放水**：放水会让"引用私库文件名"也变成合法，
    而那与 t98 的初衷（别泄露站名）冲突。
· 「两个判据互相排斥」这次只解决了**这一个实例**。
  没有通用机制能自动发现"某数据同时承担两个语义" —— 只能靠人读到红时想这一层。
```

**何时该翻案**

```text
· 若将来把 `native-media-audit.json` 移出仓库（改放 .probe/），
  内部台账豁免就可以删掉 —— 那时冲突自然消失。
  ★ 但要注意：判据 d 的"防腐化"要求台账与文件同名，
    移出仓库后这个约束仍然有效（只是不再进 t98 的扫描范围）。
· 若 `_test.dart` 这个标记不再足够（例如出现"引用测试目录"而非文件名），
  条件②要重新设计，不能简单放宽成 `test/`。
```
