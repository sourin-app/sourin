# Agent Note: 恢复目标必须先与现盘核对 —— 参照物过期时读数看起来完全正常

Status: implemented

## Problem

**同一形状在本批连发两次**，两次都会让复核者"照说明做却把树改坏，而且看不出来"：

```text
第 1 例（task-6 的卡）：任务卡指定的恢复快照
  .probe/n8b1-n9-inject-baseline-agg.rs   md5 bd202a52…（= 中间态）
  而交付态                              md5 ca327a76…
  ⇒ 两者差 99 行（纯追加：后加的实网 #[ignore] 用例）。
    "照卡恢复"会**静默删掉那 99 行**，而 `diff -q` 恰好也报不同
    ⇒ 复核者容易误判成"恢复失败"反复折腾，或误判成"没差别"直接放过。

第 2 例（执行者自留的 inject-bak）：
  .probe/inject-bak-tvbox-source-panel.dart   备份=5ccb89aa…（= 修复前）
  而现盘                                     md5 4b2b87b9…
  ⇒ 恢复它会**正好把刚修好的 zz_t66 收口回退掉**（6 处 `$e` 回来）⇒ 该门禁重新变红。
  .probe/inject-bak-settings-page.dart        备份=d5ec953b…（= 修复前）
  而现盘                                     md5 7d5e5041…
  ⇒ 恢复它会**冲掉别人（Lead）的 N8b-3 接线**。

第 3 例（同族，同批登记）：复核者的 DLL 探针第一版把 FFI 异常压成字符串
  ⇒ `kind` 恒为 null ⇒ **连阳性对照都恒真** ⇒ 四条命令"全绿"而其实一条都没验到。
```

**三例共性**：**判据的参照物过期或失效时，读数看起来完全正常**。
这类缺陷不会红、不会报错，只会让"已验证"变成空话。

## Decision

把"恢复源 / 基线 / 备份"当作**有保质期的引用**，规则四条：

1. **每个备份/基线文件必须标注它对应的交付态 md5** ——
   光有文件名不够：`.probe/inject-bak-x.dart` 这个名字**不说明它是什么时候的快照**。
   落盘时就在同目录写一份对照表（本批做法：`.probe/task2-restore-targets-for-task7.md`），
   把「恢复目标（现盘 md5）」与「旧日志里的值（别用）」并列。
2. **被引用为恢复目标之前，先 `diff -q` 与现盘核一次**。
   ```text
   不一致 ⇒ 是**它过期了**，不是现盘坏了。
   ```
   ★ 这一条是整篇的核心：它把"要不要信这个备份"从**记忆/推理**变成**一条命令**。
3. **任务卡/日志里写在"恢复后 md5 = …"的读数，必须注明它是"当时的读数"**，
   否则今天读起来就像"恢复目标"（第 2 例的日志正是这样被误读的）。
4. **中间态快照不许当交付态用**：恢复目标只允许是**交付态**。
   若确实需要留中间态（例如为了演示某次注入），单独命名（本批：`…-inject-baseline-*.rs` 语义上
   该叫 "midstate"），并在卡里写明"它不是恢复目标"。

发现过期副本时**删除或重生成**，不要留着（留着就是下一颗雷）——
本批处置：重生成 3 份交付态 `inject-bak`、重生成 2 份交付态 Rust 基线、删除 2 份中间态旧副本。

## Alternatives considered

- **在恢复脚本里硬编码 md5 断言**（恢复后校验"是否等于某个期望值"） ——
  它最强的论据是**完全机械化**，人不用记任何东西。
  否决理由：这只覆盖"恢复**后**对不对"，覆盖不了"**恢复源**本身是不是对的"——
  拿一个过期快照去恢复、再断言"等于**那个过期快照的** md5"，两条会一起错、一起绿。
  ⇒ 真正要做的是**拿现盘当权威**（规则 2），而不是给快照再钉一个校验值。

- **每次都重新从 git 取基线**（不落盘副本） ——
  它最强的论据是**没有副本就没有过期副本**，根除问题。
  否决理由：本批的注入必须在**工作树**上做（改的是未提交的在途改动），
  而 `git` 里根本没有那些改动的提交 ⇒ 取不到对应基线。落盘副本是必需的，
  所以问题只能靠"标 md5 + 用前核对"解决。

- **禁止留副本，靠"改前先 commit"** ——
  它最强的论据是让 git 天然承担基线职责。
  否决理由：本批纪律是**执行者不 commit/push**（改动攒到批末统一由 Owner 决定），
  且多处改动同时在途 ⇒ 无法为每个注入点单独建提交。

- **把这套写进 AGENTS.md 当硬门禁** ——
  它最强的论据是覆盖面最广。
  否决理由：**"快照是否过期"无法机械判定**（它取决于当前树，而树一直在动），
  写成门禁只能变成"每个快照都要带 md5 注释"这种形式检查（可被形式满足）。
  ⇒ 本批做法是**写成笔记 + 在任务卡里点名**，把它作为复核者的检查项
  （复核者本来就要"读真实 diff、自己跑"，加一条核 baseline 不增加成本）。

## Consequences

- **收益**：把"照说明做却把树改坏"这一类静默事故，从**靠人记得**变成
  **一条 `diff -q` 命令**。本批两次都由这条挡住（第 1 例由复核者发现并改用自己的快照；
  第 2 例由执行者自查发现并重生成）。
- **收益（连带）**：暴露了"日志里的历史读数会被当成现行指令"这个更普遍的问题 ——
  `.probe/` 里的老日志**不会**随代码更新而失效，读它们时必须先确认时效性。
- **代价**：每个注入/备份环节多两条命令（写对照表 + 用前 `diff -q`）。
  相对"静默改坏树"的代价，这个成本可忽略。
- **代价**：对照表本身也会过期（它同样是副本）—— 但它**声明了权威来源是现盘 md5**，
  所以过期时能被判出来，而不是继续误导。
- **边界**：本规则只管"**恢复源/基线/备份**"这一类**被当作参照物引用**的文件。
  普通产物日志（读数、截图）不需要标 md5 —— 它们是**证据**，不是**指令**。
- **重访条件**：若将来出现"改判据必须同批重标多张表"的场合（本批 `zz_t66` 的
  budget-exact 表就是），本条规则要与之配合：**改判据不能塞进别人正在复核的窗口里**
  （本批裁定：不动判据，只留 `.probe/t66-scanner-blockcomment-scope.md` 记录）。

## Testing

本批两条实测（都在 `.probe/` 可复核）：

- 第 1 例：复核者用 `diff -q` 发现卡里的 baseline 与现盘差 99 行 ⇒ 改用自己的交付态快照；
  Lead 随后重生成 `.probe/n8b1-n9-baseline-{agg,tvbox}-DELIVERED.rs`
  （md5 `ca327a76…` / `9b433d2c…`，与现盘逐字一致）并删除旧副本。
- 第 2 例：执行者自查发现 2 份 `inject-bak` 过期 ⇒ 重生成 3 份并留对照表
  `.probe/task2-restore-targets-for-task7.md`；Lead 复核 `diff -q` 全部 **SAME**。
