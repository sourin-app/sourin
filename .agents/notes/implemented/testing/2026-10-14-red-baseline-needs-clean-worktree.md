# Agent Note: 「在某个提交上跑测试」必须用纯净 worktree

Status: implemented

## Problem

工作树里有在途未提交改动时，测试实际测的是**工作树**，不是那个提交。
于是「修复前应当红」的红基线会得出无意义结论：代码已经被改了，
跑出来当然全绿 —— 而这个绿被当成「缺陷本来就不存在」或「修复已被验证」。

## Decision

要证明红基线（或做变异复红）时，必须 `git worktree add` 检出目标提交到纯净副本再跑。

**不翻案。**

Independent: 红基线要用纯净 worktree。与上一条同域但讲的是**取证条件**，不是同一决定。

## Alternatives considered

- **`git stash` 后跑** —— 它最强的论据是就地完成、不必另建目录。
  否决理由：会与并行工作冲突（stash 是全仓操作），且容易忘记恢复，
  丢改动的风险落在最不该出错的一步上。

## Consequences

- **收益**：红基线结论与实际提交一一对应，可复现、可复查。
- **代价与已知上限**：每次要多一次 worktree 建删，且 worktree 目录本身是
  本机脚手架（需被门禁扫描跳过，否则同一份源码两份命中）。
- **重访条件**：不翻案。
