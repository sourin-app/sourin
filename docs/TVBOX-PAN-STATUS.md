## 一、TVBox 多源聚合配置

### 能做到什么

| 能力 | 状态 |
| --- | --- |
| 导入配置（贴 JSON 或给 URL） | ✅ 既有实现，本批未改 |
| `type 1`（苹果CMS）源 | ✅ 既有实现（会真去探测分类） |
| **`lives[]` 直播源** | ✅ **本批新增**：解析 m3u/txt → 注册成 provider → 落盘 → 重启恢复 |
| **`parses[]` 解析服务** | ✅ **本批新增**：读配置里的 `type: 0` 前缀，优先于内置兜底 |
| `type 3`（Java 爬虫）源 | ❌ **做不到**，见下 |

### 做不到什么（关键）

一份实测样本（`sites` 100 个）里 **100 个全是 `type: 3`** —— Java CSP 爬虫，
由配置里的 `spider` jar 在 JVM 里执行。本产品是 Rust 原生实现，没有 JVM。

**这不是"还没做"，是运行时根本不同。** 除下列两条外没有第三条路：

1. **内嵌 JVM**（GraalVM / JRE 子进程）—— 包体 +40~60MB，**iOS 平台不可行**
   （App Store 3.3.2 禁止运行时加载可执行代码），且 spider jar 是第三方任意代码。
   **这需要产品决策，不由实现层决定。**
2. **等生态转向纯 HTTP 类型**（`type 0/1/4`）—— 本仓已支持 `type 1`。

### 「从 `type: 3` 源里救出站点」已实测否掉

一个自然的想法是：这些源里有的 `ext.site` 带真实站点地址，能否据它救成纯 HTTP？
**实测过，转化率 1%，明确不做**（数据与理由见 [PLUGIN-SPEC-PARITY.md](PLUGIN-SPEC-PARITY.md) 附录）。

### `rules` / `ads` / `doh` / `flags` 为什么不落地

这四项在**本仓没有消费方**（用宽关键词复查过：`adblock`/`watermark`/`alias`/`clean_title`
等都没有对应的运行期机制）。按「不加没有用例的机制」的原则不实现 ——
写进来也无处生效，只会变成死代码。

## 二、网盘账号登录

### 能做到什么

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| **识别分享链接** | ✅ | 8 种盘（夸克/UC/百度/阿里/123/115/天翼）；域名**精确匹配**（不用 `contains`）；提取码可从正文取 |
| **凭据存储** | ✅ | 走**系统钥匙串**，cookie **绝不落盘**；有源码门禁钉死 |
| **分层原因** | ✅ | 认不出 / 缺分享 id / 需登录 / 已过期 / 已登录但取直链未接入 |
| **界面** | ✅ | 设置页 ⋮ 菜单 →「识别网盘链接」 |

### 做不到什么（关键）

**取直链（换 token → 文件列表 → 下载地址）没有实现，也不会在没有真账号的情况下实现。**

理由：这条链路的每一步都需要真实登录态才能验证。没有账号写出来的代码，
是"看起来完成了但一行都没真跑过"——那正是本项目明令禁止的形态。

`identify_pan_share` 返回的 `resolvable` **恒为 false**，界面上也没有"播放"按钮，
就是不让用户误以为能用。

### 需要的输入

**一个网盘测试账号**（任选一个盘，夸克或 UC 成本最低）。

## 三、插件开发规范同步

### 做了什么

- [PLUGIN-SPEC-PARITY.md](PLUGIN-SPEC-PARITY.md)：与 WebHome Devkit 的 10 项逐条对照
- [PLUGINS.md](PLUGINS.md)：补「该做与不该做」+ 每条 API 的失败语义表

### 明确**不**引入的（都有理由，不是遗漏）

| 项 | 为什么不 |
| --- | --- |
| `depends` + 版本约束 + 拓扑排序 | 本仓插件是彼此独立的数据源，没有任何插件需要另一个的产物。加了是一套**没有用例的机制** |
| `runAt` 三档注入时机 | 本仓插件由宿主调用时执行，没有页面生命周期 |
| `cspKeyRegex` | 本仓一个插件对应一个源，不需要按站点匹配 |
| `GM_*` 异步存储语义 | 本仓沙箱内同步存储，没有宿主阻塞问题 |

### 「让插件报错带行号」经实测**不可行**

两次探针证明：QuickJS 对 `eval` 的脚本**恒报 `1:1`**（错误放第 2 行与第 5 行都一样）。
展示一个假行号比不展示更糟 —— 作者会去第 1 行找一个不存在的错误。
⇒ 明确不做。现有取 `e.message` 的做法是对的（实测能拿到有信息量的消息）。
