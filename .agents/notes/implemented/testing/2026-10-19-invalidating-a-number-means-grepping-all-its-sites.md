# Agent Note: 作废一个数字时，要 grep 它的全部出现位置

Status: implemented

Independent: 与
[thresholds-from-measurement-not-from-myth](2026-10-19-thresholds-from-measurement-not-from-myth.md)
是**同一件事的两半**：那篇讲「阈值该按实测定」，
本篇讲「**把一个旧数字从代码里彻底清除**」时容易漏的地方。

## Problem

`test/zz_t66_player_jank_test.dart` 里有一个作废的基线数字 `190`。
我改了它出现的三处中的**两处**：

```text
✓ :63   基线表里的「E 隐藏光标 … all=190」        改了
✗ :438  print('…（改前：page=1 all=190）')       ★ 漏了
✓ :443  注释里的「hideAll 仍是 ~193」            改了
```

★ 漏掉的那处是**运行时 `print`** —— 它每次跑测试都往日志里印一个
**已经被证伪**的数字。⇒ 读日志的人（人或 CI）会继续拿它当对照。

而且翻出第二件事：**同一份基线表里，`190` 与 `~193` 并存**
（`:63` 写 190、`:443` 写 193），而复核实测
「worktree 里缺 `sourin_core.dll` 时读数正好是 **193**」
⇒ 这两个数很可能是**同一个坏环境**下的读数被当成了「改前对照」。

## Decision

```text
① 把 :438 的运行时 print 也改掉，并写明「已作废 + 为什么作废」
   —— 一个每跑一次就印一次的假数字，比注释里的假数字危害大得多
② :443 的注释同样改成「实测 531 + 三重兜底搜索 + 那个 193 巧合的推断」
③ 在注释里把「为什么缺 DLL 会让读数变」写清楚
   （核心加载失败 ⇒ _playing 路径不同 ⇒ widget 树规模不同）
   这是 MEMORY 里「worktree 只 checkout 受版本控制的文件」那条的又一实例
```

## Alternatives considered

**A. 只改「看起来是主结论」的那一处（我第一版）。**
最强理由：那一处是三条断言的依据，改了它门禁就正确了。
否决理由：**运行时 `print` 也在印那个数**。
读日志的人看到「改前 all=190」与屏幕上的 531 并列，
会以为两者可比 —— 而它不可比。

**B. 把 `190` / `193` 全仓删干净，一个字不留。**
最强理由：彻底。
否决理由：需要在注释里**说清它为什么作废**，否则下一个人会
「好心」地把它当成有效基线恢复回去。删除 ≠ 澄清。

**C. 用脚本批量替换这两个数字。**
最强理由：快。
否决理由：**这两个数字可能是别处的合法值**（比如某个计数恰好是 193）。
⇒ 必须逐处判断语境，不能批量。

## Consequences

**判据（这次真正学到的一条）**

```text
作废一个数字时，`grep` 它的**全部出现位置**，不要只改
「看起来是主结论」的那处。

★ 尤其注意这三类位置：
  ① 断言的依据（最显眼，通常先改）
  ② ★ 注释 / 文档（容易漏）
  ③ ★★ 运行时 print / 日志输出（**最容易漏，且危害最大** ——
     它每次跑都在制造新的假证据）
```

**★ 更一般的一层**

```text
一个数字被写进基线表，意味着它在替某条断言背书。
作废它 = 撤掉那条背书 ⇒ 必须同时撤掉
  · 断言的阈值
  · 注释里的引用
  · 日志里的打印
三处缺一不可，否则下一个人会拿「注释里的 190」当默认值。
```

**★ 附一条环境陷阱（本篇最有价值的一条）**

```text
「worktree 里缺 sourin_core.dll ⇒ 读数 531 变 193」

根因：核心加载失败 ⇒ `_playing` 的置位路径不同 ⇒ widget 树规模不同
⇒ 同一条测试在两个环境下给出两个数，而它们**长得一样**
（都是 pageBuild=1 / all 都是三位数）
⇒ 不记录环境因素，就会把「坏环境的读数」当成「历史基线」。

★ 判据：**任何写进基线表/对照的数字，都必须同时记录
  「在什么环境下测的」，且那个环境要可复现。**
  「同一天测的」不算 —— 这正是 190 不可考的根因。
```

**何时该翻案**

```text
· 若将来有了 CI 产物能记录环境（commit + DLL hash + 平台），
  基线表就应当只存「带环境指纹的数字」，
  手写的裸数字应当被门禁拒收。
· 若 `debugOnRebuildDirtyWidget` 将来变更语义（它现在是内部钩子），
  本文件全部读数都要重测 —— 因为它们量的是这个钩子。
```
