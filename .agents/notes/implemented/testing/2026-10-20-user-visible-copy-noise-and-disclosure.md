# Agent Note: 用户可见文案的两类缺陷 —— 噪声字符与关键告知缺失

Status: implemented

## Problem

CS-1 的凭据同步功能里，有两类**测试永远抓不到**的缺陷：

```text
① 噪声字符：Rust 拼好的字符串里有连续空格，经 FFI 进 Dart 的 Text
   ⇒ 界面上一句话中间裂开一大块空白
   ⇒ 不报错、不崩、用例全绿

② 关键告知缺失：全仓没有任何一处说「上传的是密文，网盘解不开」
   ⇒ 用户看到"登录态同步到云盘"的第一反应是"我的密码要传到别人服务器？"
   ⇒ **不敢开这个功能** —— 功能因为没解释而没人敢用
```

第 ② 类尤其值得记：它不是"文案不够漂亮"，而是**功能的可用性缺陷**。
一个正确实现、正确加密、有 49 条门禁保护的功能，因为没告诉用户
"服务端解不开"，实际使用率可能是 0。

## Decision

### 一、噪声字符：判据按**字符类别**拆开，不合并成一条

```text
`**`（markdown 粗体）    ⇒ 已有两条门禁（Dart 侧 / Rust 侧）
连续空格 / 制表符 / 零宽  ⇒ 本轮的 zz_t66_cs1_user_text_gate_test.dart
```

**不把 `**` 塞进新门禁**：那是同一份真相两处维护，改一处另一处会漂。
已有两条门禁的判据是 `isMarkdownBoldLiteral`，新门禁的判据是 `noiseIn()`，
两者**对象不同**，就该是两条门禁 —— 但要**互相引用**，说明为什么分开。

### 二、关键告知：判据用**精确子串**，不用正则

```dart
const mustSay = '上传的是密文，网盘那边解不开（口令不在服务器上）';
expect(src.contains(mustSay), isTrue, reason: ...);
```

**为什么不用正则**（这是本笔记最重要的一条，见下面 Alternatives）。

### 三、修文案的边界：只去噪声、补关键告知，**不删警示**

```text
删掉：连续空格（纯噪声）
新增：一句关键告知
保留：所有警示（"忘记口令无法恢复" / "明文密码类单独提示" / "整次导入会失败"）
```

并用一条门禁把"必须存在的警示"钉住（`必要的警示文案必须还在`），
防止将来有人为了"文案整洁"把它们删掉。

### 与既有笔记的关系

**部分重叠**：[Rust 侧用户可见文案的 markdown 星号](../bug-fix/2026-10-20-rust-user-visible-markdown-leak.md)
处理的是**同一行**里的 （判据 `isMarkdownBoldLiteral`），本篇处理
**同一行里的空白噪声**与**另一处完全缺失的告知**。



⇒ 两篇的**判据对象不同**，不是重复。本篇不修改那篇的结论，也不取代它。
★ 这正是本篇 Alternatives 里「不把  也塞进新门禁」的理由。

## Alternatives considered

- **用正则判"服务端解不开"这句话存在** —— 我试了**两次**，两次都假绿：

  ```text
  第 1 版：RegExp(r'(服务端|云端|网盘)[^。]{0,24}(解不开|看不到|无法解密)')
    命中：「⚠️ 忘记口令 = 云端那份和已导出的备份包都解不开（没有找回途径）。」
    主语是"你"（用户自己解不开），**不是"服务端"** ⇒ 假绿

  第 2 版（收紧到同一句 + 顺序）：仍然命中同一句
    因为"云端"在前、"解不开"在后，恰好满足"同一句 + 顺序正确" ⇒ 仍然假绿

  第 3 版：精确子串 mustSay ⇒ 立刻红
    因为那句文案当时**根本不存在**
  ```

  否决理由：**正则能表达「顺序」，表达不了「主语」。**
  用正则判语义，只要文里恰好有一句含这两个词就绿，
  而那句话可能完全是别的意思（"你解不开" vs "服务端解不开"）。

- **把 `**` 也加进新门禁一起查** —— 否决理由：
  已有 `zz_t66_rust_markdown_gate_test.dart` 与 `zz_t66_markdown_audit_test.dart`
  在用 `isMarkdownBoldLiteral` 判它，再加一份就是同一份真相两处维护。

- **只修 Rust 那条空格，不动 UI** —— 否决理由：
  用户看到的是**最终渲染出来的那句话**，不是"哪一层产生的空格"。
  只修一层等于把问题留给下一层。

- **`credentialsNote` 不显示** —— 否决理由：
  它是"包里到底有没有登录态"的唯一告知。不显示的话，
  用户会以为备份了全部数据，而实际上换机器后每个源都要重新登录。

## Consequences

### 收益

```text
· 用户能读到「网盘那边解不开」⇒ 敢开这个功能（这是本轮最实际的收益）
· 噪声字符有了可长期防退化的门禁（不依赖人 review）
· "必要的警示必须还在"被钉住 ⇒ 防止将来为了整洁删警示
```

### 代价

```text
· 精确子串判据**绑定了文案本身**：改一个字就要同步改门禁。
  这是有意的取舍 —— 那句话就是要给用户看的原文，
  改它本来就该是"要同时想清楚门禁"的动作。
· 新门禁只扫 CS-1 的三个 Rust 文件 + 两个面板，
  不是全域扫描 ⇒ 别的模块的同类问题它抓不到。
  （有意收窄：全域扫描会把别人正在改的文件拖进来，造成假红）
```

### 已知未做

```text
· `credentialsNote` 里的**换行**（如果有）在 Text 里的表现没验过
· 界面没有"预览这个包长什么样"的能力，用户只能看到 note 的一句话
```
