# Agent Note: 占位态文案不许替用户断言未发生的事

Status: implemented

> 同域：[2026-10-19-criteria-must-distinguish-cause-and-ciphertext.md](../testing/2026-10-19-criteria-must-distinguish-cause-and-ciphertext.md)
> （判据要精确到"为什么"）；本篇管的是**文案**层面的同一问题。

## Problem

弹幕诊断面板有一个「占位态」——探针判 offline、`_diagnose` 还在跑的那一两秒。
它直接套用了**完成态**的文案：

```dart
remedy: DanmakuProbeReport.remedyFor(DanmakuProbeFailure.connectionTimeout)
```

而此刻 `InternetAddress.lookup` **还没执行**。于是界面断言了三件当时**根本不存在**的事实：

```text
· 「地址解析出来了」   ← 没解析过
· 「连不过去」         ← 没连过
· 「通常是被墙 / 需要代理 / 路由不通」  ← 没有任何依据
```

★ 这是 `48183b8`（X4）修过的**同一个病**，但漏了这一处：
X4 修的是 `fromError` 的兜底分支，没覆盖 `_runProbe` 里的占位态。

**同仓对照是最有力的证据** —— 同一件事，设置页做对了、面板做错了：

```text
danmaku_source_page.dart:215   '连不上 —— 正在确认是本机网络还是服务端的问题…'  ← 中性，正确
danmaku_settings_dialog.dart   remedyFor(connectionTimeout)                    ← 断言全文
```

## Decision

### ① 占位态一律用中性句：只说「还不知道」，不说结论

```dart
remedy: '连不上 —— 正在确认是本机网络还是服务端的问题…'   // 25 字（原 131 字）
```

照抄设置页 `:215` 的写法。131 → 25 字，**变短不会溢出**。

### ② 判据：这段文案陈述的事实，此刻**有没有证据**

逐个核对全部 19 个 `remedy:` 赋值点的**证据前提**：

```text
面板 :463   fromError          有 errno / 异常类型              ✓ 完成态
面板 :501   remedyFor(f)       有 failure 分档                  ✓
面板 :512   TLS                有 HandshakeException            ✓
面板 :531   probeFailed        有原始异常                       ✓
面板 :589   dnsHijacked        有 localAddresses 物证           ✓
面板 :602   emptyResponse      有 HTTP 200                      ✓
面板 :617   auth 401/403       有 statusCode                    ✓
面板 :2533  **占位态**          ★ 无（_diagnose 未跑）          ✗ ← 就是这处
面板 :2585  dnsFailed          有 addrs.isEmpty 物证            ✓
面板 :2619  serverError        有 TCP 连通物证                  ✓
面板 :2645  connectionTimeout  有 local 物证 + TCP 超时         ✓
面板 :2659  dnsFailed 超时     有 TimeoutException              ✓
设置页 :215 **占位态**         无                              ✓ 已是中性句（正确写法）
设置页 :278/286/301/329/353/368  同面板各档                     ✓ 全部有物证
```

**结论：只有 1 处违规，已修。没有其它实例。**

### ③ 门禁必须**两档对照**，不能一刀切

```text
占位态：不许出现断言词（地址解析出来了 / 被墙 / 需要代理 / 路由不通 / 连不过去）
完成态：**必须**出现那些词，且必须用「通常 / 也可能」留余地
```

★ **为什么必须成对**：完成态确实解析过、连过，说那些是**对的**。
只写「出现断言词就红」会把正确的完成态也判红 —— 那不是判据，是一刀切。

### ④ 同时修掉：文案指向一个不存在的地方

401/403 的可行步骤里写着「或在上面的「凭证」节填一对 AppId / AppSecret 并保存」。
实测：

```text
grep -n "_credentialsSection"  ⇒ 全是注释/定义，**零调用点**
grep -rn "setAppId|setAppSecret" lib/ui/ ⇒ 只有一条**注释**
```

⇒ 用户照着找，找不到；整个客户端无处可填凭证。**删掉那半句**，保留两条真实路径。

★ 门禁不能简单断言「不含凭证」—— 开头「这是**凭证**问题」是**诊断结论**，必须留。
判据要精确到「不许把凭证当作**可去的地方**」（「凭证」节/页/栏/上面…）。

★ 门禁还含**前提检查**：`_credentialsSection` 若将来接回来，门禁会主动红并提示放宽。
这条防的是「门禁比代码活得更久，最后被绕过」。

## Alternatives considered

### ① 「占位态干脆不显示 remedy，只显示一个转圈」

**最强论据**：既然什么都还不知道，就什么都别说 —— 最诚实，也最省事。

**为什么否决**：**用户在那个位置会盯着看一两秒，空着会被读成"卡住了"。**

```text
· 探针判 offline 到 _diagnose 返回，实测约 1~3 秒
· 这段时间用户看到的是一个"没有说明的失败"
⇒ 他会以为产品坏了，而不是"正在确认"
★ 判据：**"还不知道"本身需要被说出来** —— 沉默不等于诚实，
  沉默会被读成"没结果"。
```

### ② 「把 `remedyFor(connectionTimeout)` 改成 `remedyFor(unknown)` 新增一档」

**最强论据**：语义更准确 —— 加一个 `unknown` 档，文案自然是"正在确认"，
而且能复用到别处。

**为什么否决**：**它要改 `DanmakuProbeFailure` 枚举，而那是一个跨文件的类型契约。**

```text
· 加枚举值 ⇒ 所有 switch 都要处理（Dart 的穷尽性检查会强迫）
· 而本仓设置页**已经有正确的写法**（直接写中性字符串）
⇒ 有现成的正确做法时，不要为了"语义更美"去改类型契约。
★ 判据：**一致性修复优先复用仓内已有的正确写法，不引入新的抽象。**
```

### ③ 「只删文案，不加门禁」

**最强论据**：文案改动很小，加门禁是过度工程；而且门禁需要维护。

**为什么否决**：**这个病已经复发过一次（X4 修了兜底，漏了占位态）。**

```text
· 48183b8 修的是同一类问题的另一个实例
· 说明"靠人读一遍"不足以保证不再犯
· 而门禁的成本很低：占位态切片 + 若干断言词的黑名单
★ 判据：**同一个病第二次出现时，就该机械化。** 第一次可以靠人，第二次不行。
```

## Consequences

### 收益

```text
· 占位态不再替用户断言三件未发生的事（131 字 → 25 字中性句）
· 删掉指向不存在的「凭证」节的文案（用户不会去找一个不存在的地方）
· 门禁 11 条：占位态/完成态两档对照 + 凭证节前提检查
· 同类排查覆盖 19 个 remedy 赋值点，确认只有 1 处违规
```

### 读数

```text
flutter analyze lib                        ⇒ 0 error
R3 十个门禁                                ⇒ +113 All tests passed
相关既有门禁（10 个文件）                   ⇒ +126 ~1 All tests passed

注入 M  占位态改回 remedyFor  ⇒ -3 红（①不含断言词 / ②含正在确认 / ⑤两处一致）
注入 N  凭证半句加回去        ⇒ -1 红（②组）
注入 O  两条路径也删掉        ⇒ -1 红（③组，防删过头）
每条注入后 analyze 0 error；还原后 sha256 回到 c2603a21…
```

### 代价

```text
· 占位态与完成态的文案现在是两套，改完态文案时要记得占位态也要看一眼
  （门禁 ⑤ 会检查"面板与设置页占位态必须一致"，但不会检查"完成态改了要不要动占位态"）
· `zz_t66_r3_placeholder_wording_test.dart` 的断言词黑名单是硬编码的
  （地址解析出来了 / 被墙 / 需要代理 / 路由不通 / 连不过去）
  ⇒ 将来新增断言词要同批加进去，否则门禁漏报
```

### 没做的

```text
· 没恢复 _credentialsSection（那是产品决策，不是文案修复）
· 没改 `⇒`（181 次 / 13 文件，是既有风格）与 `⚠️`（25 次，未达门槛，待定）
· 没改「番剧季兜底」（既有用户词，非开发过程用语）
```

### 何时该翻案

```text
① 若将来恢复凭证入口 ⇒ 门禁 ① 会主动红（前提检查），按提示放宽
② 若 `⇒` 在用户可见文案里继续增长（>300）⇒ 可能需要统一的排版规范
③ 若占位态那一两秒被去掉（例如探针改成立即返回分档）⇒ 这一整节可以删
```
