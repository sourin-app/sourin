# Agent Note: 首页判据是 home() 拿不拿得到内容，不是登录态好不好

Status: implemented

## Problem

`Registry::home_all()` / `live_all()` 曾按 `session_usable()` 过滤源，于是
「游客态能正常浏览、只是播放需要登录」的源被整个跳过，首页落到空态
「还没有可用的内容源」—— 而用户明明启用了它（源切换条上就有）。

根因是把 `Capabilities::login_required` 当成了浏览门禁。它的定义是
「需要登录才能**取流**」：它管**播放**、不管**浏览**。

顺带纠正一处长期误读：`session_usable()` **从不**过滤「失效账号」——
会话过期也走 `Ok(Some(_)) => true`。它唯一返回 false 的情形是
「需要登录 + 从没登录过 + 无凭据」，也就是**游客**。
所以旧行为的真实语义是「游客看不到这个源」，而不是注释写的「失效账号」。

## Decision

`home_all()` / `live_all()` **不**按 `session_usable()` 过滤源。
一个源该不该上首页，只看它的 `home()` 有没有真的返回内容：

```text
home() 真需要登录 → Err(Unauthorized) → 错误隔离挡掉（不展示）
home() 游客态能用  → Ok(sections)     → 正常展示
```

Independent: 首页判据改用 home() 是否拿到内容。单点判据修正。

## Alternatives considered

- **给 `login_required` 加一个「只挡播放」的新语义位** —— 它最强的论据是语义最精确：
  把浏览与取流两个权限显式分开。否决理由：需要改所有插件声明，
  而 `home()` 的真实返回值本来就是更准的信号，不必新增字段。

- **保留门禁、只改界面文案** —— 它最强的论据是改动最小。否决理由：治标 ——
  源条上看得见、内容区永远空，用户点进去还是什么都没有。

- **在 `-Dev` 播种里拷 `plugins/.data/` 把会话补上** —— 否决理由：
  违反「凭据一律不带」的播种约束，而且只掩盖症状：真实用户没登录时照样撞到。

## Consequences

- **收益**：游客态能浏览的源正常出现在首页；「有没有内容」由内容本身回答，
  而不是由一个语义被误读的标志回答。
- **代价与已知上限**：`home()` 现在会对**每个**启用源调用一次，包括
  「确实要登录、必然失败」的那些 —— 多几次注定失败的请求，
  由既有的错误隔离与每源超时兜住。
- **重访条件**：若将来某个源的 `home()` 在未登录时**既不报错也不返回空**
  （返回一个「请登录」的假分区），那应由**插件**返回 `Unauthorized`，
  而不是把宿主门禁加回来。
