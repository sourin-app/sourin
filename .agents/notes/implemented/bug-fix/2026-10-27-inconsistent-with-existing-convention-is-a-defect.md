# Agent Note: 「与既有惯例不一致」本身是一个缺陷类别 —— 只在装了代理的机器上坏

Status: implemented

## Problem

本批（2026-10-27）补 csp 类时，一位执行者的第 11 个类 `hd_moli` 真网 `list` 失败：
`error sending request ← operation timed out`（50 秒）。

它**没有**直接判"上游死"，而是逐层取证：

```text
① curl -L                   ⇒ 000 / 超时 25s
② DNS                       ⇒ Cloudflare 地址（104.18.42.88 / 104.18.34.88）
③ 裸 TCP 443                ⇒ **通**（3/3）
④ TLS（openssl s_client）    ⇒ **握手成功**、证书 CN 匹配、Verification OK
⑤ 手工 HTTP（openssl 发完整请求）⇒ **200 OK / 真页面 36186 字节**（2/2 可复现）
⑥ curl 用与 openssl **完全相同的极简头** ⇒ **仍超时**
⑦ 查环境 ⇒ ★ **`https_proxy=http://127.0.0.1:7890/`**（curl / reqwest / urllib **都读它**）
⑧ ★ 决定性对照（同一 URL）：
     不走代理 ⇒ **HTTP 403 / 1.2s**（服务器**回了** —— 是反爬页）
     走代理   ⇒ **TLS 握手超时 / 25.0s**
```

⇒ **结论：失败与上游完全无关，是"我们的 HTTP 客户端读了系统代理，而该代理对这几站不通"。**

★ 这一步的关键是 ⑧ —— **同一 URL 的对照实验**，而不是"我改了配置之后好了"
（后者是自我确认，前者才是独立证据）。

## Decision

**判据：一个模块若属于某个"既有行为族"，就必须与该族的**行为约定**一致；
  不一致本身是缺陷，即使"在当前环境里跑得通"。**

具体到本条：本仓既有 **8 个 csp 类**都写了 `.no_proxy()`（`app_yqk:131` 还逐字注释
「与其它 csp 源一致：不读系统代理」）⇒ 那就是**该族的行为约定**
⇒ 漏写的类不是"风格不统一"，而是**只在装了代理的机器上坏**的隐性缺陷。

落地：那个执行者**名下 11 个类全部补 `.no_proxy()`**，并**重跑了全部 11 条真网用例**。

★ 而"重跑"这一步**证明必要**（若只补不测，会**既漏掉收益也漏掉副作用**）：

```text
· Jpys   取流：`CDN 403 the source ip is forbidden` → **真 m3u8**   ← 正向变化
· AppGet 取流：`腾讯播放页` → **真 m3u8**                          ← 正向变化
· HDMoli 全段：50s 超时 → **四段全通**                              ← 正向变化
· GuiGui 从通 → 不通（逐层取证=站点自身此刻异常，**未判它死**）      ← 副作用（已如实分档）
```

⇒ **"补一行惯例"确实改变了行为** ⇒ 凡"惯例性修正"都必须**全量重测行为**。

## Alternatives considered

1. **把这 11 个类当作"独立模块"，不要求与既有 8 类一致**。
   论据：每个类都是独立实现，"不读系统代理"只是别人的选择，不是规范。
   **否决** —— 与实际后果不符：漏 `.no_proxy()` 的类**只在装了代理的机器上坏**，
   而错误是含糊的 `operation timed out`（**极难定位**）。
   ⇒ 这不是"风格"，是"**同一份产品在不同用户机器上行为不同**"。
   ★ 而且它**在干净环境里跑得通** ⇒ 常规验证**看不见**它 —— 这正是它的危险所在。

2. **判"上游死"，把这个类标成不可用**（最省事）。
   论据：真网确实打不开，按本批"上游死就如实标"的惯例，标了就行。
   **否决** —— 那会**固化一个错误结论**（把"我们读了不该读的代理"写成"上游不可用"），
   而且用户装了代理也一样坏，却永远看不到"换掉代理就好了"。
   ⇒ 与
   [2026-10-27-upstream-dead-is-a-strong-claim.md](../testing/2026-10-27-upstream-dead-is-a-strong-claim.md)
   **同源**："上游死"是强断言，必须拿到正面/反面证据；**"我打不开"不是证据**。

3. **只在出问题的那个类（HDMoli）上补 `.no_proxy()`**。
   论据：最小改动，谁坏了修谁。
   **否决** —— 那个执行者**主动查了既有 8 类**，发现是**族级约定**
   ⇒ 只修一个类等于**留着 10 个同类隐性缺陷**。
   ★ 它选择"11 个全补 + 全量复验 + 如实报 md5 全变" —— 这个处置是对的
     （**改已交付文件必须报**，不能静默改）。

## Consequences

- **收益**：消除了一类"只在特定环境坏"的隐性缺陷；且**两个类的取流质量因此升级**
  （403 / 播放页 → 真 m3u8）—— 这是"修惯例"带来的**功能净收益**。
- **代价（如实）**：11 个已交付文件的 md5 **全部变化**（每类 +21 行：注释 + 一行调用）
  ⇒ 所有引用者（Lead / 复核者）手里的基准**作废**，必须重记。
  ★ 这与
  [2026-10-27-anchoring-something-that-moves.md](../process/2026-10-27-anchoring-something-that-moves.md)
  那条配对：**"改动了已交付物，其 md5 必须重报并重记基准"**。
- **已知上限**：
  · 本批只处理了"**代理**"这一项环境差异。**未**建立"csp 类应与既有族一致"的**机器判据**
    （例如一条门禁断言"每个 csp 类的 HTTP client builder 都调用了 `.no_proxy()`"）。
    ⇒ **本批未做**，如实记为缺口：这类"族级约定"目前**靠人查**，不靠门禁。
  · 未能证实"装了代理的用户里这个代理对哪些站不通"（那需要真机环境采样）。
